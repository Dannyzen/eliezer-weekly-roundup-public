# Daily Synthesis: 2026-05-27

Today’s strongest signal: agent systems are becoming routing and containment systems. Retrieval should route the cheapest sufficient pipeline per query. Skills should be governed assets with tests and lifecycle memory. Tool gateways need data-flow capability budgets, not only per-tool allowlists. Local execution needs lightweight confinement before every agent shell becomes a privileged workstation.

## Top findings

### 1. Per-query retrieval configuration beats fixed RAG pipelines
- Category: [AgenticAI](../AgenticAI/2026-05-27/reasoning.md#per-query-retrieval-configuration-beats-fixed-rag-pipelines)
- Durable topic: [Agentic Search and Retrieval](../AgenticAI/agentic-search/agentic-search.md)
- Core source: https://arxiv.org/abs/2605.27361
- Why it matters: BRANE shows that retrieval agents can route the entire pipeline configuration per query — LLM, retriever, document count, hop count, synthesis strategy — instead of applying one expensive RAG setup to every request.
- Implementable now: build a retrieval configuration catalog, log cost/quality per route, start with rule-based escalation, then train a lightweight correctness predictor from held-out tasks.
- Implementability score: 0.84

### 2. Skill systems need lifecycle management, not just skill files
- Category: [AgenticAI](../AgenticAI/2026-05-27/reasoning.md#skill-systems-need-lifecycle-management-not-just-skill-files)
- Durable topic: [Skills as Control](../AgenticAI/skills-as-control/skills-as-control.md)
- Core source: https://arxiv.org/abs/2605.27366
- Why it matters: MUSE-Autoskill treats skills as long-lived assets with creation, memory, management, evaluation, and refinement. That is the right response to the current skill-library failure mode: wrong-skill selection and untested self-editing.
- Implementable now: add per-skill tests, selection logs, use/failure memory, held-out promotion gates, and quarantine paths for skills that hurt outcomes.
- Implementability score: 0.70

### 3. Permission laundering needs data-flow capability budgets
- Category: [Strategy](../Strategy/2026-05-27/sovereignty.md#permission-laundering-needs-data-flow-capability-budgets)
- Durable topic: [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md)
- Core source: https://arxiv.org/abs/2605.26542
- Supporting sources: https://arxiv.org/abs/2605.26269, https://arxiv.org/abs/2605.26754
- Why it matters: ChainCaps shows how an agent can satisfy every per-tool permission check while laundering confidential data across a tool chain. Authority has to travel with values, not reset at each tool boundary.
- Implementable now: classify tool outputs by data class and allowed sinks, propagate capability metadata through gateway traces, and block sink actions when transformed values do not carry the required authority.
- Implementability score: 0.62

### 4. Lightweight process sandboxing is becoming practical agent infrastructure
- Category: [Strategy](../Strategy/2026-05-27/sovereignty.md#lightweight-process-sandboxing-is-becoming-practical-agent-infrastructure)
- Durable topic: [Agent Sandboxing](../Strategy/agent-sandboxing/agent-sandboxing.md)
- Core sources: https://arxiv.org/abs/2605.26298, https://github.com/multikernel/sandlock
- Why it matters: Sandlock targets the practical middle ground between weak wrappers and heavyweight VMs: rootless Linux process confinement with filesystem, syscall, network, and reversible-effects controls.
- Implementable now: run agent-generated commands under explicit read/write/network policies, keep COW diffs reviewable, and log denials plus final effects in the trace.
- Implementability score: 0.78
