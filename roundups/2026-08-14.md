# Friday Synthesis, Week Ending 2026-08-14

## Thesis

Evidence is not authority. Across evaluation, memory, skills, tool packages, multi-agent governance, and iterative repair, this week’s strongest work points to the same architecture: models may propose, but separately owned runtime mechanisms must admit, authorize, execute, recover, and verify.

## The single argument

Terminal success is too weak a release condition.

QuoteBench shows that transport can damage a fixed model reply. CAPRI shows that a valid result can cross the authorized edit boundary. The IaC regression study shows that a later repair can break a property that already passed. Memory and skill research shows that retained experience can become durable instruction. AgentChaos, SpecPath, and HarnessSafe show that hidden conditions and carrier stages can reverse conclusions. Agent Plugins 1.0 shows that capability packaging is becoming cheap enough to standardize, which makes client-specific admission more important, not less.

The common answer is a split control plane:

1. The model proposes a plan, action, repair, memory, or skill.
2. Evidence retains stable identity, lineage, validity, and restrictions.
3. Admission decides whether the component may enter this client and policy profile.
4. Authority binds one exact principal, action, target, and version.
5. Execution records transforms, denial, recovery, and realized effect.
6. Verification checks outcome, authorization, preservation, and receipts independently.

## Strongest themes

### 1. Conjunctive acceptance replaces the green check

QuoteBench’s extra parser reduces success on fixed replies by 55.4 to 73.2 percentage points. CAPRI finds six protected-text changes among 144 Isabelle-accepted candidates. The IaC study finds a conservative 3.3 percent strict regression rate across 5,968 repair timelines.

### 2. Retained state is an authority graph

Poisoned experience can become promoted skill behavior. Temporal memory needs supersession and revocation. Shared memory needs permission filtering before relevance and a second gate before action. Skill files need supply-chain treatment.

## What is implementable now

- Add fixed-reply replay across shell, SSH, container, and CI wrappers.
- Use typed action manifests and independent edit-contract checkers for writes.
- Promote every passing check into a preservation obligation for the next repair.
- Give memories, summaries, and skills stable IDs, lineage, validity states, and revocation.
- Add test-owned API fault injection, alternate specification histories, and earliest-error labels.
- Admit each package component separately per client and policy profile.
- Model denial as a durable state with bounded safe recovery.

The strongest ready-to-pilot artifacts are QuoteBench, AgentChaos, OpenCodeReview, ToolHazard, Agent Plugins 1.0, and Quadrat-IPI. Stable releases from OpenAI Agents, Agno, PydanticAI, and Microsoft Agent Framework now expose many of the required approval, recovery, and state primitives.

## What is not ready

Several important designs remain paper-only or partially packaged: READ, LivePlan, TEPA, MAP-Graph, SpecPath, CAPRI, and Beyond Final Scores. POLIS is a valuable institutional-design signal but is single-author and unreplicated. AgentJailbreak’s strong exploitation rates come from a narrow auto-approval setup and a repository without a declared license.

## Best objection

This split control plane adds objects, state machines, validators, and operational cost. The guardrail is to start only where evidence can become authority: package admission, memory promotion, external writes, permission changes, and release. Add upstream machinery only after traces show repeated ambiguity.

## Strategic question

If an approval can coexist with an unmediated effect path, is it approval, or only user-interface theater?
