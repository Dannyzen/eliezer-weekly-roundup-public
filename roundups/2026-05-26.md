# Daily Synthesis: 2026-05-26

Today’s strongest signal: agents need gates at every state boundary. Memory needs storage gates, skills need selection gates, computer-use agents need executable reward gates, and MCP needs metadata-admission gates. The stack is moving from “give the model more context/tools” to “prove which context/tool/state is allowed to influence the run.”

## Top findings

### 1. Personalized memory needs storage gates, not static retention
- Category: [AgenticAI](../AgenticAI/2026-05-26/reasoning.md#personalized-memory-needs-storage-gates-not-static-retention)
- Durable topic: [Memory Systems](../AgenticAI/memory-systems/memory-systems.md)
- Core source: https://arxiv.org/abs/2605.25535
- Why it matters: universal memory rules waste budget on transient sessions and miss user-specific long-horizon context. PerMemBench makes personalized retention a benchmark problem, and session-level storage gating is the implementable control.
- Implementable now: classify sessions before durable memory writes, log admission/rejection reasons, preserve raw evidence, and evaluate personalized retention under fixed token/retrieval budgets.
- Implementability score: 0.72

### 2. Skill libraries need selection discipline before self-evolution
- Category: [AgenticAI](../AgenticAI/2026-05-26/reasoning.md#skill-libraries-need-selection-discipline-before-self-evolution)
- Durable topic: [Skills as Control](../AgenticAI/skills-as-control/skills-as-control.md)
- Core sources: https://arxiv.org/abs/2605.25430, https://arxiv.org/abs/2605.24050
- Why it matters: CODESKILL shows why skill banks can improve coding agents; Skill Shadowing shows why larger libraries can make agents worse. The bottleneck is selecting the right skill, not stuffing more procedural text into context.
- Implementable now: trace selected/rejected skills, keep active skill sets small, test no-skill/thin-skill/full-skill baselines, and accept self-edited skills only after held-out improvement.
- Implementability score: 0.74

### 3. Computer-use agents need verifiable environments, not more screenshots
- Category: [AgenticAI](../AgenticAI/2026-05-26/reasoning.md#computer-use-agents-need-verifiable-environments-not-more-screenshots)
- Durable topic: [GUI-Tool Path Orchestration](../AgenticAI/gui-tool-path-orchestration/gui-tool-path-orchestration.md)
- Core sources: https://arxiv.org/abs/2605.25624, https://arxiv.org/abs/2605.26114, https://arxiv.org/abs/2605.25707
- Why it matters: CUA-Gym, MobileGym, and AgentHijack all move computer-use agents toward deterministic state checks, executable rewards, parallel synthetic environments, and realistic corruption tests.
- Implementable now: build small state-checkable GUI/browser/mobile fixtures, add corruption cells, and score final state, path length, recovery, verification, and side effects separately.
- Implementability score: 0.60

### 4. MCP tool metadata is now a security boundary
- Category: [Strategy](../Strategy/2026-05-26/sovereignty.md#mcp-tool-metadata-is-now-a-security-boundary)
- Durable topic: [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md)
- Core sources: https://arxiv.org/abs/2605.24069, https://arxiv.org/abs/2605.24248
- Why it matters: Tool Description Poisoning hides malicious instructions in the metadata agents read for planning. MCP admission has to authenticate and govern descriptions, schemas, examples, and server identity, not only executable code.
- Implementable now: pin tool metadata digests, review description diffs, allowlist admitted MCP servers/tool subsets, fuzz descriptions for semantic poisoning, and log metadata version in every tool-call trace.
- Implementability score: 0.66
