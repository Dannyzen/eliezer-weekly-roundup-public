# Friday Synthesis: 2026-10-09

## Thesis

The strongest finding this week is that agent reliability depends on executable evidence at every lifecycle boundary. The model may propose a capability, plan, action, completion claim, or scaling decision. The runtime must bind that proposal to a checked object, an explicit effect, a terminal-state oracle, and a receipt.

This turns a loose collection of safety techniques into one stack:

1. admit the right capability;
2. constrain the effect path;
3. observe and govern the live run;
4. verify required terminal state;
5. scale only when workload evidence supports it.

## Weekly findings

### 1. Terminal state outranks agent self-report

ThinkingBox evaluates 507 stateful workflows through executable backend checks and repeats each task 20 times. The strongest reported model falls from 65.36% pass@1 to 25.25% pass^20. ObligationGuard reaches the complementary conclusion: a run can avoid forbidden actions and still finish unsafely because cleanup, verification, rollback, or handoff never occurred.

The implementation pattern is a completion bundle containing terminal-state predicates, positive obligations, repeated trials, and failure snapshots. A textual claim of completion is evidence to inspect, not authority to close the run.

Core sources: [ThinkingBox article](https://huggingface.co/blog/microsoft/thinkingbox), [ThinkingBox paper v4](https://arxiv.org/abs/2608.19741v4), [ObligationGuard paper v1](https://arxiv.org/abs/2610.11773v1), [public repository](https://github.com/THU-Agent/ObligationGuard)

Implementability score: 0.88

### 2. Security controls need paired effect tests

HarnessSecurity-Bench tests legitimate utility and forbidden effects under the same task and environment. Across 2,500 trials and 81,155 tool calls, auto-approve raised attack success from 29.2% to 95.6%. Alternative execution paths remained a material bypass risk.

The useful unit is a control-effect contract tied to an exact harness version: protected effect, authorized path, utility oracle, attack oracle, alternate-path coverage, cost, and release decision. Control names and settings are configuration evidence. Paired effect tests are release evidence.

Core sources: [HarnessSecurity-Bench paper v1](https://arxiv.org/abs/2610.07639v1), [task repository](https://github.com/TsingPig/HarnessSecurity-Benchmark)

Implementability score: 0.81

### 3. Runtime supervision needs one event spine

Transect shows how long trajectories can remain reviewable by aligning events, token use, sub-agent activity, structure, and judge labels on one timeline. AgentTime shows why time belongs on that spine: across 222 tasks from 18 benchmark families, duration following varies sharply by model and harness. OnTrack adds a preliminary intervention layer, reporting about one millisecond per step and roughly 18% compute savings on failing runs under an abort policy.

The implementation pattern is one normalized event stream for active time, idle time, tool effects, sub-agent ownership, resource use, intervention evidence, and recovery checkpoints. Shadow warnings should precede automatic pause or abort.

Core sources: [Transect paper v1](https://arxiv.org/abs/2610.08364v1), [Transect repository](https://github.com/AI-Safety-Institute/transect), [AgentTime paper v1](https://arxiv.org/abs/2610.09944v1), [AgentTime repository](https://github.com/michaelofengenden/agenttimebench), [OnTrack paper v1](https://arxiv.org/abs/2610.12375v1)

Implementability score: 0.76

### 4. Capability admission and policy compilation are one authority surface

One Skill Too Many found that a similar co-installed skill displaced the intended skill in one in five runs without lowering task completion. When the wrong skill was opened first, more than one third of exclusive core functions were lost. NOMOS demonstrates the downstream complement: compile written policy into typed rules, validate them against tool schemas, replay them against known-good traces, and gate state changes deterministically.

The implementation pattern joins catalog governance to action governance. A capability needs identity, precedence, conflict checks, a first-read receipt, typed policy, schema validation, and a versioned effect gate.

Core sources: [One Skill Too Many paper v1](https://arxiv.org/abs/2610.11647v1), [replication package](https://github.com/ltroin/conflict), [NOMOS paper v1](https://arxiv.org/abs/2610.11030v1), [artifact repository](https://github.com/iamupd/NOMOS)

Implementability score: 0.70

### 5. Parallelism is a routing decision, not a default

The dynamic-concurrency study covers 2,124 trajectories across Codex, Claude Code, and Kimi Code. Mean runtime increased in 14 of 15 agent-benchmark combinations. Claude Code lost 24.0 pass-rate points on SWE-bench Verified while gaining 14.3 points on LoopsBench.

The implementation pattern is an explicit topology gate. Admit parallel work only when the task is decomposable, write ownership is disjoint, integration cost is bounded, and the selected harness has measured gains on that workload class.

Core sources: [dynamic-concurrency paper v1](https://arxiv.org/abs/2610.10263v1), [trajectory artifact](https://github.com/schwerli/Concurrency-Failures-Trajectory-Artifact)

Implementability score: 0.86

## What is implementable now

1. Require terminal-state predicates, positive obligations, and failure snapshots before completion.
2. Add one paired utility and forbidden-effect fixture for every consequential harness control.
3. Emit one normalized event stream for time, tools, sub-agents, resources, and interventions.
4. Intercept the first skill read, record the selected capability, and compile one narrow policy domain into typed tool rules.
5. Gate concurrency on decomposability, ownership, integration cost, and workload-specific evidence.

Highest score: 0.88 for terminal-state proof.

Lowest score: 0.70 for unified capability admission and policy compilation. The concept is clear, while NOMOS withholds its compiler and runtime gate and several skill artifacts have no detected license.

## What remains immature

- OnTrack reports only six automatic interventions, so abort precision is preliminary.
- NOMOS publishes rules and reports but withholds the compiler and runtime gate.
- Several public research artifacts have populated branches and no GitHub-detected license.
- Dynamic concurrency results are strong evidence against default parallelism, not a universal scheduler policy.
- Long-horizon observability still needs calibrated human review and incident-derived obligation sets.

## Strategic question

If an agent can select a different capability, bypass the monitored effect path, or declare completion without a terminal-state receipt, what authority did the approval actually grant?
