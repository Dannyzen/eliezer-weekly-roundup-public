# Daily Synthesis: 2026-06-17

Today's strongest signal is that agent trust is becoming evidence-owned. A claim, skill, trajectory, test, route, or delegated handoff is not trustworthy because it exists. It is trustworthy when the runtime can show where it came from, why it was admitted, and what verified it.

## Executive Summary

1. **MCP factuality needs source ownership, not pooled support.** ProvenanceGuard catches cross-source conflation by routing atomic claims back to source-specific evidence in captured MCP traces.
2. **Skill systems need compositional routing plus per-skill utility evals.** SkillWeaver decomposes tasks, retrieves skills, and composes a dependency DAG; the agentic skill evaluation framework supplies no-skill and skill-specific utility testing.
3. **Evaluation needs trajectory preferences and oracle-aware test gates.** Terminal pass/fail creates too many ties, and agent-authored tests are often smoke without real assertions.
4. **Evidence provenance is the strategic control plane.** MCP source IDs, test oracles, agent registries, access graphs, and delegation traces are all parts of the same governance substrate.

## Signals

- **Highest implementability today:** trajectory preferences and oracle-aware test gates at 0.86. The first version can be built with trace checkpoints, pairwise comparisons, AST checks, mutation tests, and CI gates.
- **Lowest implementability today:** MCP source-owned factuality at 0.74. The trace schema is straightforward, but source attribution remains hard when sources are semantically close.
- **Strategic convergence:** agent platforms are becoming evidence systems. The artifact that steers or verifies a run needs identity, source, version, route, policy, and verifier output.

## Actionable Insights

1. **Add source IDs to traces.** Tool output without stable source identity is weak evidence.
2. **Route skills compositionally.** Decompose tasks before loading skills, then compose selected skills into a checked DAG.
3. **Evaluate skills against baselines.** A skill is not good because it exists. Compare no-skill, wrong-skill, thin-skill, and full-skill variants.
4. **Grade trajectories, not only endings.** Use progress and time-to-return profiles to separate good near-misses from dead-end runs.
5. **Reject test theater.** Agent-authored tests need explicit oracles, not just files that execute code.
