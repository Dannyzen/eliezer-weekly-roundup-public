# Daily Agent Research Roundup: 2026-10-25

## Thesis

Agent control fails when descriptive context is mistaken for current authority. Live code, memory lifecycle state, and email content each need an explicit precedence or admission rule before they can drive effects.

## Freshness note

No new weekend arXiv listing was available. These are nonduplicate carry-forwards from the Friday, October 23 batch, submitted October 22.

## Top findings

### 1. Give live code precedence over stale descriptive instructions

In 320 runs across 40 Python projects, 90.1% of coding-agent choices followed stale instruction files. A one-sentence precedence rule raised code-conforming choices from 4.2% to 91.4% and restored a 100% test pass rate.

Source: https://arxiv.org/abs/2610.30571v1

Artifact: https://github.com/WenJing95/stale-docs-data

Implementability: 0.97

### 2. Test memory governance state independently from retrieval

Governance-state corruption changed the operative memory projection in 96.25% of 2,080 matched fault pairs. Selected downstream contrasts showed 40.54 points of LongMemEval damage and 30.60 points of Memora FAMA damage, with recovery under oracle-backed enforcement.

Source: https://arxiv.org/abs/2610.30698v1

Implementability: 0.72

### 3. Grade whether email agents comply with adaptive phishing

AgentPhishing separates detection from malicious-request compliance. Four of nine evaluated agents had detection below 10% and compliance above 45% under adaptively generated persuasion.

Source: https://arxiv.org/abs/2610.31404v1

Implementability: 0.64

## Implement now

1. Add a live-code precedence rule for descriptive repository guidance, while preserving explicit safety and authorization constraints.
2. Fault memory lifecycle state separately from content and retrieval.
3. Grade email-agent side effects and disclosures independently from phishing classification.
