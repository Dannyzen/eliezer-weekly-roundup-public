# Daily Synthesis: 2026-05-17

Today’s strongest signal is evidence discipline. Long-lived agents should not be trusted because they remember more, run longer, or produce more confident code. They should be trusted when raw evidence survives consolidation, adaptation is tested through replay, generated code carries verified claims, and security benchmarks are mapped to the real threat surface.

## Top findings

### 1. Continuous memory consolidation can corrupt useful experience
- Category: [AgenticAI](../AgenticAI/2026-05-17/reasoning.md#continuous-memory-consolidation-needs-evidence-preserving-gates)
- Durable topic: [Memory Systems](../AgenticAI/memory-systems/memory-systems.md)
- Core source: https://arxiv.org/abs/2605.12978
- Why it matters: self-mutating memory banks can degrade even when built from useful trajectories. Raw episodes need to remain first-class evidence, and consolidated memories need provenance, rollback, and replay tests.
- Implementable now: preserve append-only raw trajectories, store derived memories as lineage-bearing hypotheses, gate high-impact memory writes, and compare behavior with and without consolidated memory.
- Implementability score: 0.84

### 2. Adaptive agents need chronological replay evals
- Category: [AgenticAI](../AgenticAI/2026-05-17/reasoning.md#futuresim-makes-adaptation-measurable-as-chronological-replay)
- Durable topic: [Trajectory-Aware Evaluation](../AgenticAI/trajectory-aware-evaluation/trajectory-aware-evaluation.md)
- Core source: https://arxiv.org/abs/2605.15188
- Why it matters: static benchmarks do not measure whether an agent updates beliefs from new evidence. FutureSim’s event-replay setup turns adaptation, evidence use, and calibration into measurable behavior.
- Implementable now: replay dated tickets, docs, incidents, or news streams; require forecasts and uncertainty; score accuracy, Brier calibration, evidence use, and state updates.
- Implementability score: 0.60

### 3. Coding agents need proof-carrying outputs
- Category: [AgenticAI](../AgenticAI/2026-05-17/reasoning.md#coding-agents-need-verified-assertions-not-just-plausible-patches)
- Core source: https://arxiv.org/abs/2605.14972
- Why it matters: a persuasive patch is not the same as a verified patch. Viverra’s useful pattern is generated code plus assertions plus deterministic verification, with only proven claims presented as guarantees.
- Implementable now: ask agents for invariants and postconditions, run static analyzers/property tests/model checkers where feasible, and attach verified and unverified claims to PR review.
- Implementability score: 0.52

### 4. LLM security benchmarks need threat-surface coverage maps
- Category: [Strategy](../Strategy/2026-05-17/sovereignty.md#llm-security-eval-needs-coverage-maps-not-benchmark-name-dropping)
- Durable topic: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md)
- Core source: https://arxiv.org/abs/2605.15118
- Why it matters: major benchmarks cover non-overlapping slices of the threat surface and at most 25% of the audited Target x Technique matrix. Passing “a benchmark” can hide entire untested STRIDE categories.
- Implementable now: create a Target x Technique coverage matrix, map current evals into it, mark missing cells explicitly, and add service-disruption, token-amplification, model-internals, tool-abuse, retrieval, and memory-poisoning fixtures.
- Implementability score: 0.72

## Highest and lowest implementability today

- Highest: evidence-preserving memory gates at 0.84. This can start with append-only logs, provenance metadata, memory diff review, and replay fixtures.
- Lowest: proof-carrying code generation at 0.52. The artifact pattern is clear, but formal verification remains language- and domain-constrained.

## Actionable moves

1. Treat every consolidated memory as a derived hypothesis with a pointer back to raw evidence.
2. Add a small chronological replay harness for at least one long-running agent workflow: tickets, docs, incidents, or source feeds.
3. Make coding agents propose invariants and postconditions, then let deterministic tools prove or reject them.
4. Replace generic “we ran safety evals” language with a threat-cell coverage map.
5. Keep agent-native tool registries and code graphs on the watchlist, but do not treat trending repos as proof until benchmark claims are reproduced locally.
