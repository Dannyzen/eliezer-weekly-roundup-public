# Daily Synthesis: 2026-05-09

Today's scan found a practical pattern across papers, repos, and vendor security writing: the agent stack is moving from prompt discipline to compiled surfaces and runtime evidence. Tool schemas are being optimized like code, traces are being monitored before final failure, tests are being treated as evolving project state, and security is moving into the parameter/retrieval/host-execution path.

## Top findings

### 1. Tool-schema compilation turns MCP catalogs into an optimization target
- Category: [AgenticAI](../AgenticAI/2026-05-09/reasoning.md#tool-schema-compilation-turns-mcp-catalogs-into-an-optimization-target)
- Durable topic: [Agent Harness Architecture](../AgenticAI/agent-harness-architecture/agent-harness-architecture.md#may-9-update-tool-schema-compilation-is-a-harness-control-surface)
- Core sources: https://arxiv.org/abs/2605.04107, https://github.com/SKZL-AI/tscg, https://arxiv.org/abs/2605.05247
- Why it matters: MCP and function-calling catalogs are not free. Their schema representation affects cost, latency, model choice, and tool-call accuracy.
- Implementable now: audit large tool catalogs; test deterministic schema compression; log schema versions and compression profiles with tool-call outcomes.
- Implementability score: 0.86

### 2. Agent evaluation is shifting to prefix warnings and test-suite co-evolution
- Category: [AgenticAI](../AgenticAI/2026-05-09/reasoning.md#agent-evaluation-is-shifting-to-prefix-warnings-and-test-suite-co-evolution)
- Durable topic: [Trajectory-Aware Evaluation](../AgenticAI/trajectory-aware-evaluation/trajectory-aware-evaluation.md#may-9-update-prefix-monitors-and-test-evolution-move-eval-before-final-failure)
- Core sources: https://arxiv.org/abs/2605.06455, https://arxiv.org/abs/2605.06125, https://github.com/iSEngLab/TEBench, https://github.com/ChromeDevTools/chrome-devtools-mcp
- Why it matters: final answer checks are too late. Long-running tool agents need prefix risk monitors, and coding agents need to prove they can update tests that are broken, stale, or missing.
- Implementable now: label risky trace prefixes; build a small stale/missing-test fixture set; capture browser evidence from Chrome DevTools MCP or equivalent tools as CI artifacts.
- Implementability score: 0.78

### 3. Prompt injection is now a code-execution primitive when frameworks trust tool parameters
- Category: [Strategy](../Strategy/2026-05-09/sovereignty.md#prompt-injection-is-now-a-code-execution-primitive-when-frameworks-trust-tool-parameters)
- Durable topic: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md#may-9-update-prompt-injection-is-now-a-code-execution-primitive)
- Core sources: https://www.microsoft.com/en-us/security/blog/2026/05/07/prompts-become-shells-rce-vulnerabilities-ai-agent-frameworks/, https://arxiv.org/abs/2605.05287
- Why it matters: model output is not a security boundary once framework code maps parsed parameters into files, scripts, vector stores, databases, or tenant data.
- Implementable now: patch affected frameworks; intercept high-risk tool parameters; enforce tenant authorization before retrieval; log model intent, parameters, verdicts, and host detections together.
- Implementability score: 0.74

### 4. Least-privilege skills and host isolation are the next containment layer
- Category: [Strategy](../Strategy/2026-05-09/sovereignty.md#least-privilege-skills-and-host-isolation-are-the-next-containment-layer)
- Core sources: https://arxiv.org/abs/2605.05868, https://arxiv.org/abs/2605.06393, https://huggingface.co/blog/lablab-ai-amd-developer-hackathon/cybersecqwen-4b
- Why it matters: skills, browsers, files, commands, and local cyber models are all useful, but each becomes a privilege boundary when an agent can invoke it.
- Implementable now: add skill permission metadata; route side-effecting skill actions through policy; classify host operations by action, target, context, and effect; keep sensitive cyber triage local where possible.
- Implementability score: 0.55

## Signals

- Highest implementability: tool-schema compilation at 0.86. This is normal engineering: compress, version, benchmark, and trace tool schemas.
- Lowest implementability: least-privilege skills plus TEE-backed host isolation at 0.55. Metadata and policy gates are easy to start; high-assurance host isolation is architecture-heavy.
- Noise filter: GitHub Trending is full of agent memory, skills, browser, and code-index tools. Treat it as demand signal until claims are reproduced inside a local harness.

## Actionable moves

1. Add schema-version and catalog-size fields to every tool-call trace.
2. Build three coding-agent test fixtures: one broken test, one stale passing test, one missing test.
3. Put a parameter policy layer in front of file, shell, browser, database, and vector-store tools.
4. Add permissions and side-effect declarations to every reusable skill before letting agents auto-run it.
5. Keep browser/network/runtime evidence as artifacts, not just screenshots in chat.
