# Daily Synthesis: 2026-05-11

Today's scan found a practical control-plane theme: agents are not bottlenecked only by model IQ. The stronger signals are in harnesses, memory policies, routers, and CI/CD boundaries. Good systems will test long-range tool state, live failure diagnosis, abstention, memory writeback, tool-call routing, and tainted repository inputs before giving agents more authority.

## Top findings

### 1. Agent eval is moving from answer checks to operational stress tests
- Category: [AgenticAI](../AgenticAI/2026-05-11/reasoning.md#agent-eval-is-moving-from-answer-checks-to-operational-stress-tests)
- Durable topic: [Trajectory-Aware Evaluation](../AgenticAI/trajectory-aware-evaluation/trajectory-aware-evaluation.md#may-11-update-eval-must-test-state-propagation-live-failures-and-abstention)
- Core sources: https://arxiv.org/abs/2605.07926, https://arxiv.org/abs/2605.07161, https://github.com/SREGym/SREGym, https://arxiv.org/abs/2605.07769, https://arxiv.org/abs/2605.07935
- Why it matters: final-answer eval misses the failures that break agent deployments: lost intermediate tool state, noisy live systems, unnecessary edits, and broken multi-agent handoffs.
- Implementable now: add DAG tool-use tests, live environment/fault-injection harnesses, stale-ticket abstention fixtures, and state-machine or TLA+ checks for critical coordination protocols.
- Implementability score: 0.76

### 2. Memory systems need usability budgets and writeback firewalls
- Category: [AgenticAI](../AgenticAI/2026-05-11/reasoning.md#memory-systems-need-usability-budgets-and-writeback-firewalls)
- Durable topic: [Memory Systems](../AgenticAI/memory-systems/memory-systems.md#may-11-update-memory-needs-usability-budgets-and-writeback-firewalls)
- Core sources: https://arxiv.org/abs/2605.08060, https://arxiv.org/abs/2605.07313, https://arxiv.org/abs/2605.06731
- Why it matters: memory is active state. Expanded recall can degrade cooperation, irrelevant history can make evidence unusable, and routine chats can poison durable behavioral defaults.
- Implementable now: report budget-compliant reliability, inject irrelevant sessions to find usable-scale limits, audit state diffs before writeback, and store provenance plus rollback metadata with high-impact memories.
- Implementability score: 0.72

### 3. Tool-call model routing is budget governance, not model shopping
- Category: [Strategy](../Strategy/2026-05-11/sovereignty.md#tool-call-model-routing-is-budget-governance-not-model-shopping)
- Durable topic: [Model Router Governance](../Strategy/model-router-governance/model-router-governance.md#may-11-update-tool-call-routing-is-budget-governance-not-model-shopping)
- Core sources: https://arxiv.org/abs/2605.07112, https://github.blog/ai-and-ml/github-copilot/improving-token-efficiency-in-github-agentic-workflows/
- Why it matters: chat routers and provider price lists are too blunt for agents. Tool-call routing needs schema-aware correctness evidence, real token/cost telemetry, and task-specific model selection.
- Implementable now: validate tool calls with AST/schema checks, train or rule-build a cheap router on internal tool-call traces, prune unused MCP tools, and prefetch deterministic context outside the model loop.
- Implementability score: 0.78

### 4. Agentic CI/CD needs taint-aware prompt boundaries and agent-secret scopes
- Category: [Strategy](../Strategy/2026-05-11/sovereignty.md#agentic-cicd-needs-taint-aware-prompt-boundaries-and-agent-secret-scopes)
- Durable topic: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md#may-11-update-agentic-workflow-injection-makes-cicd-an-agent-security-boundary)
- Core sources: https://arxiv.org/abs/2605.07135, https://docs.github.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/configure-secrets-and-variables, https://github.blog/changelog/2026-05-08-more-flexible-secrets-and-variables-for-copilot-cloud-agent
- Why it matters: issue and PR text can flow into privileged repository agents and then into scripts, GitHub API calls, MCP servers, and secrets. Prompt-only protection is not a security boundary.
- Implementable now: treat GitHub event fields as tainted, separate trusted instructions from untrusted content, avoid shell interpolation of model output, scope `GITHUB_TOKEN` and Agents secrets, and add static flow checks.
- Implementability score: 0.70

## Signals

- Highest implementability: tool-call routing at 0.78. A basic version can start with logs, cost maps, schema validation, and rules before training a classifier.
- Lowest implementability: agentic CI/CD taint analysis at 0.70. The controls are clear, but static analysis across YAML, prompts, model outputs, shells, `gh`, MCP, and secrets takes real platform work.
- Noise filter: GitHub search surfaced many high-star agent frameworks and memory projects. I treated those as demand signals unless their README or primary paper added a new control-plane pattern. The strongest selected sources were primary papers, official docs, official changelogs, or repo READMEs.

## Actionable moves

1. Add one long-range tool-state eval where every intermediate tool result is checked, not just the final answer.
2. Add an abstention path to coding-agent tickets: empty patch plus evidence can be success.
3. Put Pass@B and tail retrieval-call burden into memory evals before adding another memory backend.
4. Route tool calls by predicted correctness and real cost, not by model prestige.
5. Treat GitHub event context as tainted until it has passed explicit prompt/dataflow boundaries.
