# Friday Synthesis - 2026-09-18

## Thesis

Trust cannot carry across an agent boundary by default.

This week's strongest findings all expose an inherited-trust failure: a registry entry is treated as an executable tool, a successful call as a completed effect, a final answer as proof of a sound process, a popular skill as a safe capability, or a message as legitimate coordination. The practical stack replaces each inheritance with a typed runtime transition that binds identity, authority, evidence, policy, and rollback.

## Week-level findings

### 1. Tool trust must be continuous from registry to committed effect

A probability sample of 400 MCP servers found that only 48.8% initialized without repair. A separate census of 21,643 registry servers found that 40.58% of multi-version servers changed meaning or destination under stable identifiers, while 4.16% redirected endpoint hosts. OATS then found that 34.7% of 144 live-agent commands carried a consequence class absent from documentation code blocks. At the effect boundary, eight transaction anomalies showed how retries, speculation, concurrency, and partial failure can leave duplicate, missing, provisional, or aborted effects even when each call reports success.

What changed: discovery, identity, permission, and effect completion are different gates. Local step compliance also does not prove that the composed workflow respects cumulative limits or separation of duty.

Implementable now:
- probe startup before catalog admission;
- pin package, source revision, schema hash, transport, endpoint origin, and approved authority;
- run an operator-specific allow, hold, or block check at every side-effecting call;
- require effect IDs, outcome lookup, idempotency keys, compensation preconditions, and trace-level policy predicates.

Implementability score: 0.86

### 2. Final success is too lossy for evaluation; preserve process evidence and replay incidents

ParaRecover contains 10,626 faulted parallel tool-use cases across 14 error types. Models kept Pass@1 above 89% while average process scores stayed below 70, so completion hid weak diagnosis and replanning. A separate audit of 254 SWE-bench submissions found the leading two Verified entries tied at 396 of 500, with all 29 examined frontier pairs statistically unresolved. AgentLSD adds adversarial task evidence: across 3,061 trap trials, deceptive artifacts added about 20 turns and 2,000 reasoning tokens even when the final flag was recovered.

Chronicle supplies the missing regression shape. It records nondeterministic model, tool, and routing boundaries, then replays selected cut points against changed code. Across six incidents, selective replay caught every unsafe-action mutant while a fully stubbed baseline caught none.

What changed: the evaluation object is the evidence-bearing trajectory, not the terminal answer or leaderboard rank.

Implementable now:
- score localization, dependency impact, repair minimality, invalid plans, rounds, cost, and completion separately;
- report statistically separable tiers before using small leaderboard differences for routing or procurement;
- add non-instructional evidence traps to existing evaluations;
- commit production incidents as immutable replay fixtures with selected boundaries left live.

Implementability score: 0.88

### 3. The harness is a conditional policy, not a universal scaffold

A 176-setting study across four models and two coding benchmarks found no universal best harness. Context management mattered most under tight windows, deterministic elision should precede summarization, planning changed role with model capability, and tool richness needed to match shell proficiency. COBRA-Skills reached a similar conclusion for skill improvement: spend evaluations on promising or uncertain candidates rather than rewriting everything, reducing reported optimization cost by 55% to 58% against SkillOpt.

The same conditionality appears in orchestration and serving. Hierarchical collaboration cost about 9.95 times more tokens than a single call, while its gain rose from 2.4 pass@1 points on easy problems to 21.1 on hard ones. Tool-progress signals were several times to an order of magnitude more accurate than pre-call duration predictors at cache-decision points and reduced post-tool p90 time to first token by about 20.7% in the tested configuration.

What changed: prompts, tools, context policies, collaboration topology, and cache decisions should be selected from measured run conditions.

Implementable now:
- run model-by-component ablations under fixed budgets;
- elide deterministic low-value context before model summarization;
- default to one agent, then route to collaboration only when calibrated difficulty predicts value;
- emit monotonic tool progress outside model context and replay serving decisions offline.

Implementability score: 0.79

### 4. Persistent skills are executable policy and need reversible change control

Skill popularity and scanner consensus were weak proxies for safety in a registry that grew from 33,399 to 65,175 listings in 91 days. Of readable skills, 85.06% carried privilege evidence, 77.86% had no stars or comments, and three scanners disagreed on 23,702 of 61,990 shared listings. Repository-skill optimization also proved noisy: a paired frozen-snapshot method reported a 4.9-point gain, but 20 to 26-task holdouts could not separate it from agent variance.

SkillAA gives the state a safer shape. It separates applicability, procedure, exclusion, and dependency objects, routes failures to a specific edit or `NO_PATCH`, retests affected cases, rolls back harmful atomic groups, and commits only a net-positive merged graph.

What changed: a skill file is not advice. Once it persists across runs, it is versioned policy that can expand behavior and authority.

Implementable now:
- assign stable IDs and content hashes to skill objects;
- keep no-skill and prior-version controls at one frozen source snapshot;
- map each proposed mutation to affected-case tests and explicit exclusions;
- commit skill epochs atomically and preserve cheap rollback.

Implementability score: 0.70

### 5. Multi-principal work needs a social harness and observation parity

Across 600 released scheduling runs, capable agents with basic messaging did not reliably produce satisfactory coordination across principals. The social-harness proposal separates identity, ordered envelopes, personal firewalls, task norms, and accountability from transport. At the interface boundary, 546 mobile tasks across 13 apps showed that a human-visible screen can diverge from the agent's observation, producing 77.9% static and 66.9% dynamic misleading rates. Affora's controlled studies point toward the repair: declare machine-readable control identity, relationships, state, and recovery semantics instead of asking agents to infer meaning from pixels or transport alone.

What changed: messaging and visible UI are representations. They are not proof of principal identity, shared meaning, or approval parity.

Implementable now:
- sign inter-agent envelopes with principal, task state, expiry, and allowed transitions;
- keep local effect gates behind every principal's personal firewall;
- hash the exact screenshot, accessibility tree, control target, and action into approval receipts;
- add executable interface checks for identity, state, errors, recovery, and terminal success.

Implementability score: 0.66

## The stack after this week

1. Discover: treat registries as candidate populations, not trusted catalogs.
2. Identify: pin exact source, schema, transport, origin, principal, and version.
3. Authorize: evaluate operator-specific permission at action time.
4. Execute: attach transaction semantics and trace-level policy to every effect.
5. Observe: retain raw progress, process, interface, and resulting-state evidence.
6. Replay: turn incidents and adversarial evidence into selective regression fixtures.
7. Route: choose harness components, collaboration, and serving policy from measured conditions.
8. Evolve: admit persistent skill changes only through frozen controls, localized tests, atomic commit, and rollback.
9. Coordinate: put multi-principal messaging behind identity, norms, personal firewalls, and accountability.

## Implementability range

The highest weekly score is 0.88 for process-aware evaluation and cut-point incident replay. The lowest is 0.66 for a full social harness with observation parity, because identity, norms, interface evidence, and cross-principal accountability still require substantial integration.

## Strongest objection

This design adds manifests, probes, receipts, process scores, and replay fixtures to systems already criticized for control-plane overhead. Several findings are fresh preprints, and GitHub did not recognize a license for the inspected implementation repositories. That weakness is survivable because the first controls are cheap: startup probes, immutable manifests, idempotency keys, process scorecards, and committed incident fixtures. Promote heavier social, compensation, and adaptive-routing mechanisms only after a failure fixture proves the simpler boundary is insufficient.
