# Friday Synthesis: Week ending 2026-06-26

This week's strongest signal is that agent control surfaces are becoming explicit engineering artifacts. The stack is moving from prompt-managed behavior to runtime-managed authority: repo guidance, config lockfiles, workflow blueprints, task ledgers, memory authority records, capability manifests, policy verdicts, and external mutation monitors.

The practical conclusion is blunt: a serious agent system should treat every reusable instruction, memory, tool, workflow, and grant as an object that can be versioned, tested, scoped, revoked, and audited outside the model.

## Executive summary

1. **Repo-local agent control is becoming a supply-chain surface.** `AGENTS.md`, `DESIGN.md`, IDE rule files, and coding-agent configs now need probes, hashes, permission declarations, drift checks, and compiled targets.
2. **Agent services are becoming blueprint-owned runtimes.** ADK, tRPC-Agent-Go, UnifAI, AssetOpsBench, ToolBench-X, and Constraint Tax all push agent workflows toward typed topology, traces, recovery tests, and reviewable execution.
3. **Evaluation is moving from final answers to evidence paths.** GroundEval, RigorBench, MIRROR, ToolBench-X, and GUI-vs-CLI evals make route quality, process discipline, recovery, novelty, and final-state verification first-class.
4. **Agent state is becoming ledgered and event-sourced.** LedgerAgent, ESAA-Conversational, Multi-Agent Transactive Memory, and governed shared memory reject transcript reconstruction as the primary state mechanism.
5. **Authority is becoming manifest-shaped and revocable.** AgentRiskBOM, PORTICO, LedgerAgent, and GitHub issue-field MCP support make autonomy, credential scope, memory scope, and post-task revocation explicit.
6. **Sovereignty lives in policy gates and mutation monitors.** Autoformalized Cedar policies, ShareLock, ToolPrivBench, Phoenix, and the Unfireable Safety Kernel all point to the same rule: prompts can guide, but external systems must enforce.

## Signals

- **Highest individual implementability this week:** `DESIGN.md` at 0.92. The cheap version is just a linted, diffable context file that agents can read before UI edits.
- **Lowest individual implementability this week:** ShareLock-style multi-tool MCP poisoning defenses at 0.46. Catalog diffing and set fuzzing are available now, but robust detection against threshold-split hidden instructions remains underdeveloped.
- **Most durable Wednesday finding:** memory authority. Persistent memory is now an authority object because it can steer future tool use after the originating session disappears.
- **Noise filtered out:** generic model releases, repo README claims without benchmark or artifact grounding, and papers that only improved final-answer scores without trace, authority, or implementation consequences.

## Actionable insights

1. **Make repo guidance testable.** Add probes, hashes, permissions, and CI gates before trusting `AGENTS.md`, `DESIGN.md`, or client-specific agent rule files.
2. **Review workflows as blueprints.** Put agent topology, tools, retrievers, execution backend, and policy profile under code review before rollout.
3. **Evaluate paths, not only outcomes.** Evidence paths, recovery behavior, process discipline, and novelty are now core eval dimensions.
4. **Ledger state before mutation.** High-risk agents need typed state and pre-mutation checks, not transcript inference.
5. **Turn memory into an authority surface.** Origin, scope, derivation, expiration, and elevation should be part of durable memory writes.
6. **Move enforcement out of prompts.** Use policy engines, reference monitors, scoped credentials, and target-system rejection paths.
