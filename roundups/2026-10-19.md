# Daily Synthesis: 2026-10-19

## Thesis

Today's strongest signal is that selection systems need explicit contracts. Dynamic tool catalogs, harness diagnostics, memory consolidation, and proactive notifications all fail when selection is mistaken for authority or evidence.

## Freshness note

No new Monday arXiv listing or stronger agent release had appeared by the 12:00 UTC scan. The four findings below are unreported Friday carry-forwards submitted on October 15 and 16. Hugging Face's feed had no newer agent-systems release. GitHub Trending was used as a demand signal only.

## Top findings

### 1. Dynamic tool discovery belongs behind the gateway

Arcade serves an 8,252-tool catalog through three fixed tools. It recommends only within the gateway's eligible scope and executes under the calling user's authorization. On ToolRet, complete top-ten coverage reached 45.2% versus 28.8% for BM25; the first recommendation covered every required tool in 304 of 327 Codex sessions.

Implementability score: 0.82

Source: https://arxiv.org/abs/2610.23707v1

### 2. Tool-agent scores are also harness scores

ToolBottleneckBench held tasks fixed while varying menus, workflows, returned-state encoding, and registered catalogs. A sixteenfold completion-cap increase nearly removed the pooled large-menu penalty in truncation-heavy configurations, showing that benchmark failures can be budget failures before they are model failures.

Implementability score: 0.86

Sources:
- https://arxiv.org/abs/2610.21098v1
- https://github.com/zichuanxu/tool-bottleneck-bench

### 3. Tool-transition memory is a weak prescription

Across nine models and two benchmarks, tool graph memory rarely produced reliable gains, while one method averaged 2.72 times as many model calls and 2.21 times as many tokens. Random or absent suggestions retained most of the gain. Source-linked situational insights are the better default.

Implementability score: 0.74

Source: https://arxiv.org/abs/2610.21571v1

### 4. Proactive memory needs a timing gate

ProPerMem makes the assistant retrieve tiny target evidence from histories averaging 618K tokens and act only inside human-verified trigger windows. Oracle evidence plus oracle timing reached 96%; chosen timing fell to 38%, and retrieval instead of oracle evidence fell to 15%. Relevance and interruption value must be separate gates.

Implementability score: 0.45

Source: https://arxiv.org/abs/2610.22671v1

## What is implementable now

1. Put tool search and execution behind a fixed gateway interface with scope-first retrieval and per-call authorization.
2. Add paired harness-pressure tests with frozen budgets and deterministic failure records.
3. Replace next-tool graph prompts with source-linked natural-language insights and no-memory controls.
4. Add trigger windows, silence grading, cooldown, and evidence receipts before any proactive assistant pilot.
