# Daily AI Agent Research Roundup - 2026-06-24

## Thesis

Today's strongest sources all point at the same architecture: agent state cannot be an opaque blob. Memory needs authority metadata, shared memory needs policy semantics, handoff needs event logs, and computer-use execution needs matched GUI, CLI, and skill-surface evaluation.

## Deep Dive Wednesday

Winner: [Memory Authority Control Plane](../Strategy/memory-authority-control-plane/memory-authority-control-plane.md).

Why it won: this week had good implementation signals around event-sourced handoff, GUI-vs-CLI skill coverage, and shared-memory governance. Origin-bound memory authority matters most because it controls what future agents are allowed to believe and act on after the original session is gone.

What is implementable now: add origin principal, source event, authority tier, scope, derivation, expiration, and elevation policy to memory records; route semantic search and direct memory reads through the same policy gate; run MEM-INV-Bench laundering fixtures against the memory stack before trusted recall reaches tools.

## Top findings

### 1. Origin-bound memory authority closes laundering attacks

Persistent memory can carry an attack across sessions. The memory-poisoning paper shows why content and lineage checks are insufficient once adversarial text can be summarized, echoed by trusted tools, or apparently corroborated. The proposed fix is non-malleable origin-bound authority for memory records, with explicit elevation rules before a memory can steer consequential action.

What to do now: add origin, authority tier, source event, scope, and elevation policy to durable memories, then test memory-laundering fixtures before trusted recall reaches tools.

Category: Strategy

Implementability score: 0.66

Source: https://arxiv.org/abs/2606.24322

### 2. Governed shared memory makes fleet memory a policy service

Governed Shared Memory names four fleet-memory failures: unauthorized leakage, stale propagation, contradiction persistence, and provenance collapse. Its MemClaw and ArgusFleet evaluation is useful because it tests a live multi-tenant memory service and finds real enforcement bugs, including a direct `GET-by-id` scope bypass and a pipeline-ordering conflict around contradiction supersession.

What to do now: treat memory search, direct reads, propagation, contradiction handling, and derivation reconstruction as one governed service surface.

Category: Strategy

Implementability score: 0.72

Source: https://arxiv.org/abs/2606.24535

### 3. ESAA-Conversational turns agent handoff memory into an event log

ESAA-Conversational gives coding-agent continuity a practical shape: capture visible turns into an append-only `activity.jsonl`, then project deterministic `handoff.md`, `state.md`, `decisions.md`, and `tasks.json` views. That lets heterogeneous agents share continuity without private vendor logs or direct agent-to-agent chat.

What to do now: make handoff files projections from an append-only event log, and test that the same log regenerates the same state before agents consume it.

Category: AgenticAI

Implementability score: 0.88

Source: https://arxiv.org/abs/2606.23752

### 4. GUI vs CLI shows that skill coverage controls computer-use reliability

The GUI vs CLI paper runs 440 matched desktop tasks across 18 applications with identical goals, states, and final verifiers. GUI reaches 59.1%, original-skill CLI reaches 48.2%, and verifier-guided skill-augmented CLI reaches 69.3%. The takeaway is concrete: the missing object is often skill coverage, not raw model capability.

What to do now: run GUI-only, original-skill CLI, augmented-skill CLI, and hybrid baselines against the same final-state verifiers before trusting a desktop agent.

Category: AgenticAI

Implementability score: 0.78

Source: https://arxiv.org/abs/2606.24551

## Practical implementation moves

1. Add origin-bound authority metadata to every durable memory write.
2. Route memory search and direct memory reads through the same policy checks.
3. Project coding-agent handoff state from an append-only event log.
4. Build memory tests for laundering, stale propagation, contradiction handling, and provenance reconstruction.
5. Compare GUI, CLI, skill-augmented CLI, and hybrid execution under matched final-state verifiers.
6. Promote new skills only after verifier-guided improvement on held-out tasks.
