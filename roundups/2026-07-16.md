
# Daily Roundup - 2026-07-16

## Daily thesis

Agents need promotion boundaries around both learning and action. Evaluation, memory, self-improvement, and permission become safer when the runtime turns them into typed decisions with evidence, replay, and explicit authority.

## Top findings

### 1. AgentCompass makes benchmark, harness, and environment separate evaluation objects

The paper and public repository provide an active evaluation substrate with more than 20 benchmarks, async execution, retry evidence, and trajectory analysis. This is the strongest implementation-ready finding because it makes model, scaffold, task, and environment attribution testable.

Primary category: AgenticAI

Implementability score: 0.84

Sources:
- https://arxiv.org/abs/2607.13705v1
- https://github.com/open-compass/AgentCompass

### 2. MemCon makes memory use a learned control policy

A lightweight contextual bandit chooses retrieve, plan inject, re-retrieve, consolidate, forget, or no-op actions from task state and binary outcomes. The paper reports up to 15.2 points higher task success and 5 to 20 percent lower token use across six benchmarks.

Primary category: AgenticAI

Implementability score: 0.73

Sources:
- https://arxiv.org/abs/2607.13591v1
- https://github.com/ericjiang18/MemCon

### 3. Self-improvement needs verified-failure admission and regression-controlled promotion

Phantom Guardrails shows proposers can invent failures. A Terminal-Bench continual-learning study shows one-shot gains can fail to transfer or compound. GPT-Red shows the productive version: explicit threat models, held-out environments, layered safeguards, and human review around automated attack discovery.

Primary category: Strategy

Implementability score: 0.68

Sources:
- https://arxiv.org/abs/2607.14004v1
- https://github.com/relai-ai/Continual-Learning-Terminal-Bench
- https://arxiv.org/abs/2607.13083v1
- https://openai.com/index/unlocking-self-improvement-gpt-red/

### 4. Permission needs a canonical action fingerprint and receipt

CAVA supplies a canonical runtime action and approval-bound receipt model. A survey of 21 permission systems and five commercial agents shows the missing user-policy path from interface preference to internal policy and runtime enforcement.

Primary category: Strategy

Implementability score: 0.56

Sources:
- https://arxiv.org/abs/2607.13716v1
- https://arxiv.org/abs/2607.13718v1

## What is implementable now

- separate benchmark, harness, and environment interfaces in one existing agent evaluation;
- put a small policy wrapper around retrieval with explicit no-op, re-retrieve, consolidate, and forget actions;
- require a reproducible failing trace before any automated prompt, guardrail, skill, or harness edit is admitted;
- replay old tasks and held-out new tasks before promoting a self-improvement;
- bind user approval to a canonical action fingerprint and record enforcement depth plus final-effect evidence.

## Highest and lowest implementability today

Highest: 0.84, AgentCompass. Its repository is active, populated, documented, and broad, although it has no detected license file or release.

Lowest: 0.56, permission-bound canonical actions. The schema and fingerprint are buildable now, but provider adapters, user-policy derivation, and true final-effect enforcement require meaningful architecture.
