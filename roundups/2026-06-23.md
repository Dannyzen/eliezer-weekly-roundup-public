# Daily AI Agent Research Roundup - 2026-06-23

## Thesis

The agent stack is moving from policy prose and final-answer grading to authority artifacts and evidence-path tests. Today's strongest sources all say the same thing: a serious agent system must declare what it can do, revoke temporary power when the subtask closes, and prove through the trace that its final answer or patch came from the right process.

## Top findings

### 1. AgentRiskBOM makes agent authority a machine-readable artifact

AgentRiskBOM proposes an additive bill of materials for agentic systems, covering autonomy level, tool permissions, memory scope, credential scope, approval gates, audit signals, inter-agent communication, and external action capability. The paper reports a JSON-schema compliant artifact, risk scenario library, scorer, deployment mutation diff detector, and evaluation across 13 open-source agentic systems and 52 risk scenarios.

What to do now: create a compact authority manifest for every internal agent workflow and fail CI when tools, credentials, memory scopes, delegation rights, or external effects expand without review.

Category: Strategy

Implementability score: 0.82

Source: https://arxiv.org/abs/2606.21877v1

### 2. PORTICO closes the lingering-authority gap with revocable capabilities

Lingering Authority names a concrete least-privilege failure: an agent may need a resource for one episode, then keep that capability exposed after the episode ends. PORTICO compiles task contracts into grants, closure predicates, and epoch-bound opaque handles. In the paper's comparator tests, PORTICO rejects 10/10 post-closure capability reuses while a non-revoking baseline permits all 10/10.

What to do now: put privileged coding tools behind a reference monitor that issues scoped handles, closes them when subgoals end, and rejects stale replay before file, git, network, or external effects occur.

Category: Strategy

Implementability score: 0.76

Source: https://arxiv.org/abs/2606.22504v1

### 3. GroundEval makes evidence-path evaluation deterministic

GroundEval replaces LLM-as-judge scoring for stateful agents with deterministic checks over what the agent searched, fetched, cited, and was allowed to access. Its useful tracks are silence, perspective, and counterfactual evaluation. The key case study is blunt: LLM judges rated a plausible response above 0.85, while GroundEval scored it 0.000 because the needed artifact never appeared in the trace.

What to do now: add source IDs, raw-output references, access scopes, retrieval timestamps, and deterministic evidence-path checks to high-risk agent evaluations before using judge models.

Category: AgenticAI

Implementability score: 0.84

Source: https://arxiv.org/abs/2606.22737v1

### 4. RigorBench measures coding-agent process discipline

RigorBench scores autonomous coding agents on planning, verification, recovery, abstention, and atomic transition integrity. It reports a 30-task suite and claims structured process discipline improves process quality by 41% on average and downstream correctness by 17%. Treat the numbers as early evidence, but copy the rubric.

What to do now: add process-rubric checks to coding-agent replay suites so a reckless agent that eventually passes is not scored the same as one that plans, verifies, recovers, abstains, and preserves invariants.

Category: AgenticAI

Implementability score: 0.74

Source: https://arxiv.org/abs/2606.22678v1

## Practical implementation moves

1. Define a JSON Schema authority manifest for each agent workflow.
2. Put privileged tools behind scoped, revocable capability handles.
3. Add deterministic evidence-path tests before LLM judge scoring.
4. Score coding-agent process discipline, not only final test pass.
5. Store grant, invoke, close, deny, retrieval, citation, and verifier events in the same trace.
6. Diff authority manifests and process-rubric scores across releases.

## Watchlist

Managing Procedural Memory in LLM Agents introduces the AFTER benchmark for procedural skills across 382 enterprise tasks, 6 roles, and 22 skills. It is worth adding to the next memory-systems pass, especially because it separates local improvement from cross-task, cross-role, and cross-model transfer.

Watchlist source: https://arxiv.org/abs/2606.23127v1
