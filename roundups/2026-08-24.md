# Daily AI and Agent Research - 2026-08-24

## Thesis

A reliable agent stack should turn every soft input into a harder contract before it can matter. Workflow prose should compile into artifact dependencies. Approval should persist as one stateful effect lineage. Memory should prove itself on non-inferable carryover with executable oracles. Skills should earn admission through paired runtime lift.

## Top findings

### 1. Compile workflow prose into artifact contracts

ARTIC improved task resolution by 28 percentage points across 488 instances from 11 workflows, with 32-point cross-model and 56-point repeated-execution consistency gains. The mechanism is explicit reads, writes, constraints, control transfers, local faithfulness obligations, and dry runs.

Implementability score: 0.72

Sources:
- [paper](https://arxiv.org/abs/2608.21341v1)

### 2. Carry authorization through effect closure

AID-Guard binds one approval to one reservation lineage through commit, ambiguous delivery, retry, reconciliation, and recovery. Its evaluated schedules produced no duplicate effects, but the paper's promised artifact is not yet publicly inspectable and strict manifests carry a substantial utility cost.

Implementability score: 0.62

Sources:
- [paper](https://arxiv.org/abs/2608.21159v1)

### 3. Grade memory hygiene with executable hidden oracles

DreamBench-SWE makes earlier-session evidence necessary for later code changes, then grades the final state with hidden executable oracles. Its public v2.1.0 evidence package is usable now, and its conservative results warn against treating one provider configuration as a general memory mechanism.

Implementability score: 0.76

Sources:
- [paper](https://arxiv.org/abs/2608.20664v1)
- [repository](https://github.com/iroiro147/dreambench-swe)
- [v2.1.0 release](https://github.com/iroiro147/dreambench-swe/releases/tag/v2.1.0)

### 4. Measure the marginal value of each skill

ACES found that structural and judge scores weakly predict each other and do not establish runtime value. NVIDIA SkillEvaluator v0.1.0 operationalizes paired with-skill versus no-skill trials, normalized traces, and Skill Lift across agent harnesses.

Implementability score: 0.90

Sources:
- [paper](https://arxiv.org/abs/2608.20614v1)
- [repository](https://github.com/NVIDIA/SkillEvaluator)
- [v0.1.0 release](https://github.com/NVIDIA/SkillEvaluator/releases/tag/v0.1.0)

## What is implementable now

- Define a typed intermediate representation for one existing agent procedure and dry-run every branch before execution.
- Add a durable effect-lineage state machine around one consequential provider action.
- Create multi-session memory fixtures with hidden tokens, stale facts, and executable repository oracles.
- Pilot SkillEvaluator on a small owned skill set with paired no-skill controls.

## Scope and duplicate gate

The selected papers are newly first-listed in the August 24 arXiv batch but were submitted August 20 to 21, so none falls inside a strict trailing 48-hour submission window at run time. Exact IDs and titles were checked against the existing repository and were not previously covered. Hugging Face, GitHub Trending, and official vendor feeds were scanned; no stronger newer finding displaced the four selected papers. External repositories were inspected read-only. No external source code was cloned, installed, built, imported, or executed. NotebookLM remained disabled and untouched.
