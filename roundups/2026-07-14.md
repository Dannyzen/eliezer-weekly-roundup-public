# Daily Roundup - 2026-07-14

## Daily thesis

Tool-using agents need runtime-owned knowledge and commit boundaries. The strongest new work makes faults replayable, moves verified tool behavior to the provider, compiles procedures before execution, and rechecks authority before durable effects.

Three selected papers were submitted July 13 and appeared in the Tuesday arXiv batch. The commit-time authorization paper was submitted July 11 and surfaced in Tuesday's public category list after the weekend.

## Top findings

### 1. AgentCheck turns MCP failures into reproducible regression tests

AgentCheck records a clean tool run, injects one of 12 response faults while replaying matching calls, then reruns the same fault after a mitigation. Its public MIT-licensed repository includes 120 scenarios, deterministic checks, a workbench, and experiment artifacts.

Primary category: AgenticAI

Implementability score: 0.90

Sources:

- https://arxiv.org/abs/2607.11098v1
- https://github.com/aritra741/AgentCheck

### 2. ToolAtlas makes verified tool memory a provider-owned asset

ToolAtlas builds provider-side graphs of tool traces, capabilities, failure boundaries, and compositions through execution-verified probing. The public MIT repository exposes the graph-memory pipeline and a filesystem demonstration, although it does not reproduce the paper's full eight-service surface.

Primary category: AgenticAI

Implementability score: 0.78

Sources:

- https://arxiv.org/abs/2607.11126v1
- https://github.com/PuppyKnightUniversity/ToolAtlas

### 3. Commit-time authorization separates visible success from authorized durability

The paper shows that a DOM snapshot, approval epoch, version token, branch marker, worker result, or shared-memory entry can become stale before the final effect. A same-day OpenBox and Temporal release provides an implementation signal: durable workflows can carry policy checks, approvals, attestations, and audit evidence through the runtime.

Primary category: Strategy

Implementability score: 0.74

Sources:

- https://arxiv.org/abs/2607.10487v1
- https://www.prnewswire.com/news-releases/as-enterprises-move-ai-agents-into-production-openbox-ai-and-temporal-introduce-runtime-governance-for-long-running-agents-302820622.html
- https://github.com/OpenBox-AI/openbox-temporal-sdk-python

### 4. Compile Then Page makes SOPs executable but keeps paging model-gated

A deterministic compiler turns machine-readable SOP constraints into pseudo-code with verifier recipes and evidence-bearing returns. Compiled text never significantly hurts in the reported comparisons and improves where official prose underperforms, but active-frame paging helps strong models and harms weak ones, so paging must be enabled only after a model-specific discipline test.

Primary category: AgenticAI

Implementability score: 0.58

Source:

- https://arxiv.org/abs/2607.11346v1

## What is implementable now

- Run AgentCheck-style timeout, stale-data, schema-drift, permission, poisoning, and corruption fixtures against one MCP server.
- Store verified capability and failure-boundary records with the tool provider rather than inside each consuming agent.
- Compile one critical SOP into explicit states, verifiers, and refusal exits, then compare prose, compiled text, and paged runtime variants.
- Bind temporary authority to one effect and recheck freshness, source version, target, policy epoch, and branch eligibility inside the final commit activity.
- Inspect the OpenBox Temporal SDK in a separate approved sandbox spike before adopting its runtime interceptors.

## Highest and lowest implementability today

Highest: 0.90, AgentCheck. The MIT-licensed repository is populated with the workbench, 120 scenarios, deterministic scoring, results, and documentation.

Lowest: 0.58, Compile Then Page. The compiler pattern is concrete, but no public implementation repository was found and the paging result reverses for weaker models.
