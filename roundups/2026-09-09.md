# Daily Agent Research - 2026-09-09

## Thesis

Agents should not author the evidence that proves their patch, declare the lifecycle state that stops their loop, or inherit every capability the overall task needs. Runtime-owned state, independently frozen tests, per-principal authority, and held-out procedure gates are the practical control surfaces.

## Deep Dive Wednesday: agent-fleet monitoring

MOLE is the week's strongest finding because it adds the missing organizational layer above tool dispatch. It tracks 150 persistent AI-operated accounts across nine stateful services and 30 workdays, verifies completed harm in service state, and measures how much of that harm a security team can catch when it can review only the top one through ten accounts per day.

The implementable pattern is a two-stage monitor: compute cheap action-rarity, peer-deviation, and sequence features for every principal, then route only suspicious account-days to expensive semantic review. The paper's selected cascade reached 0.629 budget-AUC at 2.43 times the modeled cost of uniform GPT-4.1, versus 0.571 for uniform GPT-5.5 at 2.5 times cost.

The caveat is material: one synthetic organization, assigned harmful objectives, two-account collusions, and end-of-day detection. Use the released schema and replay surface for bounded offline validation, not as evidence of production prevalence or as authority for autonomous intervention.

## Top findings

### 1. Runtime state must own completion

Across StageIF deployments, nonterminal-to-terminal reporting gaps spanned 29.4 to 89.3 percentage points. One deployment reached 97.4% adherence at completion but only 8.2% mid-task. Model status should be diagnostic, not the sole stop condition.

Implementability score: 0.90

Source: [The Unreliable Progress Bar](https://arxiv.org/abs/2609.08589v1)

### 2. Scope authority per principal

CapScope fixes a task-wide ceiling from trusted input, then gives each sub-agent only the typed capabilities its role needs. Injected effects fell from 33/75 under the strongest global baseline to 3/75, with 68/75 repairs completed.

Implementability score: 0.76

Sources: [paper](https://arxiv.org/abs/2609.08371v1), [artifact](https://figshare.com/s/86184ed20f66d1f0cf91), [GitHub managed sandbox signal](https://github.blog/changelog/2026-09-08-enterprise-managed-sandbox-in-copilot-for-jetbrains)

### 3. Freeze independent tests before repair

ExecCritic separates test construction from source repair and prevents the Repair agent from editing the admitted test. Poor generated tests lowered resolution, while trained independent test and repair agents reached 72.6% on SWE-bench Verified.

Implementability score: 0.72

Sources: [paper](https://arxiv.org/abs/2609.09133v1), [artifact](https://github.com/MSR-Orchard/execcritic)

### 4. Evolve procedures as held-out-gated graphs

Procedural Graphs localizes runtime guidance to an editable transition graph and admits offline mutations only after held-out validation. It ranked first or tied first in 21 of 24 model-benchmark cells, but no public implementation repository was found.

Implementability score: 0.61

Source: [Procedural Graphs](https://arxiv.org/abs/2609.09153v1)

## What to implement now

1. Derive task progress from runtime state and pending obligations, then compare it with model reports.
2. Give test and repair principals separate write scopes and freeze qualified tests.
3. Add per-principal capability checks at tool dispatch, beginning with reader, runner, and patcher roles.
4. Prototype one small procedural graph with deterministic held-out acceptance before enabling self-evolution.
