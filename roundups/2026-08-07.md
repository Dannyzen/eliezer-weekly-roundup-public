# Daily Roundup - 2026-08-07

## Thesis

Retained state is not authority. Failed trajectories, multi-turn tool history, self-written skills, and gateway traffic all need gates before they can decide the next privileged action.

## Top findings

### TRAJDEBUG attributes the earliest decisive error in long-horizon failures

TRAJDEBUG builds multi-granularity trajectory views, then detects error triggers, classifies error state, and attributes the critical step. On 486 annotated failed trajectories from τ²-Bench and SWE-Bench Pro, diagnosis-guided re-execution improves success by about 10.80 percent on average, and transferred failure memory improves held-out tasks by about 5.70 percent. The public repo ships detector, adapters, eval tools, and a viewer.

Sources:
- https://arxiv.org/abs/2608.06346v1
- https://github.com/THU-KEG/TrajDebug
Implementability: 0.78

### Misleading history can flip tool decisions the model already knows

When History Lies shows that structurally valid but non-authoritative multi-turn tool history can hijack policy. Against an Oracle State view, polluted history flips about 32.1 percent of Qwen3-1.7B decisions the model can otherwise get right. Session memory needs authority labels, not just retention.

Source: https://arxiv.org/abs/2608.06057v1
Implementability: 0.64

### Self-evolving skills need pre-commit admission gates

When Self-Evolution Backfires finds that skill pools are not monotonically helpful. Past a critical size, new skills contaminate performance, and post-hoc rollback recovers little. Verifier-as-Gatekeeper moves checks before a skill becomes executable runtime memory.

Source: https://arxiv.org/abs/2608.05810v1
Implementability: 0.69

### AgentCore exposes temporal policy and rate limits at the gateway

AWS posts from 2026-08-06 make stateful temporal authorization and per-user or per-tool rate limits concrete on AgentCore gateway, and package Automated Reasoning policy work as Agent Skills. The portable pattern is stateful policy plus metered mediation, with enforcement receipts outside the prompt.

Sources:
- https://aws.amazon.com/blogs/machine-learning/securing-ai-agents-with-temporal-policies-in-amazon-bedrock-agentcore/
- https://aws.amazon.com/blogs/machine-learning/configure-rate-limits-for-ai-traffic-on-agentcore-gateway/
- https://aws.amazon.com/blogs/machine-learning/control-agent-behaviors-and-cost-beyond-a-single-action-new-capabilities-in-amazon-bedrock-agentcore/
- https://aws.amazon.com/blogs/machine-learning/agent-skills-for-automated-reasoning-policies-in-amazon-bedrock/
Implementability: 0.84

## What to implement now

1. Attribute failed coding and tool-use runs to an earliest decisive error with linked evidence.
2. Label multi-turn tool traces as verified, superseded, failed-no-effect, or untrusted before reuse.
3. Put draft versus admitted states on skill writeback, with replay before load.
4. Add stateful policy and rate budgets at the gateway, not only request-time allowlists.

## Signal versus noise

- Strongest ready artifact: TRAJDEBUG, with public detector repo and annotated long-horizon failure framing.
- Strongest product control-plane signal: AgentCore temporal policies and gateway rate limits.
- Strongest skill-governance rule: pre-commit verification before skill admission.
- Strongest session-memory warning: polluted history can flip known-good tool policies.
- Watchlist, not top finding: HarnessOpt-Bench and Activity Frames are directionally right but lacked verified public packages in this scan.
- Demand-only noise: GitHub Trending skill packs and fresh one-day harness repos were not promoted without paper or product primary evidence.
