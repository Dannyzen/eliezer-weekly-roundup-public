# Daily Agent Research Roundup: 2026-09-13

## Thesis

Optimize the control substrate, not just the model. Skill improvement needs explicit evaluation allocation, high-fanout workers need lifecycle-aware resource control, and product agents need versioned contracts linking user intent to effects.

## Freshness note

There is no new weekend arXiv batch. The three selected v1 papers were submitted September 10 and first listed Friday, September 11, so they are listing-window carry-forwards. The arXiv API returned HTTP 429; recent category pages, immutable abstract pages, and downloaded PDFs were used instead. Hugging Face, GitHub Trending, GitHub changelog, and public GitHub metadata were also scanned. No external repository was cloned, installed, built, imported, or executed.

## Top findings

### 1. Skill optimization is an evaluation-allocation problem

COBRA-Skills uses a neural reward predictor plus LinearUCB to spend evaluations on promising or uncertain candidates, then mutates the population from accumulated execution evidence. The paper reports 55 to 58 percent lower optimization cost than SkillOpt across six benchmarks and three target models. Its Apache-2.0 repository is populated and includes a dry-run path.

Primary: https://arxiv.org/abs/2609.11682v1
Artifact: https://github.com/Jerry-LuP/COBRA-Skills
Implementability: 0.78

### 2. Interaction effects need versioned contracts

Agent-Integrated Software binds task revisions, referenced objects, role authority, control transitions, postconditions, evidence, and dependency versions. Its controller-epoch model also distinguishes asking an agent to stop from proving that old authority can no longer admit work.

Primary: https://arxiv.org/abs/2609.11381v1
Artifact status: no public implementation was linked.
Implementability: 0.62

### 3. High-fanout agent workers can be memory-bound while compute waits

AgentZip exploits template-relative and cross-sandbox redundancy, prefetches restores, and schedules compression during LLM wait phases. The paper reports up to 8.7 times lower sandbox-owned memory, versus 2.1 times for the Linux configuration, while reducing aggressive-compression slowdown from as high as 3.1 times to 1.40 times. No public AgentZip implementation was linked.

Primary: https://arxiv.org/abs/2609.11294v1
Related substrate: https://github.com/zerobootdev/zeroboot
Implementability: 0.34

## Implementable now

1. Add explicit evaluation budgets, frozen holdouts, candidate digests, and UCB-style selection to skill improvement loops.
2. Add `pre`, `step`, `invariants`, `post`, and `dependencies` fields plus controller epochs to consequential agent operations.
3. Instrument worker resident memory, fanout, model-wait phases, restore faults, and task tail latency before attempting AgentZip-style compression.
4. Join agent adoption metrics to task outcomes rather than treating session and message counts as quality evidence.

## Supporting release signal

GitHub added VS Code Agents activity to Copilot usage metrics on September 11. The API now exposes daily active agent users, session counts, total user messages, and per-user usage flags. This is useful adoption telemetry, but it does not measure task completion, quality, review acceptance, cost, or recovery. Join it to runtime-owned outcomes before using it as an agent-program success metric.
