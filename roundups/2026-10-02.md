# Friday Synthesis: 2026-10-02

Scope: 2026-09-26 through 2026-10-02.

## Thesis

Reliable agent systems are becoming executable evidence pipelines. Stable workflow structure belongs in code. The full model-harness-tool-context-budget configuration is the evaluation unit. Memory policy must expose retrieval and lineage. Approval must bind the complete effect path, and authority must be rechecked against concrete arguments immediately before execution.

The common failure across this week’s papers and releases is hidden state: implicit control flow, unvaried configuration choices, payloads that never arrive, memories that retrieval never exposes, copied claims that masquerade as corroboration, and side effects outside the approved object.

## 1. Put stable control flow in programs, not prompts

GitHub Dynamic Workflows define commands, tool calls, sequential or parallel agents, structured handoffs, checkpoints, resume behavior, schedules, and run limits in code. HEXIS proposes the same separation for skills by compiling procedures into extended finite state machines.

The implementation consequence is immediate: use the model for judgment inside a state, while the runtime owns progression, joins, retries, limits, and terminal receipts.

Sources: [GitHub Dynamic Workflows](https://github.blog/changelog/2026-10-01-dynamic-workflows-in-copilot-cli-and-the-copilot-app/), [operating documentation](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-dynamic-workflows), [HEXIS](https://arxiv.org/abs/2609.30123v1)

Implementability score: 0.90

## 2. Evaluate the deployed system and the benchmark contract together

Agents Are Systems, Not Models shows that repeated runs of one configuration account for about 54 percent of outcome variance across four scientific coding tasks. Task information mattered more than model size or time budget, and a dedicated verification tool changed behavior more than a self-verification prompt.

The executable-contract audit shows why system evaluation must extend below the harness. Across 34 mutating tools in four benchmarks, the authors found seven tool defects and one evaluator property that could report success without the intended state change.

The practical unit of evaluation is the model, harness, tools, context, budget, environment, evaluator, and repeated-run distribution.

Sources: [Agents Are Systems, Not Models](https://arxiv.org/abs/2610.01618v1), [public trajectory repository](https://github.com/lusxvr/rethinking-agent-evaluation), [Executable-Contract Audit](https://arxiv.org/abs/2609.37315v1), [audit artifact](https://github.com/rohithreddybc/tool-contract-conformance)

Implementability score: 0.82

## 3. Security verdicts need delivery receipts and exact effects

pikit makes prompt-injection evaluation composable across attack wording, delivery carrier, prevention strategy, target agent, trace, and verdict. That structure matters because a separate audited harness changed measured attack success from 21.7 percent to 1.2 percent after correcting payload delivery and tool-argument scoring.

A security score without proof that the payload reached the intended surface and that the grader checked the realized effect is weak evidence. Use carrier-specific delivery receipts, exact argument predicates, and post-effect verification.

Sources: [pikit](https://arxiv.org/abs/2609.36817v1), [public toolkit](https://github.com/Tencent/AI-Infra-Guard/tree/main/Research/pikit), [Auditing Agent Security Benchmarks](https://arxiv.org/abs/2609.32691v1)

Implementability score: 0.88

## 4. Memory needs controlled exposure, lineage, and scope

Causal Memory Policy shows that store-level utility is unidentified when retrieval never exposes the memory. It reports identification failure for 54 percent of required LongMemEval memories and 67 percent on LoCoMo. The shared-memory admission benchmark shows a second hidden-state failure: uncontested false beliefs were repeated in 0.97 to 0.99 of probes, while a declared-source-type gate reduced false adoption to 0.06 to 0.09.

PrivDrift adds the privacy boundary. Across three models and 1,000 dialogues, hybrid secret leakage remained between 38.7 and 54.6 percent; extra topic drift did not reliably erase the risk.

Memory is therefore an evidence and authority system. Retention needs controlled retrieval exposure. Corroboration needs provenance-root collapse. Retrieval needs audience and purpose scope that survives derivation and consolidation.

Sources: [Causal Memory Policy](https://arxiv.org/abs/2610.02070v1), [Epistemic Admission in Shared Agent Memory](https://arxiv.org/abs/2609.30813v1), [PrivDrift](https://arxiv.org/abs/2609.30094v1)

Implementation scores: 0.68 for causal retrieval policy, 0.72 for scoped memory authority

## 5. Approval must cover the effect closure, then authority must be checked again at dispatch

Agent Approval Laundering shows that a truthful approved command can trigger unrecorded package hooks, generated files, network calls, or nested tools. Across 111 approval-object pairs, decision-time metadata reduced residual records from 40 to 13. PACE complements this by checking provenance, capability, and effect scope at the final tool boundary.

The operating pattern is a two-stage release: approve a frozen action manifest and its expanded effect closure, then recheck authenticated scope, provenance, concrete arguments, target, and effect class immediately before execution. A post-effect receipt closes the loop.

Sources: [Agent Approval Laundering](https://arxiv.org/abs/2609.28586v1), [GitHub proof of presence](https://github.blog/changelog/2026-09-24-require-proof-of-presence-for-high-impact-actions), [PACE](https://arxiv.org/abs/2610.01349v1)

Implementation scores: 0.78 for effect-closure approval, 0.54 for full provenance-aware dispatch enforcement

## What is implementable now

1. Encode one recurring multi-agent workflow as a versioned program with typed stage outputs, deterministic joins, review checkpoints, and a run budget.
2. Evaluate one deployed agent with repeated factorial cells across model, task information, verifier tool, and time budget.
3. Add executable contracts and mutation tests to every state-changing tool in the evaluation environment.
4. Require delivery receipts and exact argument or effect predicates in prompt-injection tests.
5. Add provenance roots, source classes, contest state, and bounded retrieval exploration to memory evaluation.
6. Freeze action manifests before approval, expand transitive effects, and verify the realized state change after execution.

## What remains architecture-heavy

- a reusable compiler from natural-language skills into safe state machines
- production-grade provenance propagation across retrieval, planning, memory, and tool arguments
- unbiased long-horizon memory value for unseen future queries
- effect-closure prediction across opaque package hooks and external services
- final-dispatch enforcement that preserves utility across heterogeneous tools and gateways

## Strategic question

If a user approves the visible command while the environment can still execute unrepresented downstream effects, is that approval, or interface theater?
