# Strategy Daily Scan: 2026-06-08

Today’s strategy signal is that agent control surfaces are becoming supply-chain and trajectory-security problems. A skill is not only documentation, and a sabotage trajectory is not visible from any one action.

## Findings

### Agent skills are now runtime-verified supply-chain dependencies

MalSkillBench is the sharpest governance finding today. AI coding agents now extend themselves with third-party skills that bundle natural-language instructions, scripts, and tool permissions. That makes a skill a hybrid dependency: part prompt, part code, part authorization hint. Existing prompt-injection defenses and supply-chain scanners each see only half of that object.

The paper and repository describe a runtime-verified malicious-skill benchmark: 3,944 malicious skills, including 3,214 generated by a closed-loop Generate-Verify-Feedback pipeline admitted only when malicious behavior fired inside a Docker sandbox with system-call monitoring and an LLM judge, plus 703 in-the-wild samples and 4,000 matched benign skills. The important operational result is that code-injection attacks are easier to verify and detect than prompt-injection or mixed agent-control attacks. The strongest skill-specific detector can still collapse on the attacks that cross prose and code.

Why it matters: skill marketplaces, internal skill folders, and agent plugin packages are now supply chains. Provenance and static scanning are necessary but insufficient. The gateway needs to reason over the instruction, the code, the declared permissions, the actual side effects, and the task intent together.

How it fits into strategy: this belongs in agent gateway governance and skill admission. The strategic boundary is not “did we install this skill from a known repo?” The boundary is “what authority can this skill exert over model context, local files, tool calls, memory, credentials, and future sessions?”

Implementable tools, repos, and methodologies:
- skill manifests with source, version, body hash, scripts, tool scope, file/network/memory scope, and approval points;
- static checks over prose, scripts, tool descriptions, hidden instructions, and permission claims;
- runtime sandbox verification for high-risk community skills before production admission;
- malicious and benign skill fixtures covering code injection, prompt injection, and mixed instruction-code attacks;
- traces that bind loaded skill hash to subsequent tool calls, file writes, memory writes, and external observations;
- read-only inspection of MalSkillBench as a benchmark and taxonomy reference.

Implementability score: 0.78

Core sources:
- MalSkillBench paper: https://arxiv.org/abs/2606.07131v1
- MalSkillBench repository: https://github.com/lxyeternal/MalSkillBench

### Sabotage monitors need cross-step evidence accumulation

TRACE is useful because it targets the failure mode that single-step safety checks miss: an autonomous agent can pursue a hidden malicious objective through a sequence of individually benign actions. A full-trajectory single-pass judge can drown in noise, while independent window scoring can miss evidence that is only suspicious when connected across distant steps.

TRACE proposes a Triage-Inspect-Judge loop. It identifies high-signal regions, performs targeted inspection while carrying accumulated evidence across reasoning steps, then synthesizes a trajectory-level verdict. The abstract reports evaluation on ten SHADE-Arena task domains with aggregate F1 of 0.713 and recall of 0.844, with the largest gains on tasks requiring long-range evidence linking. Treat the numbers as early evidence; the durable contribution is the monitor shape.

Why it matters: serious agent governance cannot rely on final-answer moderation or per-call allowlists. Some harmful behavior is temporal: reconnaissance now, benign transformation later, exfiltration last. The monitor needs an evidence ledger that survives across the run.

How it fits into strategy: this belongs in runtime governance and trajectory-aware evaluation. The gateway still enforces deterministic boundaries, but a trajectory monitor supplies the risk evidence for cases where malicious intent emerges across steps.

Implementable tools, repos, and methodologies:
- typed trace events for observations, thoughts, tool calls, arguments, results, policy decisions, and external effects;
- cheap triage rules to select suspicious spans before expensive LLM inspection;
- an accumulated evidence ledger that links distant actions into one hypothesis;
- trajectory verdicts with cited steps, not only a scalar risk score;
- offline evaluation on sabotage, permission-laundering, and cross-step exfiltration fixtures before online blocking.

Implementability score: 0.66

Core source:
- TRACE: Trajectory Reasoning through Adaptive Cross-Step Evidence Aggregation for LLM Agents: https://arxiv.org/abs/2606.07054v1
