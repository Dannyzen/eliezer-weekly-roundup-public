# Friday Synthesis: 2026-11-20

## Weekly thesis

The agent stack is becoming a system of explicit runtime objects rather than a collection of prompts. This week's strongest work makes updates compete with incumbents, memory carry lineage, sessions expose held resources, and proposed actions cross a deterministic effect boundary before they gain authority.

## Five durable findings

### 1. Candidate state needs prospective proof

Memory entries, personal-agent updates, and auditor decisions should be accepted by their measured effect on the next task. CoReMem, Safe Personal RSI, DriftGuard, and ReA-Bench each replace static plausibility with controlled comparison, paired evidence, or counterfactual replay.

Implement now: incumbent-versus-challenger evaluation, fixed replay suites, separate task and policy metrics, bounded promotion, and rollback receipts.

Implementability score: 0.72

Sources: [CoReMem](https://arxiv.org/abs/2611.17316v1), [Safe Personal RSI](https://arxiv.org/abs/2611.23651v1), [DriftGuard](https://arxiv.org/abs/2611.25583v1), [ReA-Bench](https://arxiv.org/abs/2611.16493v1)

### 2. Memory is a governed lifecycle

MemoSync makes memory visible and co-managed, Jetriever ranks by utility, DriftGuard attributes harmful influence, and Forget the Lineage extends deletion to derived state. The durable object needs source, derivation, scope, utility evidence, review state, and erasure receipts.

Implement now: source-linked records, review and quarantine states, utility evaluation on downstream tasks, derivation graphs, and reversible deletion workflows.

Implementability score: 0.66

Sources: [MemoSync](https://arxiv.org/abs/2611.24165v1), [Jetriever](https://arxiv.org/abs/2611.21478v1), [Forget the Lineage](https://arxiv.org/abs/2611.18133v1)

### 3. Session lifecycle is a capacity primitive

Held While Waiting shows that reserved environments can dominate agent capacity while model calls wait. HerAgent, ModHarness-RL, and Metal Sandbox show the same design pressure at smaller scales: checkpoint harness steps, schedule scarce resources below the model, and treat the harness as versioned executable state.

Implement now: terminal-path session close, held-environment metrics, semantic checkpoints, deterministic device queues, and real-wait capacity tests.

Implementability score: 0.82

Sources: [Held While Waiting](https://arxiv.org/abs/2611.26480v1), [HerAgent](https://arxiv.org/abs/2611.18443v1), [ModHarness-RL](https://arxiv.org/abs/2611.18533v1), [Metal Sandbox](https://arxiv.org/abs/2611.17294v1)

### 4. Effects need deterministic release gates

CapLite, System 1 Agents, runtime verification, and Tether all reduce the acting model's ability to define its own security boundary. The runtime should compile or observe typed effects, carry stateful policy outside context, and commit only after deterministic checks.

Implement now: credential separation, typed action schemas, disposable pre-execution sandboxes, effect normalization, deny-overrides policy, and receipts.

Implementability score: 0.76

Sources: [CapLite](https://arxiv.org/abs/2611.17115v1), [System 1 Agents](https://arxiv.org/abs/2611.21053v1), [Runtime Verification](https://arxiv.org/abs/2611.23074v1), [Tether](https://arxiv.org/abs/2611.25599v1)

### 5. Provenance does not close authority

Intent Contracts records user words and scope. Signed, Valid, and Unauthorized shows that authentic fields and signatures still fail when reachable execution paths exceed the mandate. The last trusted boundary must compare the full effect envelope with the grant.

Implement now: principal and resource binding, retry and sequence limits, conservative reachability checks, independent revocation, and refusal receipts.

Implementability score: 0.68

Sources: [Intent Contracts](https://arxiv.org/abs/2611.24025v1), [Signed, Valid, and Unauthorized](https://arxiv.org/abs/2611.24989v1)

## What is implementable now

1. Add terminal-path session close and held-resource telemetry before buying capacity.
2. Put challenger-versus-incumbent gates around memory and agent updates.
3. Give memory source IDs, derivation edges, review state, and erasure receipts.
4. Separate planning credentials from execution credentials.
5. Compile proposed work into typed action manifests and commit only after policy checks.

## What remains architecture-heavy

- causal memory attribution across interacting memories;
- lineage-complete erasure across backups and external systems;
- general effect inference for arbitrary scripts and services;
- authority closure across unknown downstream contracts;
- learnable harnesses that improve real operations rather than benchmark scores.

## Conceptual model

The stack now has four explicit objects:

1. Candidate: state that must beat an incumbent before promotion.
2. Memory: state with source, lineage, scope, utility, and lifecycle.
3. Session: state with resources, checkpoints, terminal conditions, and receipts.
4. Action manifest: proposed authority with typed effects, policy, and a commit boundary.

The control plane owns transitions between these objects. The model proposes content inside them.
