# Friday Synthesis: Week ending 2026-05-29

This week’s strongest signal is that the agent stack is becoming an admission-controlled runtime. The important question is no longer “can the model call tools?” It is “which specification, skill, memory write, retrieval policy, team topology, tool artifact, browser surface, or sandboxed process is allowed to shape this run, and what evidence proves it behaved?”

The practical model is clear: move gates upstream, preserve evidence downstream, and make every high-authority surface auditable. Specifications get reviewed before code. Skills and generated tools get validated before admission. Memory writes carry provenance. Multi-agent communication is budgeted by confidence and disagreement. MCP servers sit behind identity, scopes, approvals, and rollback. Evaluation grades traces and work products, not just final answers.

## Executive Summary

1. **Evaluation moved from answers to evidence packages.** SpecBench, goal-persistence metrics, operations fault-injection, LiveBrowseComp, ITBench-AA, RAMPART, and Gram all make final-answer grading look thin. Serious agent eval now needs specs, traces, state snapshots, artifacts, verifier outputs, fault injections, and adversarial trajectories.
2. **Routing widened beyond model choice.** Workflow placement, per-query retrieval configuration, tool-wait scheduling, and confidence-gated multi-agent topology are now routing decisions. Static RAG pipelines and all-agent chat are wasteful defaults.
3. **The gateway became the sovereignty boundary.** MCP metadata, permission laundering, validation-carrying generated tools, Chrome Enterprise MCP, KV-cache leakage, sandboxing, and sabotage auditing all point to the same control plane: identity, capabilities, provenance, approval, rollback, and trace review.

## Signals

- **Highest single implementability:** per-query retrieval configuration at 0.84. The implementation path is direct: expose retrieval settings, classify query intent, log chosen settings, and evaluate freshness/recall/cost tradeoffs. Source: https://arxiv.org/abs/2605.27361
- **Highest weekly category finding:** agent evaluation as evidence packages at 0.82. The core work is plumbing and discipline: specs, traces, artifacts, state snapshots, verifier outputs, and adversarial scenarios.
- **Lowest single implementability:** KV-cache sharing as a hidden data boundary at 0.42. The risk is real, but practical mitigation still needs architecture choices around cache isolation, tenancy, provenance, and accelerator economics. Source: https://arxiv.org/abs/2605.22786v1
- **Best immediate build target:** a pre-code spec-review gate plus evidence-package trace schema. This is cheap relative to model training and immediately improves coding-agent governance.
- **Noise filter:** deprioritize star-velocity repos, generic agent wrappers, undifferentiated skill libraries, and demo-only browser agents unless they expose validation artifacts, replayable traces, policy gates, or concrete runtime control surfaces.

## Actionable Insights

1. **Add a spec-review gate before coding-agent edits.** Require omissions, ambiguities, contradictions, acceptance-test gaps, and non-functional risks before implementation.
2. **Standardize an evidence package.** For every agent run, keep prompt/spec input, source evidence, tool trace, state snapshot, intermediate artifacts, verifier outputs, final answer, and failure labels.
3. **Treat skills and tools as admitted runtime state.** Version them, test them, hash them, trace them, quarantine them, and require promotion evidence.
4. **Make routing explicit.** Record model, retrieval policy, workflow placement, wait budget, agent topology, and confidence thresholds as first-class trace fields.
5. **Put privileged MCP behind a gateway.** Scope OAuth, split diagnosis from mutation, require approvals, record before/after state, and preserve rollback evidence.
6. **Use executable browser workspaces.** Browser agents should leave scripts and verifiable state assertions, not just screenshots and prose.
7. **Run deployment-shaped red teams.** Test sabotage, concealment, evidence manipulation, policy bypass, and overeagerness in realistic tool-bearing scenarios.
8. **Protect latent state.** Cache, memory, embedding, summary, and shared-client boundaries deserve the same threat modeling as API keys.
