# Daily Roundup - 2026-07-13

## Daily thesis

Agent reliability is moving from final verdicts to explicit intermediate artifacts. The strongest new papers make failure stages, memory promotion, verification intent, and persistent instruction updates visible enough to test before they control side effects.

The selected papers were submitted July 10 and appeared in the Monday arXiv batch after the July 12 scan.

## Top findings

### 1. Failure as a Process turns coding-agent errors into intervention windows

The paper labels the decisive error, empirical lock-in, and first observable symptom across 1,794 complete CLI coding-agent trajectories. Median failed-run timestamps are steps 7, 12, and 16, and 28% of failures never surface externally.

Primary category: AgenticAI

Implementability score: 0.80

Sources:

- https://arxiv.org/abs/2607.09510v1
- https://github.com/xz-Sean/cli_trajectory_analysis

### 2. Property templates bind formal proof and runtime testing to one intent

A typed property template produces both a Lean 4 proof and an executable property-based test. Across 400 Apache Spark properties, the approach increases proof success by up to 2.6x, reduces proof hallucinations by 59%, cuts test-intent mismatches from 22 to 1, and reduces synthesis cost by up to 5.7x.

Primary category: AgenticAI

Implementability score: 0.72

Sources:

- https://arxiv.org/abs/2607.09072v1
- https://anonymous.4open.science/r/AgentLeanDiscprop-1597/

### 3. Shared selective memory keeps durable configuration and drops stale traces

The architecture persists task specifications, schemas, tool configurations, and output constraints, while excluding old reasoning and tool traces from the next active context. It combines Git-versioned artifacts, draft isolation, RBAC, and runtime data binding, but the implementation and datasets are not public.

Primary category: AgenticAI

Implementability score: 0.68

Source:

- https://arxiv.org/abs/2607.09493v1

### 4. GRACE makes evolving instructions a graph-validated promotion pipeline

GRACE represents persistent system guidance as typed nodes and edges, validates changed neighborhoods, consolidates the growing artifact, and reconstructs deployable text. The method is strategically important, but its advertised repository returned 404 and the evaluation is limited to one telecom domain with a fixed harness.

Primary category: Strategy

Implementability score: 0.48

Source:

- https://arxiv.org/abs/2607.09175v1

## What is implementable now

- Add `t_err`, `t_lock`, and `t_obs` to coding-agent postmortems and place prefix checks before irreversible changes.
- Separate durable configuration memory from raw episodes and require explicit promotion into active context.
- Pilot one recurring invariant as a shared proof and property-based-test template.
- Atomize one mutable system instruction into typed clauses, validate a local graph change, and replay before promotion.

## Highest and lowest implementability today

Highest: 0.80, Failure as a Process. Its annotation schema, codebook, dataset, and analysis scripts are public, although raw trajectories and a declared repository license are missing.

Lowest: 0.48, GRACE. The pattern is concrete but architecture-heavy, domain-limited, and its advertised public repository is unresolved.
