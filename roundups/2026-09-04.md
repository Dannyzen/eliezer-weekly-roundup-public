# Daily Agent Research - 2026-09-04

## Thesis

Observed success is not authorization. A patch can pass the issue tests and still fail the review constraint. A replica can hold the latest fact and still execute a plan derived from the previous version. A plugin can stay trusted while its hooks become a host-privileged control plane. A serving stack can report zero tool calls while the model is emitting them.

## Top findings

### 1. Functional tests hide reviewer rejection

SWE-Gate adds an executable review-constraint oracle beside the functional suite. Across 303 instances from 75 Python repositories, 221 of 644 functionally successful repairs fail the constraint tests (34.3% hidden-failure rate). GPT-5.5 reaches 74.9% FSR and 52.8% JSR. Providing the constraint text improves joint success, not functional success.

Implementable now: dual F/C oracles, non-compliant reference patches, FSR/CFR/JSR/HFR reporting, constraint text as task input with hidden constraint tests.

Implementability score: 0.74

Sources:

- https://arxiv.org/abs/2609.04167v1
- https://github.com/DeepSoftwareAnalytics/SWE-Gate

### 2. Lifecycle-hook updates are a privileged control plane

HookPry shows that harness lifecycle hooks run host-privileged commands as configuration, including at times the LLM never observes. Across seven harnesses and 1,000 end-to-end runs, verified E2E-ASR is 77.9% macro-average. Hermes is 92.5%. Claude Code is 52.5%. Privilege Escalation averages 93.5%. Native hooks beat translated MCP descriptions (92.0% vs 56.0% on the paired 50-target set).

Implementable now: pin hook command hashes, treat plugin update as a new admission, emit hook-event receipts even when the model is out of the loop, add hook-only mutation fixtures. Do not implement the attack.

Implementability score: 0.62

Source: https://arxiv.org/abs/2609.03884v1

### 3. The serving interface can delete the tool-using trajectory

On BFCL v4, changing only the serving adapter moves the same model from 0.00 to 0.96 / 0.19. Template and parser main effects are zero; the interaction is the entire effect. Qwen2.5-Coder 32B emits 80/100 well-formed calls while the server parses 0/100. GRPO can raise pass@1 while multi-turn rescues stay flat at 6 to 9 of 540, and a function-calling GRPO run can execute zero tools while the critic reward climbs.

Implementable now: log raw bytes vs parsed calls vs executor admissions, 2x2 template/parser checks, fail closed on silent empty `tool_calls`.

Implementability score: 0.80

Sources:

- https://arxiv.org/abs/2609.03966v1
- https://github.com/nebula-1999/Interface-Induced-Trajectory-Censoring

### 4. Fresh memory is not a valid plan

PlanFence distinguishes replica freshness from lineage validity. Plans cite exact parent record IDs. The executor validates only action-relevant parents, then replans or blocks. In 30 live workflows with a post-plan revision, freshness-only execution issued the obsolete action every time (0/30). PlanFence completed all 30 without an invalid action.

Implementable now: parent-ID stamps on plans, action-scoped validation, freshness-only negative fixtures.

Implementability score: 0.58

Source: https://arxiv.org/abs/2609.03340v1
