# Daily Agent Research Roundup - 2026-08-30

## Thesis

Agent reliability depends on binding change, context, and authority to explicit identities. Verify each harness change against the behavior it touches, separate mutable persona from audited execution, preserve labels across persistent state, and make permission checks survive resource substitution.

## Top findings

### 1. Verify harness changes on behavior-relevant evidence

HarnessLens selects candidate-specific verification tasks from trajectories, affected components, intended behavior, and regression risk. Across three harnesses and four benchmarks, it reports 7.6 to 13.6 percent average held-out improvement with less evaluation budget than fixed-set baselines.

Implementable now: add change manifests, impact sets, paired trials, and attribution notes before admitting prompt, tool, hook, or runtime changes.

Implementability score: 0.78

Sources: [paper](https://arxiv.org/abs/2608.27311v1), [repository](https://github.com/jhxu5214/HarnessLens)

### 2. Bind permission checks to the resource actually used

Claude Code v2.1.251 fixes symlink-swap, plugin path-traversal, pre-permission-read, search-path deny-rule, sandbox-output, browser-permission, and security-sensitive configuration gaps. It also adds model-switch hooks and prompt-cache telemetry.

Implementable now: update after normal release review, then add check-and-use identity fixtures and trace model or configuration changes as authority events.

Implementability score: 0.97

Source: [Claude Code v2.1.251](https://github.com/anthropics/claude-code/releases/tag/v2.1.251)

### 3. Separate mutable persona from audited execution

Persona-Execution Separation places tone, instructions, and self-presentation in a permissive domain while execution identity, state, credentials, and audit remain stable. A typed bridge returns status summaries and gates data-body egress.

Implementable now: separate persona and execution configuration, define typed bridge requests, and record persona version beside the execution receipt. The paper is a single-case architecture study, so this is a design pattern rather than a broadly replicated result.

Implementability score: 0.61

Source: [paper](https://arxiv.org/abs/2608.27427v1)

### 4. Preserve information-flow labels across persistent state

SPA plans before reading untrusted outputs, stores labeled artifacts, and exposes semantic metadata rather than raw payloads to later planners. It reports 0 percent and 0.2 percent attack success on AgentDojo and AgentDojo-MQ, with reuse falling from 95.4 percent without IFC to 89.9 percent with IFC.

Implementable now: add provenance and integrity labels to persistent artifacts, split metadata from values, and test delayed attacks across queries. Full adoption requires meaningful runtime architecture.

Implementability score: 0.68

Source: [paper](https://arxiv.org/abs/2608.27234v1)
