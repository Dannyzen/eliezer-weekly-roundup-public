# Friday Synthesis: Week ending 2026-05-15

This week’s strongest signal is that the agent stack is becoming a runtime substrate, not a chat interface. The week was not mainly about better demos. It was about compiling tool schemas, routing capabilities, scheduling tools asynchronously, evaluating trajectories instead of final answers, governing memory and skills as stateful software, and treating coding/browser agents as live privileged sessions.

The practical direction is clear: serious agent systems need build-system discipline. Version the tool surface. Record the workflow profile. Gate the parameters. Preserve the path through GUI and tools. Track which memory state was trusted. Route models with cost and tool correctness in the trace. Then use those traces to improve agents rather than guessing from final success.

## Executive Summary

1. **The harness became a compiler and scheduler.** TSCG, DADL, QVeris, GitHub token-efficiency work, FlowCompile/CANTANTE-style profiling, and AsyncFC all point to the same layer: tool schemas, workflow profiles, capability routing, model choice, token budgets, and futures belong in a versioned runtime control plane.
2. **Evaluation moved into the trajectory.** PrefixGuard, TEBench, EvalMonkey, SREGym, AgentEscapeBench, AgentLens, SWE-Cycle, and BenchJack make final pass/fail look obsolete. The important evidence is the path: context gathering, tool sequence, test evolution, retries, setup, recovery, and lucky-pass detection.
3. **State became the security boundary.** Memory, skills, GraphRAG citations, browser observations, GitHub Actions, MCP calls, and coding-agent sessions all showed the same risk: untrusted context can become a future action unless provenance, consent, sandboxing, and policy follow it through the stack.

## Deep Dives

### 1. Runtime compilation is the highest-leverage build move
- Category: [AgenticAI](../AgenticAI/2026-05-15/reasoning.md#runtime-compilation-turns-tool-schemas-capability-routers-workflow-profiles-and-async-calls-into-control-surfaces)
- Durable topic: [Agent Harness Architecture](../AgenticAI/agent-harness-architecture/agent-harness-architecture.md)
- Core sources: https://arxiv.org/abs/2605.04107, https://github.com/SKZL-AI/tscg, https://arxiv.org/abs/2605.05247, https://github.com/QVerisAI/qveris-agent-toolkit, https://arxiv.org/abs/2605.15077v1, https://github.blog/ai-and-ml/github-copilot/improving-token-efficiency-in-github-agentic-workflows/
- Why it matters: the agent’s effective capability is shaped by how tools are described, pruned, routed, scheduled, and measured. A giant MCP catalog is not neutral context; it is a runtime surface that can waste tokens, reduce accuracy, and hide cost loops.
- Implementable now: compile tool schemas, route capabilities instead of exposing whole catalogs, audit token usage, add future IDs and `await_future` for slow tools, and log schema versions, model choices, token budgets, and future lifecycles.
- Implementability score: 0.80

### 2. Trajectory-aware evaluation is replacing final-answer grading
- Category: [AgenticAI](../AgenticAI/2026-05-15/reasoning.md#evaluation-moved-from-final-answers-to-trajectory-and-process-evidence)
- Durable topic: [Trajectory-Aware Evaluation](../AgenticAI/trajectory-aware-evaluation/trajectory-aware-evaluation.md)
- Core sources: https://arxiv.org/abs/2605.06455, https://arxiv.org/abs/2605.06125, https://github.com/Corbell-AI/evalmonkey, https://arxiv.org/abs/2605.07161, https://github.com/SREGym/SREGym, https://arxiv.org/abs/2605.12925, https://arxiv.org/abs/2605.13139, https://arxiv.org/abs/2605.12673
- Why it matters: agents can pass by accident, fail too late, exploit stale tests, or succeed with an unusable process. The trace is the artifact that tells you whether the system is improving.
- Implementable now: persist trajectories, add prefix monitors, run chaos tests, grade setup/test/review/merge behavior, detect lucky passes, and turn failures into replayable regression fixtures.
- Implementability score: 0.80

### 3. Memory and context are governed state, not recall
- Category: [AgenticAI](../AgenticAI/2026-05-15/reasoning.md#memory-and-context-became-governed-state-with-provenance)
- Durable topics: [Memory Systems](../AgenticAI/memory-systems/memory-systems.md), [Context Economy for Agents](../AgenticAI/context-economy/context-economy.md)
- Core sources: https://github.com/MemoriLabs/Memori, https://github.com/smaramwbc/statewave, https://arxiv.org/abs/2605.06132, https://arxiv.org/abs/2605.12477v1, https://seokwonjung-jay.github.io/meme-eval/, https://arxiv.org/abs/2605.15109v1
- Why it matters: long-running agents need memory admission, memory budgets, invalidation, deletion handling, and retrieval provenance. Otherwise old state silently becomes instruction.
- Implementable now: separate raw events from promoted memory, use typed memory schemas, add writeback firewalls, log GraphRAG traversal paths, and test deletion, absence, stale premise, conflict, and dependency reasoning.
- Implementability score: 0.77

### 4. Skills crossed from convenience into software supply chain
- Category: [AgenticAI](../AgenticAI/2026-05-15/reasoning.md#skills-are-becoming-a-semantic-supply-chain)
- Durable topic: [Skills as Control](../AgenticAI/skills-as-control/skills-as-control.md)
- Core sources: https://github.com/anthropics/skills, https://arxiv.org/abs/2605.13716, https://github.com/Hik289/SkillOps, https://arxiv.org/abs/2605.13044
- Why it matters: skills compress procedures into reusable authority. That makes them useful and dangerous. Stale or underspecified skills can leak secrets, delete data, or bypass policy without any explicit attack.
- Implementable now: require skill manifests with permissions and side effects, run semantic fuzzing, maintain dependency/deprecation graphs, pin privileged skills, and log skill versions in traces.
- Implementability score: 0.75

### 5. GUI and computer-use agents need path-level supervision
- Category: [AgenticAI](../AgenticAI/2026-05-15/reasoning.md#computer-use-agents-need-gui-tool-path-supervision)
- Durable topic: [GUI-Tool Path Orchestration](../AgenticAI/gui-tool-path-orchestration/gui-tool-path-orchestration.md)
- Core sources: https://arxiv.org/abs/2605.12481v1, https://x-plug.github.io/ToolCUA/, https://github.com/X-PLUG/ToolCUA, https://github.com/X-PLUG/OSWorld-MCP, https://arxiv.org/abs/2605.10787v1, https://github.com/trycua/cua
- Why it matters: for browser and desktop agents, the path through screenshots, UI elements, tools, files, confirmations, and recovery steps determines cost, risk, and auditability. The final state is not enough.
- Implementable now: record a unified GUI/tool trace, compare GUI-only/tool-only/hybrid routes, require verification after state-changing UI actions, and prefer deterministic tools when they reduce risk.
- Implementability score: 0.64

### 6. Environment and trajectory substrates are the next training layer
- Category: [AgenticAI](../AgenticAI/2026-05-15/reasoning.md#environment-and-trajectory-substrates-are-the-next-training-layer)
- Durable topic: [Agent Harness Architecture](../AgenticAI/agent-harness-architecture/agent-harness-architecture.md)
- Core sources: https://arxiv.org/abs/2605.15040v1, https://huggingface.co/datasets/microsoft/Orchard
- Why it matters: open agent training needs reusable environment services, sandbox lifecycle, trajectory schemas, verification labels, and replay loops. Prompt iteration is not enough.
- Implementable now: define a minimal internal environment API, store messages/tool calls/state/screenshot/terminal/verifier outputs, label productive unresolved segments, and treat the Orchard dataset as a watch item until its re-upload warning disappears.
- Implementability score: 0.62

### 7. Coding agents became managed endpoints and live sessions
- Category: [Strategy](../Strategy/2026-05-15/sovereignty.md#coding-agents-are-now-managed-endpoints-and-live-sessions)
- Durable topic: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md)
- Core sources: https://openai.com/index/running-codex-safely, https://github.com/openai/codex, https://openai.com/index/building-codex-windows-sandbox, https://openai.com/index/work-with-codex-from-anywhere, https://github.blog/changelog/2026-05-14-github-copilot-app-is-now-available-in-technical-preview, https://github.blog/changelog/2026-05-13-start-copilot-cloud-agent-tasks-via-the-rest-api, https://github.blog/changelog/2026-05-14-copilot-cloud-agent-supports-auto-model-selection
- Why it matters: a coding agent is now a principal that can span local sandboxes, remote SSH, mobile control, REST APIs, hooks, access tokens, PR state, model routing, and isolated cloud sessions.
- Implementable now: bind each session to repo, branch, host, writable roots, network mode, model, token class, and approval state; enforce sandbox policy; log every prompt, approval, command, network decision, routing decision, and PR event.
- Implementability score: 0.78

### 8. Prompt injection became parameter and dataflow security
- Category: [Strategy](../Strategy/2026-05-15/sovereignty.md#prompt-injection-is-now-a-parameter-and-dataflow-security-problem)
- Durable topics: [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md), [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md)
- Core sources: https://www.microsoft.com/en-us/security/blog/2026/05/07/prompts-become-shells-rce-vulnerabilities-ai-agent-frameworks/, https://arxiv.org/abs/2605.05287, https://arxiv.org/abs/2605.07135, https://docs.github.com/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/configure-secrets-and-variables, https://github.blog/changelog/2026-05-08-more-flexible-secrets-and-variables-for-copilot-cloud-agent
- Why it matters: if the model can influence a parameter, file path, filter expression, CI variable, workflow output, or secret-bearing config, that value is attacker-controlled until proven otherwise.
- Implementable now: validate parameters, remove internal helper functions from tool surfaces, taint untrusted retrieval and repo inputs, and block dangerous sinks unless policy authorizes the exact action.
- Implementability score: 0.74

### 9. MCP and browser authorization need scoped consent plus live guards
- Category: [Strategy](../Strategy/2026-05-15/sovereignty.md#mcp-and-browser-authorization-need-scoped-consent-and-live-indirect-injection-tests)
- Durable topic: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md)
- Core sources: https://arxiv.org/abs/2605.11360v1, https://arxiv.org/abs/2605.11868v1, https://arxiv.org/abs/2605.15030v1, https://github.com/caothientri2001vn/WARD-WebAgent, https://huggingface.co/tricao1105/WARD-0.8b, https://huggingface.co/tricao1105/WARD-2b
- Why it matters: broad “allow this tool” consent and URL allowlists are too coarse for agents acting on live web content. Consent needs argument-level scope; web agents need continuous indirect-injection tests and parallel guards.
- Implementable now: use option-level MCP grants, run IPI-proxy-style red-team tests, and run WARD-style sidecar checks over task, HTML, screenshot, action, and context.
- Implementability score: 0.74

### 10. Always-on provenance gates and host isolation are strategic but heavier
- Category: [Strategy](../Strategy/2026-05-15/sovereignty.md#always-on-agents-need-provenance-gates-action-digests-and-os-containment)
- Durable topics: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md), [Agent Sandboxing](../Strategy/agent-sandboxing/agent-sandboxing.md)
- Core sources: https://arxiv.org/abs/2605.13471, https://github.com/maloyan/sleeper-channels, https://arxiv.org/abs/2605.11053, https://openai.com/index/building-codex-windows-sandbox
- Why it matters: persistent agents turn low-trust reads into delayed writes through memory, skills, scheduling, shell, and files. Provenance must travel with state into future actions.
- Implementable now: attach provenance IDs, compute action digests before side effects, gate low-trust provenance reaching shell/files/network/credentials/skill creation, and isolate risky workers at the OS layer.
- Implementability score: 0.58

## Signals

- **Highest single implementability:** TSCG-style tool-schema compilation at 0.86 in the daily notes. It is a concrete engineering move: compile schemas, measure token savings, and test tool-call accuracy.
- **Highest weekly category scores:** runtime compilation and trajectory-aware evaluation at 0.80. Both can be started with ordinary engineering effort and improve every downstream agent workflow.
- **Lowest weekly score:** least-privilege skills plus TEE-backed host isolation at 0.55. Skill permission metadata is doable now, but high-assurance host isolation and TEEs require deeper platform work.
- **Most important low-score watch item:** Orchard at 0.62. The environment/trajectory substrate is strategically large, but full-scale agent SFT/RL from environment rollouts is operationally heavier than tracing, eval, or schema compilation.
- **Noise filter:** de-emphasize star-velocity repos, generic memory wrappers, and product-wrapper launches unless they expose a maintained state model, tool surface, policy gate, source evidence, cost trace, or replayable trajectory.

## Actionable Insights

1. **Build a runtime manifest for every agent run.** Include tool schema version, exposed tools, model, token budget, workflow profile, scheduler decisions, memory state, skill versions, and policy verdicts.
2. **Prototype async tool semantics.** Start with slow read-only tools, symbolic futures, `await_future`, conservative scheduling, and latency/accuracy traces.
3. **Turn eval into trajectory review.** Capture traces and add prefix monitors, chaos fixtures, full-cycle coding eval, and lucky-pass detection.
4. **Make memory writeback explicit.** Store raw events, promote typed durable records through gates, and test deletion, absence, stale premise, and graph traversal provenance.
5. **Treat skills like dependencies.** Add manifests, semantic fuzzing, permission metadata, dependency graphs, version pins, and deprecation workflows.
6. **Make coding-agent sessions principals.** Scope by repo, branch, host, network, token, model, and approval state; log hooks, commands, model routing, and PR lifecycle.
7. **Move prompt-injection defense to dataflow.** Validate parameters, canonicalize paths, taint untrusted retrieval/repo/web inputs, and guard dangerous sinks.
8. **Require path traces for computer-use agents.** Unify GUI actions, tool calls, screenshots, confirmations, and verification into a single audit trail.
