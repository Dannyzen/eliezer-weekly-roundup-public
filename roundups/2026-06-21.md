# Daily AI Agent Research Roundup - 2026-06-21

## Thesis

The agent stack is shifting from static configuration to tested authority surfaces. The strongest signals today are not bigger models. They are probe-tuned repository guidance, issue-state machines, governed capability discovery, and least-privilege tool routing.

## Top findings

### 1. Repository guidance should be probe-tuned, not written once

Probe-and-Refine shows that `AGENTS.md`-style repository guidance becomes useful when it is tested against synthetic bug-fix probes and refined from failures. On SWE-bench Verified, probe-and-refine guidance reports a 33.0% mean resolve rate versus 28.3% for a static knowledge base and 25.5% unguided. The gain comes from more evaluable patches, not magically better patch precision.

What to do now: maintain repo guidance as a tested artifact. Generate probes for file localization, test selection, and known wrong paths. Patch the guidance when probes fail.

Category: AgenticAI

Implementability score: 0.78

Source: https://arxiv.org/abs/2606.20512v1

### 2. Issue-to-PR agents need explicit safety state machines

Phoenix resolves GitHub issues through six specialized agents coordinated by a label-based webhook state machine. The useful pattern is not the agent names. It is the production path: baseline test run, post-patch comparison, layered safety controls, and explicit handling of WAF filtering, token expiry, permission boundaries, and flaky CI.

What to do now: route autonomous issue work through labels, issue fields, baseline CI, role separation, and branch protection before allowing PR creation.

Category: AgenticAI and Strategy

Implementability score: 0.72

Source: https://arxiv.org/abs/2606.20243v1

### 3. Agentic Resource Discovery turns tool discovery into governance

GitHub Agent Finder and the ARD specification are making capability discovery dynamic. Agents can search catalogs for MCP servers, skills, tools, agents, APIs, and workflows on demand. That saves context and setup, but it also creates a new authority surface: what the agent is allowed to discover.

What to do now: build or use a private registry for approved capabilities. Log discovery queries and selected resources. Keep relevance score separate from trust score. Never auto-install a discovered capability without policy approval.

Category: Strategy

Implementability score: 0.84

Sources:
- https://github.blog/changelog/2026-06-17-agent-finder-for-github-copilot-now-available/
- https://commandline.microsoft.com/agentic-resource-discovery-specification-ard/
- https://docs.github.com/en/copilot/concepts/mcp-management#agent-finder
- https://github.com/huggingface/hf-discover

### 4. Least-privilege tool choice needs its own tests

ToolPrivBench shows that agents often choose or escalate to higher-privilege tools even when lower-privilege alternatives are sufficient. The important finding is that general safety alignment does not reliably transfer to least-privilege tool selection, and prompt controls degrade under transient tool failures.

What to do now: split tool tiers, require escalation justification, log fallback and retry paths, and test routers against paired lower/higher privilege alternatives.

Category: Strategy

Implementability score: 0.77

Sources:
- https://arxiv.org/abs/2606.20023v1
- https://github.com/AISafetyHub/agent-tool-selection-bias

## Practical implementation moves

1. Turn one repo's `AGENTS.md` into a tested guidance artifact with a small bug-fix probe suite.
2. Add baseline/post-patch CI comparison before any agent-created PR.
3. Treat GitHub labels and issue fields as an agent state machine, not just project metadata.
4. Create a small approved-capability registry for MCP servers, skills, and tools.
5. Add privilege tiers to tool metadata and require explicit escalation reasons.
6. Record discovery, selection, privilege escalation, and PR creation as trace events.

## Watchlist

DeerFlow is worth manual review as an implementation candidate for a long-horizon agent harness with subagents, memory, sandboxes, skills, and message gateways. It was not promoted to a top finding because today's evidence is repo metadata and documentation rather than a fresh benchmark.

Runtime probabilistic verification is also worth tracking. `Efficient and Sound Probabilistic Verification for AI Agents` extends Datalog-style runtime monitoring to probabilistic predicates and distributionally robust upper bounds. It is important, but less directly implementable this week than the four selected findings.

Watchlist sources:
