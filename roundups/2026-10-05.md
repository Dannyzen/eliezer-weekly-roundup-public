# Daily Agent Research Roundup: 2026-10-05

## Thesis

Agent reliability improves when evidence is collected after a proposal is fixed and at the boundary where the effect occurs. Fresh audits beat visible tests, browser action receipts beat click intent, restored constraints beat old context, and deployment-shaped detector evaluation beats generic benchmark rank.

## Top findings

### Fresh audits after code commitment

GTDD generates new tests after a coding candidate is fixed, reduces failures into regression fixtures, and keeps final acceptance independent. This is implementable as a harness policy without changing the coding model.

Source: [paper v1](https://arxiv.org/abs/2610.02952v1)

Implementability score: 0.76

### Browser steps need round-trip evidence

WebFovea raised a live hidden-set score from 31.0 to 57.0 with the same model by hardening parsing, action effects, observation reporting, and returned context. Browser automation should label and verify each stage.

Sources: [paper v1](https://arxiv.org/abs/2610.03036v1), [browser-use](https://github.com/browser-use/browser-use)

Implementability score: 0.86

### Long-horizon constraints need execution-time restoration

GHOST reports an 11.5% benign safety-constraint violation rate on GPT-5.5. STAR-Guard combines historical constraint restoration with deterministic pre-execution audit.

Source: [paper v1](https://arxiv.org/abs/2610.02664v1)

Implementability score: 0.81

### Detector evidence must match deployed tool outputs

Prompt-injection detector rankings transfer poorly across BIPIA, AgentDojo, and tau-bench. The public benchmark repo supports replay-based evaluation against agent-shaped outputs.

Sources: [paper v1](https://arxiv.org/abs/2610.03448v1), [benchmark repository](https://github.com/lzwhehe/benign-instruction-bench)

Implementability score: 0.91

## What to implement now

1. Add post-commit generated audits and regression-fixture capture to one coding-agent workflow.
2. Add post-action assertions and stage-specific error labels to one browser-agent journey.
3. Store safety constraints in a provenance-bearing register and check them before effect release.
4. Replay real tool outputs through prompt-injection detectors at a fixed low false-positive rate.
