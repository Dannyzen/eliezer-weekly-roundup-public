# Daily Roundup, 2026-07-07

Today's scan found four strong items. The shared thesis is untrusted boundary engineering: serious agents need to know which observations can be seen by the planner, which evidence can authorize action, and which tool or memory outputs must stay quarantined.

## Top findings

### 1. Untrusted web content should be masked before the planner sees it

Untrusted Content Masking replaces untrusted DOM regions with labeled placeholders before a web agent observes the page. When a task needs hidden content, the agent asks a quarantined model a narrow question and receives a typed answer. The verified repo includes 10 self-hosted websites, WebArena GitLab support, WASP attack tests, and automatic boundary detection.

### 2. Tool-use failure needs phase labels, not final accuracy

ToolFailBench separates failures where a model misses a required tool, calls the wrong tool, builds bad arguments, ignores returned values, or overuses irrelevant tools. The practical lesson is that tool QA needs phase labels. Final task accuracy is too coarse to guide harness fixes.

### 3. Agent data injection attacks the evidence channel

Agent Data Injection shows that malicious tool or page data can masquerade as trusted metadata or evidence. The attack does not need explicit jailbreak instructions. A bad value in the right field can steer an agent toward an unauthorized effect unless the gateway preserves data origin and trust class.

### 4. Personal-agent sovereignty needs explicit consent and platform-mediation tests

SovereignPA-Bench evaluates user-owned personal agents under evolving intent, platform mediation, and consent constraints. It is useful because it makes sovereignty testable: privacy, consent, evidence, user burden, resistance to manipulative incentives, and current user interest should be scored, not assumed.

## What is implementable now

- Mask untrusted DOM regions before web-agent planning and expose narrow typed quarantine reads.
- Add tool-use phase labels to traces: missed call, wrong tool, bad arguments, bad result use, and over-tooling.
- Split tool outputs into trusted metadata, user content, external content, and derived summaries.
- Add data-injection fixtures that mutate values, identifiers, deadlines, URLs, recipients, and account references.
- Add consent scope, revocation, platform-influence, and burden fields to personal-agent task manifests.

## Working conclusion

The daily thesis is untrusted boundary engineering. The agent stack should stop flattening page text, tool outputs, memory, and trusted state into one prompt. Serious systems need typed trust boundaries before planning, evidence lineage before action, and regression fixtures that prove untrusted content cannot become authority by accident.
