# Daily Roundup: 2026-06-26

## Bottom line

The strongest daily signal is that agent control surfaces are becoming explicit engineering objects. Coding-agent configs need deterministic provenance and permissioning. Agent policies can be compiled into Cedar and enforced outside the model. MCP catalogs need set-level security analysis. Agentic RAG red-teaming needs novelty checks across retrieval, modality, and orchestration surfaces.

## Top findings

### 1. Coding-agent configs need a deterministic control plane

Source: [A Deterministic Control Plane for LLM Coding Agents](https://arxiv.org/abs/2606.26924v1)

The paper's repo-scale study makes agent rules files look like an unmanaged software supply chain. The actionable pattern is to treat agent definitions as versioned, content-addressed, permission-bearing artifacts with lockfiles, drift checks, traceability, and CI enforcement.

Implementability score: 0.64

### 2. Agent instructions are becoming policy-as-code

Source: [Autoformalization of Agent Instructions into Policy-as-Code](https://arxiv.org/abs/2606.26649v1)
Artifact: [sondera-ai/sondera-harness-python](https://github.com/sondera-ai/sondera-harness-python)

The useful product shape is LLM-assisted policy compilation plus deterministic enforcement, not prompt-only safety. Use the model to propose Cedar policies, then force syntax, schema, contradiction, coverage, and runtime checks outside the agent process.

Implementability score: 0.76

### 3. ShareLock shows MCP poisoning is a multi-tool problem

Source: [ShareLock: A Stealthy Multi-Tool Threshold Poisoning Attack Against MCP](https://arxiv.org/abs/2606.27027v1)

The attack distributes hidden intent across multiple benign-looking tool descriptions. The practical lesson is that MCP gateways must inspect enabled-tool sets, update epochs, and cross-tool reconstruction risk, not only individual tool descriptions.

Implementability score: 0.46

### 4. MIRROR makes agentic RAG red-teaming novelty-aware

Source: [MIRROR](https://arxiv.org/abs/2606.26793v1)
Artifact: [FujitsuResearch/mirror](https://github.com/FujitsuResearch/mirror)

MIRROR pairs memory-guided MCTS with a deterministic novelty gate so red-team search does not merely replay known attacks. This is the right pattern for RAG agents because the attack surface spans text poisoning, image injection, direct queries, and orchestrator-level tool manipulation.

Implementability score: 0.72

## What is implementable now

- Add config hashes, lockfiles, permission declarations, and CI drift checks for repo-local agent rules.
- Put Cedar or OPA in front of one privileged agent tool and return deterministic denial reasons to the agent.
- Add MCP catalog-level diffing and enabled-tool-set fuzzing to gateway tests.
- Use MIRROR-style novelty gates before trusting internal RAG red-team results.

## Highest and lowest scores today

Highest: 0.76, policy-as-code for agent instructions.
Lowest: 0.46, ShareLock-style multi-tool MCP poisoning defenses.
