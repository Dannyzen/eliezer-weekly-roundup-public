# Friday Synthesis - 2026-08-28

## Thesis

Reliable agents preserve evidence and authority across every transformation, then admit adaptation only through differential tests and runtime-owned gates.

This week, research on context privilege, constraint weakening, tool authorization, safety across autonomous loops, memory compaction, agent evaluation, and non-idempotent delegation converged on the same design rule: summaries, retries, skills, routers, judges, and handoffs may change representation, but they must not silently change provenance, binding force, identity, or permission.

## Week-level findings

### 1. Provenance and binding force are runtime state

When Context Gets Root showed that coding-agent harnesses can promote tool-origin content into user-level or system-effective instructions. When "Must" Becomes "Maybe" showed the same class of failure across handoffs: mandatory constraints can become suggestions when state is summarized, reformatted, or delegated.

What changed: provenance is not annotation for later audit. It is active control state. Every context item needs an immutable origin, privilege class, transform chain, and loader identity. Mandatory constraints also need typed semantics that survive every handoff.

Implementable now:
- attach origin, privilege, transform lineage, and loader identity to each context item;
- require privilege-monotonic transforms, where a summary cannot raise authority;
- represent blockers and mandatory constraints as typed records, not prose alone;
- test plans, skills, memory summaries, subagent payloads, and instruction files as separate escalation and weakening fixtures.

Implementability score: 0.86

Sources:
- https://arxiv.org/abs/2608.27299v1
- https://arxiv.org/abs/2608.24569v1

### 2. External effects need independent authorization and terminal closure

When Tool Outputs Become Commands separated action induction from runtime authorization: untrusted observations may help construct a candidate call, but cannot create authority for its effect. AID-Guard extended that rule across provider commit, ambiguous delivery, reconciliation, and recovery. Metis made the execution surface explicit through typed runtime events and terminal-result closure.

What changed: an approval should bind to one effect lineage, not one request or one model decision. Accepted, denied, failed, timed-out, cancelled, ambiguous, and reconciled states must remain distinguishable until the provider effect is terminal.

Implementable now:
- define user effect contracts with operation, target, scope, recipients, and static arguments;
- persist canonical request identity, authorization identity, provider operation, and effect lineage;
- revalidate immediately before provider commit and reconcile ambiguous outcomes before retry;
- normalize provider output into typed events and require one terminal result for every admitted call;
- minimize arguments at the effect boundary and retain the rewrite in protected audit evidence.

Implementability score: 0.82

### 3. Improvement claims need a measured null and evaluator checks

Phantom Gains showed why self-improvement claims need an unchanged control processed through the same noisy pipeline. Evaluating Skills, Not Just Agents moved the unit of analysis from the whole agent to the specific procedural intervention. ClawProBench argued that the declared model-plus-runtime bundle, not the model alone, is the evaluated object.

AgentJudgeBench added the missing judge check. Its 3,808 workflow-DAG instances found a 77 to 82 percent ceiling for all six judges on hard ungrounded queries. Structured rubrics improved alignment by up to 6.5 percentage points, while chain-of-thought and temperature changes had negligible effect.

What changed: a green score is not evidence of improvement until the control, evaluator, runtime bundle, and uncertainty are all visible.

Implementable now:
- run an unchanged control through the identical optimization pipeline;
- evaluate each skill with paired intervention and no-intervention trials on frozen holdouts;
- version model, prompt, controller, runtime, tools, policy, and checker as one configuration;
- prefer programmatic references and structured rubrics over ungrounded judge preference;
- report uncertainty, disagreement, and evaluator failure separately from task failure.

Implementability score: 0.86

### 4. Memory and skills are typed compilation, not generic summarization

The Compaction Cliff measured the cost of treating every memory item alike. Across 20 production configurations, Claude Code's `/compact` prompt on Sonnet 4.6 preserved 53 percent of safety rules after one round and 10 percent after five. Its Knowledge Triage prototype routes constraints, procedures, and softer history through different deterministic retention operators.

WikiSkill supplied the promotion pipeline: immutable traces, a persistent pattern wiki, and validation-gated active skills. Other work this week reinforced the same shape by inducing skills at subtask boundaries, retrieving them from typed working state, and requiring applicability, risk, avoidance, recovery, and completion checks.

What changed: summaries are lossy compilers. Safety constraints need exact retention. Historical traces may remain append-only. Consolidated patterns may guide proposals. Only validated procedural artifacts should enter the active skill surface.

Implementable now:
- classify memory entries by type before compaction;
- pin exact constraints and route procedures, evidence, and episodic history through separate retention policies;
- store raw traces append-only and preserve rejected skill proposals plus measured impact;
- give each skill explicit applicability, risk, avoidance, recovery, prerequisites, produced state, and completion checks;
- promote revisions only after held-out regression and rollback checks.

Implementability score: 0.84

### 5. Orchestration should adapt from trace evidence without losing delegation identity

Observability and Fault Injection for LLM-Based Multi-Agent Systems made failure injection and trace alignment part of the harness. Progress-aware routing proposed changing models from measured trajectory progress rather than only the opening query. Agent Mesh added production failure evidence: retries, timeouts, and error-rate breakers are insufficient for non-idempotent delegation when invocation identity, mutation evidence, and terminal proof are inadequate.

What changed: orchestration needs a typed workflow ledger. Adaptation should consume measured progress, aligned faults, cost, and terminal evidence. A retry is a new delegation decision unless the runtime can prove it is the same invocation and safe to resume.

Implementable now:
- emit OpenTelemetry spans for workflow phases, agents, handoffs, models, tools, and effect states;
- inject faults at trace-aligned boundaries and compare baseline with perturbed runs;
- record marginal progress, stalls, regressions, elapsed time, and cumulative cost after each step;
- bind delegation identity to deterministic, attributable evidence before retry, resume, or circuit-break decisions;
- admit browser and tool trajectories only after isolated execution and terminal-state verification.

Implementability score: 0.76

## The stack after this week

1. Preserve: keep raw evidence, origin, binding force, and effect identity intact.
2. Type: distinguish constraints, procedures, observations, proposals, authorizations, and terminal results.
3. Challenge: compare against measured nulls, frozen holdouts, programmatic references, and fault-injected traces.
4. Promote: move memory, skills, routes, and policy changes into active use only after validation and rollback proof.
5. Authorize: release one bounded effect through a runtime-owned contract.
6. Close: reconcile terminal provider state and preserve the receipt across retries, restarts, and handoffs.

The recurring failure is silent promotion. A tool output becomes an instruction, a summary weakens a constraint, repeated history launders authority, a noisy evaluator becomes proof, or a retry becomes a duplicate effect. The runtime must make each promotion explicit and reversible.

## Implementability range

The week's highest assigned score was 0.92 for mainstream runtime release behavior around approval state, tool identity, recovery, and trace continuity. The lowest was 0.38 for adaptive prompt-injection learning loops that remain model-mediated and operationally immature.

## Strongest objection

This design adds schemas, durable state, trace volume, latency, and more failure modes in the control plane itself. Several papers are new preprints, and some artifacts are absent or only partially verified. That is survivable because the first implementation does not require a universal runtime. Start with one consequential workflow, one compaction boundary, and one provider effect. Keep only controls that catch real failures or improve recovery without unacceptable false holds.
