# Friday Synthesis: 2026-10-16

## Thesis

The strongest finding this week is that agent reliability improves when every consequential transition becomes an explicit runtime object. Skill selection, model routing, mutation, approval, containment, evidence, and completion should each have a typed release point that the model can propose but cannot silently redefine.

This creates one practical stack:

1. preselect the capability;
2. allow reversible progress;
3. hold the first mutation;
4. bind approval to a canonical effect;
5. execute inside fail-closed containment;
6. preserve source-typed evidence;
7. verify the state at the layer that produced it.

## Weekly findings

### 1. Capability selection is a control-plane decision

Lost in Implicit Routing shows that implicit skill discovery collapses as irrelevant metadata grows. With 1,000 irrelevant skills, loaded-skill recall falls from 73.6% to 27.4%, while explicit preselection retains 73.9% recall.

The implementation pattern is a small preselected capability set with identity, version, policy attachment, and first-read receipt. A large skill catalog should be searched before task execution, not dumped into the same context that must perform the work.

Core sources: [paper v1](https://arxiv.org/abs/2610.18522v1), [official repository](https://github.com/jinlinll/lost-in-implicit-routing)

Implementability score: 0.88

### 2. Routing should stop at the state transition

SpecAgent lets a weaker model perform grounded reads and draft a trajectory, then asks a stronger model to approve the longest valid prefix before the first mutation. RATED and Cadence add execution feedback: tool reliability and workflow health should alter the route during the run.

The implementation pattern is effect-aware routing. Cheap models may inspect, retrieve, and draft. Mutations wait for stronger review or deterministic policy. This preserves useful low-cost work without granting whole-request authority.

Core sources: [SpecAgent paper v1](https://arxiv.org/abs/2610.21463v1), [SpecAgent repository](https://github.com/LARK-AI-Lab/SpecAgent), [RATED paper v1](https://arxiv.org/abs/2610.13889v1), [Cadence paper v1](https://arxiv.org/abs/2610.12269v1)

Implementability score: 0.82

### 3. Evaluation must inspect the layer that produced the claim

TestSuiteBench shows that 88% of generated tests can pass on a reference implementation while mutation scores remain below 60%. FEB-30 shows that memory state and downstream QA diverge by 16 percentage points on average, with memory-operation classification correct only 20% of the time in the evaluated system.

The implementation pattern is layered oracles: requirement-targeted mutants for tests, direct state assertions for memory, independently derived references for tool arguments, and recoverability checks for reports and handoffs.

Core sources: [TestSuiteBench paper v1](https://arxiv.org/abs/2610.13065v1), [TestSuiteBench repository](https://github.com/eth-sri/testsuitebench), [FEB-30 paper v1](https://arxiv.org/abs/2610.22209v1), [DeRef paper v1](https://arxiv.org/abs/2610.18497v1), [CTXGAP paper v1](https://arxiv.org/abs/2610.20003v1)

Implementability score: 0.79

### 4. Authority needs exact activation, expiry, and effect binding

Agent Step-Up demonstrates that user approval is meaningful only when the compromised agent cannot produce it and when it names the exact stored effect. GitHub's MCP startup control and CreepScope extend that logic to capability lifetime. GitHub's local sandboxing and MXC make fail-closed file, network, and credential boundaries usable now.

The implementation pattern is a capability lease plus a canonical effect descriptor: explicit activation, narrow scope, last-justified-step expiry, trusted rendering, single-use execution, rate limits, and receipts.

Core sources: [Agent Step-Up paper v1](https://arxiv.org/abs/2610.21063v1), [repository](https://github.com/Sports-Vision-Inc/agent-step-up), [GitHub MCP startup release](https://github.blog/changelog/2026-10-10-new-controls-and-chat-improvements-in-copilot-for-jetbrains/), [CreepScope paper v1](https://arxiv.org/abs/2610.15988v1), [GitHub local sandboxing release](https://github.blog/changelog/2026-10-09-github-copilot-weekly-releases-october-5/), [MXC repository](https://github.com/microsoft/mxc)

Implementability score: 0.90

### 5. Evidence must retain provenance across sessions and runtime layers

SkillRelay shows how files, caches, and reports can carry malicious influence into later skill executions. ExecWeave shows the same attribution problem inside a live run: semantic events and OS-observed effects should remain separate until a justified bridge connects them. GitHub's telemetry controls show a practical privacy boundary by separating identity from content capture.

The implementation pattern is a typed evidence graph with producer identity, session, checksum, transformation history, source class, support IDs, confidence, and abstention. Reused artifacts regain their provenance before consumption, and cross-layer correlations remain explicitly inferred unless causal evidence exists.

Core sources: [SkillRelay paper v1](https://arxiv.org/abs/2610.13227v1), [SkillRelay repository](https://github.com/Dianshu-Liao/SkillRelay), [ExecWeave paper v1](https://arxiv.org/abs/2610.21146v1), [ExecWeave repository](https://github.com/Irish-kw/ExecWeave), [GitHub telemetry release](https://github.blog/changelog/2026-10-12-client-telemetry-user-attribution-and-configurable-capture/)

Implementability score: 0.68

## What is implementable now

1. Preselect and receipt a small capability set before task execution.
2. Classify tools by reversibility and hold the first mutation.
3. Add direct state oracles for tests, memory, and handoff recoverability.
4. Bind approvals to canonical stored calls with expiry and single-use execution.
5. Fail closed when sandbox, network policy, or capability activation is unavailable.
6. Preserve artifact and runtime evidence classes before deriving correlations.

Highest score: 0.90 for explicit capability lifetime, canonical effect binding, and fail-closed containment.

Lowest score: 0.68 for a unified cross-session and cross-layer evidence graph. The core data model is implementable, while justified attribution, privacy controls, and stable identities require meaningful architecture.

## What remains immature

- SpecAgent's gains are benchmark-specific and need validation against real provider latency, cache behavior, and effect policies.
- FEB-30 applies its intrinsic evaluation to one representative memory system and its named repository did not resolve during the daily scan.
- Agent Step-Up cannot prevent effects already permitted by policy, and approval flooding remains material.
- AgenticRV's enforcement evidence is controlled and adapter-bounded.
- Several selected public repositories have populated branches but no license detected in GitHub metadata.
- Cross-layer causality remains an attribution problem, not a benefit supplied automatically by collecting more logs.

## Strategic question

If a human approves only the narrative while capability activation, arguments, and realized effects live elsewhere, what exactly was authorized?
