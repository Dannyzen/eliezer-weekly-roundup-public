# Daily AI and Agent Research Scan: 2026-06-07

Today’s strongest pattern is protocol evidence. Agent systems are no longer improved by simply adding more memory, more tools, or more agents. The useful systems preserve the protocol that shaped the run, then repair or govern the right layer.

## Top findings

### 1. Failed trajectories should become harness repairs
- Category: [AgenticAI](../AgenticAI/2026-06-07/reasoning.md#failed-trajectories-should-become-harness-repairs-not-prompt-patches)
- Durable topics: [Agent Harness Architecture](../AgenticAI/agent-harness-architecture/agent-harness-architecture.md), [Trajectory-Aware Evaluation](../AgenticAI/trajectory-aware-evaluation/trajectory-aware-evaluation.md)
- Core source: https://arxiv.org/abs/2606.06324v1
- Why it matters: the harness owns tools, context, lifecycle, observability, verification, environment, and governance. A failed final answer is not enough evidence to decide what broke.
- Implementable now: capture trace IR, replay failed trajectories, label the broken harness layer, then promote repairs into regression fixtures.
- Implementability score: 0.82

### 2. Multi-agent workflows need normalized baselines before more agents
- Category: [AgenticAI](../AgenticAI/2026-06-07/reasoning.md#multi-agent-workflows-need-normalized-baselines-before-more-agents)
- Durable topic: [Multi-Agent Orchestration](../AgenticAI/multi-agent-orchestration/multi-agent-orchestration.md)
- Core sources: https://arxiv.org/abs/2606.05670v1, https://github.com/LINs-lab/MASArena/tree/BenchAgent
- Why it matters: multi-agent systems often look better because they get different tool access, loaders, contracts, retries, or accounting. Protocol-aligned baselines make coordination cost visible.
- Implementable now: compare single-agent, fixed-MAS, and evolving-MAS workflows under identical tool access, answer contracts, logging, and usage budgets.
- Implementability score: 0.75

### 3. Memory search needs policy and bitemporal conflict handling
- Category: [AgenticAI](../AgenticAI/2026-06-07/reasoning.md#memory-search-needs-policy-and-bitemporal-conflict-handling)
- Durable topic: [Memory Systems](../AgenticAI/memory-systems/memory-systems.md)
- Core sources: https://arxiv.org/abs/2606.06054v1, https://arxiv.org/abs/2606.06240v1, https://github.com/ZenAlexa/toki-bitemporal-memory
- Why it matters: memory failure is no longer only bad recall. A semantically related memory can be stale, sensitive, cross-domain, consent-scoped, contradictory, or dangerous when paired with a tool action.
- Implementable now: add retrieval policy gates and bitemporal fact writes with evidence, valid time, transaction time, supersession, and explicit conflict operators.
- Implementability score: 0.69

### 4. Agent toolchains are becoming governed client and CI surfaces
- Category: [Strategy](../Strategy/2026-06-07/sovereignty.md#agent-toolchains-are-becoming-governed-client-and-ci-surfaces)
- Durable topic: [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md)
- Core sources: https://github.blog/changelog/2026-06-05-enterprise-managed-plugins-in-vs-code-in-public-preview/, https://github.com/PrefectHQ/fastmcp/releases/tag/v3.4.1, https://github.com/PrefectHQ/fastmcp/releases/tag/v3.4.2, https://github.com/diomonogatari/mcp-guard/releases/tag/v1.0.0
- Why it matters: the agent tool surface is now a supply chain: client defaults, enterprise settings, hooks, MCP configs, MCP server dependencies, auth behavior, tool descriptions, and CI gates.
- Implementable now: centralize approved plugins and MCP configs, pin MCP dependencies, regression-test OAuth/JWT behavior, and statically scan tool descriptions before release.
- Implementability score: 0.87

## Signals

- Highest implementability today: managed toolchain governance at 0.87. GitHub enterprise settings, FastMCP dependency/auth fixes, and mcp-guard-style CI checks are all available now.
- Lowest implementability today: memory trust and bitemporal conflict handling at 0.69. The primitives are clear, but serious adoption needs policy, schema, and database discipline.
- Best immediate build target: a harness trace schema that labels failure by layer and can replay one failed run into a patched regression fixture.
- Noise filter: WebMCP Tool Surface Poisoning and EVA-Bench remain good sources, but they were already incorporated in the 2026-06-05 repo updates. IR3DE, hf CLI for agents, LiteLLM signed images, and Ollama 0.30 stay on the watchlist.
