# Daily Agent Research, 2026-10-29

## Thesis

Long-running agents need explicit state at two levels: a work tree that preserves unfinished reasoning and an execution protocol that constrains effects. Evaluation must also follow the work over time, because first-stage success hides inherited defects.

## Top findings

### 1. Compile subtask trees into model context

Spine keeps unfinished scopes detailed and collapses completed scopes into submitted results. On SWE-Milestone with GPT-5.6 Sol, it resolved 19 of 98 milestones versus 14 for native Codex while reducing total cost by 32.4%.

Implementability score: 0.78

Source: https://arxiv.org/abs/2610.37224v1

### 2. Evaluate the full feature arc

FeatureArc tested 10 coding agents on 73 evolving-feature tasks. Pooled success fell from 62.7% on the first stage to 28.5% on the final feature, and inherited defects appeared in 72.9% of failed later stages.

Implementability score: 0.83

Source: https://arxiv.org/abs/2610.37434v1

### 3. Enforce agent conversations as typed sessions

Concordat exposes only state-legal tools and rejects illegal effects before dispatch. Under confirmation-skipping pressure, standard agents made unauthorized changes while Concordat made none without a significant task-success loss.

Implementability score: 0.79

Sources: https://arxiv.org/abs/2610.37461v1 and https://github.com/miladsikaroudi/concordat

### 4. Compile agentic workflows into guarded CI

GitHub Agentic Workflows compiles Markdown into Actions YAML, defaults agent jobs to read-only sandboxed execution, and applies configured writes through separate safe-output jobs with scoped permissions.

Implementability score: 0.94

Sources: https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available/ and https://github.com/github/gh-aw

## What is implementable now

- represent long work as nested scopes with immutable completion results;
- run regression checks across successive feature stages;
- encode approval and effect order as runtime state transitions;
- place reasoning inside existing CI policy, sandbox, and write-release boundaries;
- measure cost, final-state correctness, and policy compliance separately.
