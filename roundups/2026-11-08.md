# Daily Agent Research Roundup: 2026-11-08

No new arXiv listing appeared on Sunday. These four unreported Friday carry-forwards converge on one operational rule: classify what failed and bind every consequential decision to the contract and source that govern it.

## Top findings

### 1. Failure monitors often predict the issue and model, not the run

A run-independent issue-difficulty score reached 0.92 AUROC on public SWE-bench Verified trajectories, versus about 0.62 for tested trajectory predictors. Retry, stop, and model-switch policies need repeated-run labels that separate hard issues, weak models, and stochastic bad runs.

Implementability score: 0.84

Analysis: [AgenticAI](../AgenticAI/2026-11-08/reasoning.md#1-separate-hard-issues-weak-models-and-bad-runs)

Source: [Hard Issue, Weak Model, or Bad Run?](https://arxiv.org/abs/2611.08285v1)

### 2. Migration tests should come from changed contracts

Across 73 tasks and 60 documented runtime changes, typical-input assertions released 41.0 percent of wrong repairs. One release-note-derived edge input cut that to 6.5 percent, though hard distractor programs still exposed a meaningful residual.

Implementability score: 0.87

Analysis: [AgenticAI](../AgenticAI/2026-11-08/reasoning.md#2-derive-migration-tests-from-changed-contracts)

Source: [Accepted but Wrong](https://arxiv.org/abs/2611.08269v1)

### 3. Prompt injection can preserve the task and alter its values

A 90-case benchmark shows that attacks on rules, action availability, observation meaning, and state can survive defenses tuned for instruction override. Tool-policy checks remained close to the undefended attack rate because the expected tool was used with attacker-shaped values.

Implementability score: 0.82

Analysis: [Strategy](../Strategy/2026-11-08/sovereignty.md#1-define-prompt-injection-by-source-authority)

Sources: [paper](https://arxiv.org/abs/2611.07640v1), [public benchmark repository](https://github.com/amazon-science/task-tampering-prompt-injection)

### 4. Signed handoffs protect transit, not extraction

Signed requirement manifests reduced unsafe commits from 69.4 percent to 9.0 percent in the primary 1,440-trajectory study. The remaining unsafe decisions came from requirements extracted incorrectly before signing, so extraction is the real trust boundary.

Implementability score: 0.76

Analysis: [Strategy](../Strategy/2026-11-08/sovereignty.md#2-sign-requirements-after-source-bound-extraction)

Source: [Signed but Not Safe](https://arxiv.org/abs/2611.07483v1)

## What to use now

1. Add issue-only and model-only baselines before trusting a trajectory failure monitor.
2. Generate migration edge tests from the exact changed release-note clause.
3. Bind consequential values to authorized sources, not merely allowed tools.
4. Sign canonical requirement manifests only after source-bound extraction checks.
