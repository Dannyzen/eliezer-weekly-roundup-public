# Daily Roundup - 2026-07-01

Thesis: the agentic stack is moving from generic tool access to governed work surfaces. Today's strongest finding is the control-plane version of that shift: connection protocols are useful, but agent products need execution-control objects before tool access becomes safe authority.

## Deep Dive Wednesday

### HCP makes execution control the missing layer under MCP-style systems

Category: Strategy
Deep dive: [Agent Execution Control Plane](../Strategy/agent-execution-control-plane/agent-execution-control-plane.md)
Source: https://arxiv.org/abs/2606.29073v1
Artifact repo: https://github.com/SymbolicLight-AGI/handle-capability-protocol

From Tool Connection to Execution Control won the week because it names the layer underneath the other good findings. ECHO needs source-indexed memory, CubeSandbox needs egress policy and audit, agents-cli needs lifecycle skills, and agent-community governance needs replayable decisions. HCP supplies the execution-control grammar that makes all of them safer: principal, grant, canonical resource, capability, handle, policy decision, approval, data-pipe check, task, and audit entry.

The paper reports a controlled 10-case benchmark where a naive MCP-like connection runtime permits all modeled attacks, a practice-informed mitigation baseline still permits 6 of 10, and HCP blocks all 10 while preserving audit evidence. Treat that as architectural evidence, not production proof. The repo is explicit that HCP is a reference prototype, not a production security platform.

Implementability score: 0.71

## Top findings

### 1. HCP makes MCP-style execution control explicit

Category: Strategy
Source: https://arxiv.org/abs/2606.29073v1
Repo: https://github.com/SymbolicLight-AGI/handle-capability-protocol
Security invariants: https://github.com/SymbolicLight-AGI/handle-capability-protocol/blob/main/docs/security-invariants.md

The useful move is separating tool reachability from authority. MCP-style connection tells an agent how to reach tools. HCP-style execution control decides who is acting, which grant authorizes the action, which canonical resource is touched, which data handle may be projected or piped, and which allow or deny evidence goes into the trace.

Implementability score: 0.71

### 2. ECHO makes selective memory traceable

Category: AgenticAI
Source: https://arxiv.org/abs/2606.31650v1

ECHO links bounded context with RL credit assignment. It compresses completed turns into source-indexed memory records, reconstructs bounded contexts by selecting records, and routes outcome credit back to the selected evidence. The abstract reports 43.4% held-out BrowseComp-Plus accuracy versus GRPO at 28.9% and SUPO at 36.1%.

Implementability score: 0.74

### 3. CubeSandbox makes sandbox policy part of the agent runtime

Category: AgenticAI
Source: https://github.com/TencentCloud/CubeSandbox
v0.4 changelog: https://github.com/TencentCloud/CubeSandbox/blob/master/docs/changelog/v0.4.0.md
Security proxy guide: https://github.com/TencentCloud/CubeSandbox/blob/master/docs/guide/security-proxy.md

CubeSandbox is an implementable sandbox substrate for code agents: KVM and RustVMM isolation, E2B SDK compatibility, snapshots, templates, and a v0.4 CubeEgress proxy for credential injection, domain filtering, and egress audit logs. The useful pattern is runtime-owned network and secret policy, not prompt-owned safety.

Implementability score: 0.86

### 4. agents-cli packages agent lifecycle expertise as skills plus commands

Category: AgenticAI
Source: https://github.com/google/agents-cli
Docs: https://google.github.io/agents-cli/guide/getting-started/
Release: https://github.com/google/agents-cli/releases/tag/v0.6.1

Google's agents-cli gives coding assistants installable skills and deterministic commands for ADK agent development: scaffold, eval, grade, analyze, optimize, deploy, publish, and observe. It is a concrete example of skills-as-control moving into vendor tooling.

Implementability score: 0.88

### 5. Agent interop protocols do not govern communities

Category: Strategy
Source: https://arxiv.org/abs/2606.31498v1

The governance-gaps paper argues that MCP, A2A, ACP, ANP, and ERC-8004 handle connection and task coordination, but not governed communities. Membership, deliberation, voting, dissent preservation, human escalation, and audit/replay need a layer above current protocols.

Implementability score: 0.48

## What is implementable now

- Put privileged tools behind an execution-control broker with principal, grant, resource, capability, approval, and audit fields.
- Add source IDs to memory records and log which records are selected into every bounded context.
- Compare full history, rolling summaries, selected turn memory, and no-memory variants on local tasks.
- Evaluate CubeSandbox on a disposable KVM host as an E2B-compatible worker backend with egress rules enabled.
- Test agents-cli on a throwaway ADK project and compare agent builds with and without lifecycle skills.
- Define an agent assembly manifest: members, roles, scopes, voting or approval rights, dissent logging, escalation, and replay bundle.
