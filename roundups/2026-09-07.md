# Daily Agent Research - 2026-09-07

## Thesis

Portability is a property of the whole execution contract. Memories depend on their readers and embedding spaces, skills depend on frozen versioned snapshots, RL policies depend on harness semantics, and security guarantees depend on every transition to finality.

## Top findings

### 1. Composable controls need a security-context contract

CONTINUITY makes every security-relevant transform carry an authenticated witness to the exact effect. Its deterministic suite contained all 128 modeled fault-domain classes with no harmful effect in 2,560 attack instances, while incomplete controls still failed badly.

Implementability score: 0.83

Sources: [paper](https://arxiv.org/abs/2609.05269v1), [artifact](https://github.com/zast-ai/continuity)

### 2. A model upgrade is a memory migration

Across 48 synthetic histories, fixed-schema memory transferred cleanly, compressed notes changed by as much as -13.28 percentage points depending on direction, and a mixed embedding index recovered less than half the gain of full re-embedding.

Implementability score: 0.77

Source: [paper](https://arxiv.org/abs/2609.05339v1)

### 3. Skill evolution needs a snapshot boundary

Skill-Evo4GUI executes against a frozen skill-library snapshot, derives structured evidence from the trace, and exposes accepted changes only in the next iteration. The public artifact includes prompts, schemas, and examples, but not the full OSWorld runtime.

Implementability score: 0.72

Sources: [paper](https://arxiv.org/abs/2609.04869v1), [artifact](https://github.com/LongtaoHu/Skill-Evo4GUI)

### 4. Multi-harness RL needs a held-out harness

Across 24,000 sealed evaluations, evaluation-harness choice moved mean solve rate 4.3x while cross-harness reward grouping did not produce a statistically clear held-out gain. Configuration adaptation is not portable capability.

Implementability score: 0.58

Source: [paper](https://arxiv.org/abs/2609.04518v1)

## Source-integrity rejection

FinalityBench was not promoted. The immutable v1 paper claims language-model results, while the current artifact README and `BLOCKERS.md` say no model was run. The programmatic benchmark may still be useful, but its headline source record is internally inconsistent.

Sources: [paper](https://arxiv.org/abs/2609.04706v1), [artifact](https://github.com/abhisheksharma2411/finalitybench)

## What to implement now

1. Add memory migration fixtures that bind writer, reader, embedding model, schema, and raw-source identity.
2. Freeze skill snapshots per run and admit mutations only into the next version with provenance.
3. Add one held-out minimal harness to every cross-harness training or evaluation claim.
4. Model one consequential action path as an assume-guarantee chain and inject context-loss faults between components.
