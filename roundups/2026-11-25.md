# Daily Agent Research Roundup: 2026-11-25

## Thesis

Durable agents need two separations: recovery must preserve unaffected work, and authorization must preserve the original source of authority. Model-written summaries and delegated approval replies are useful inputs, but they cannot inherit powers their authors never held.

## Top findings

### 1. Recover failed branches instead of replaying successful work

Agent-Kernel persists a task DAG and resets only a failed node and its descendants. Across 14,434 runs, the paper reports 100% recovery within a three-attempt budget versus 55% for whole-trajectory replay, plus up to 12.7 times speedup where parallelism is available.

Action now: persist node state and retry lineage, then compare selective invalidation against whole-run replay on deterministic fault fixtures.

Implementability score: 0.58

Source: [fork() for Agents](https://arxiv.org/abs/2611.31727v1)

### 2. Evaluate model, harness, and reasoning effort as separate factors

ShellBench crosses 12 models, five harnesses, three reasoning levels, and 100 realistic file-workspace tasks for 53,100 rollouts. Its leading models were separated by only 1.1 percentage points, while one near-leading model used about one-sixth of the estimated token cost per attempt.

Action now: pin every evaluation cell and report quality, safety, source use, tokens, latency, and cost separately.

Implementability score: 0.88

Sources: [ShellBench](https://arxiv.org/abs/2611.32946v1), [public task dataset](https://huggingface.co/datasets/OpenClaw/ShellBench)

### 3. Keep authorization inputs outside model-written compaction

A request-derived authorizer admitted an attacker-specified account in 91% of cases when it read a compactor's summary, versus none when it read the user's authenticated words. A gate that preserved user text across compaction blocked attacker actions in 40 attacked episodes.

Action now: let summaries drive reasoning while grants are derived only from immutable, source-authenticated user messages.

Implementability score: 0.72

Sources: [LLM Agent Authorization Across Context Compaction](https://arxiv.org/abs/2611.32194v1), [artifact snapshot](https://anonymous.4open.science/r/LLM-Agent-Authorization-Across-Context-Compaction-504E/)

### 4. Do not let approval replies administer persistent policy

A delegated permission answer can carry a policy update that deletes operator restrictions and changes later decisions. The safe boundary is explicit: a party may approve a bounded call, and may remove only the policy rules it owns.

Action now: separate one-shot decisions from policy changes, enforce owner-bound rule removal, and store the complete policy diff receipt.

Implementability score: 0.82

Sources: [When Answering Is Administering](https://arxiv.org/abs/2611.32195v1), [reproduction snapshot](https://anonymous.4open.science/r/-When-Answering-Is-Administering-Permission-Replies-That-Rewrite-Coding-Agent-Policy-E5B0/)

## What changed in the stack model

1. Retry state belongs to the durable runtime, not the model transcript.
2. Evaluation identity includes model, harness, reasoning level, task, grader, and cost cell.
3. Compacted context can guide reasoning without becoming authority.
4. Approval authority and policy-administration authority require separate capabilities.
