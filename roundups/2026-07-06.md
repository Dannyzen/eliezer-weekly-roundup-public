# Daily Roundup, 2026-07-06

Today's scan found four strong items. The shared thesis is process-bound authority: skills, coding chats, code review, and enterprise data access all need enforceable process evidence before the runtime grants more trust.

## Top findings

### 1. Skill use needs process rubrics, not final verifier wins

SkillCoach separates final task success from skill-use quality. It scores trajectories across skill selection, skill following, skill composition, and skill-grounded reflection, which exposes cases where an agent passes only after distractor skills, skipped steps, wrong composition, or omitted checks.

### 2. Multi-turn coding agents need regression gates

Regression Accumulation turns coding chat into an 8-turn requirement-evolution test. Across six models, 40 to 73 percent of tasks lose previously correct behavior over the full conversation. Verification Gate, which checks new code against prior tests and rolls back on regression, is the only tested mitigation that consistently improves every model.

### 3. Coding-agent steerability belongs in the substrate

Steerability via constraints argues that access control, network policies, strict conventions, typed boundaries, layered docs, and deterministic tools are cheaper and stronger than reviewing unconstrained agent work. In a controlled backdoor-review task, constrained substrate plus a compact docs CLI improved small-reviewer recall from 54.5 percent to 90.9 percent.

### 4. Approved enterprise tasks should compile into budgeted database sessions

SessionBound turns approved enterprise tasks into short-lived, budgeted, auditable database sessions. The important move is deterministic enforcement: signed task tokens bind safe views, row scope, denied fields, operation limits, query budgets, disclosure budgets, and receipts before the agent's generated SQL can execute.

## What is implementable now

- Add SkillCoach-style process rubrics to skill traces and registry records.
- Keep prior coding-turn requirements as tests or invariants, then run them on every later turn.
- Default coding agents into constrained workspaces with protected paths, network limits, type checks, linters, and local docs surfaces.
- Prototype task-scoped database sessions with signed tokens, row and column scope, operation budgets, and receipts.
- Treat final success as an outcome signal, not proof that the agent used the right process.

## Working conclusion

The daily thesis is process-bound authority. The next serious agent stack should not just ask whether the final answer looks right. It should prove that the skill path, coding conversation, workspace substrate, and data session stayed inside an enforceable process contract.
