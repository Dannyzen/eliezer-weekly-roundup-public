# Daily AI Agent Research Roundup — 2026-06-02

## Thesis

Today’s scan says the agent stack is shifting from capability packaging to lifecycle enforcement. The important control points are no longer only prompts and final actions. They are skill mutation, precommit tool observation, transfer across task streams, process evidence, and versioned runtime operations.

## Top findings

### 1. SkillHarm makes skills a lifecycle attack surface

SkillHarm shows that third-party skills can be attacked across their lifecycle, not only during one task execution. Fixed-payload poisoning compromises any task that invokes a poisoned skill. Self-mutating poisoning is worse: an initially benign skill execution silently mutates persistent skill content and defers harm until later reuse.

Implementable now:
- make production-admitted skills immutable during execution;
- block skill self-modification outside reviewed patch paths;
- log skill source, version, body hash, manifest hash, and verification level;
- test install, retrieval, execution, update, reuse, quarantine, and rollback.

Implementability score: 0.82

Source:
- https://arxiv.org/abs/2606.02540v1

### 2. Ghost tool calls turn precommit observation into a governance problem

Speculative tool dispatch can leak user intent before an agent commits to a branch. Read-only status does not solve it. Allow-lists do not solve it. The disclosure happened when the external service observed the request. The control has to happen at issue time: suppress the speculative call, change its destination, or project/redact its arguments before dispatch.

Implementable now:
- classify external observation as an effect;
- keep speculative planning local when possible;
- add issue-time policy before precommit external calls;
- log branch state, speculative calls, suppressed calls, argument projections, and final commit path.

Implementability score: 0.60

Source:
- https://arxiv.org/abs/2606.02483v1

### 3. Agent evals need controlled transfer streams and process scoring

AGENTCL argues that continual-learning eval should use controlled task streams where earlier sub-solutions, evidence, or workflows are intentionally reusable later. ClinEnv adds the long-horizon process lesson: outcome quality and process quality can decouple sharply. A model can look plausible at the end while gathering evidence badly, issuing redundant queries, or failing late-stage management actions.

Implementable now:
- build task streams with known reusable sub-solutions;
- score transfer, negative transfer, forgetting, retrieval precision, and cost separately;
- build staged simulations that force evidence gathering before commitments;
- grade process defects separately from final answers.

Implementability score: 0.70 for AGENTCL-style controlled transfer eval; 0.53 for ClinEnv-style staged interactive process eval.

Sources:
- https://arxiv.org/abs/2606.02461v1
- https://arxiv.org/abs/2606.02568v1

### 4. AgentOps is becoming deployable runtime infrastructure

AWS, Microsoft, and IBM all point at the same production shape: agents are CI/CD-managed runtime artifacts. The deployable unit includes agent definitions, tool registries, memory configs, identity propagation, eval suites, trace schemas, policy controls, release gates, and observability. This is not just orchestration. It is operational governance.

Implementable now:
- version agents, tools, memory config, prompts, policies, and eval fixtures together;
- test identity propagation, tool authorization, memory access, HITL gates, and rollback in pre-prod;
- register agents, tools, skills, MCP servers, and ownership metadata;
- trace decisions, tool calls, denied calls, memory use, cost, latency, errors, and outcomes.

Implementability score: 0.76

Sources:
- https://aws.amazon.com/blogs/machine-learning/agentops-operationalize-agentic-ai-at-scale-with-amazon-bedrock-agentcore/
- https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-at-build-2026/
- https://huggingface.co/blog/ibm-research/agent-logic-and-scalable-ai-adoption

## What to do with this

Short-term build moves:
- Add immutable loaded-skill hashes and reviewed skill-patch gates.
- Add issue-time policy for any speculative external tool dispatch.
- Create one controlled transfer-eval stream where previous episodes should help later tasks.
- Treat agent, tool, memory, policy, and eval config as one versioned release unit.
