# Daily AI Agent Research Roundup - 2026-06-20

## Thesis

The agent stack is becoming runtime-object-shaped. Today's best signals all point away from giant prompts and toward explicit objects: state ledgers, skill candidates, trajectory repositories, repo-native instructions, issue fields, and queue-managed agent populations.

## Top findings

### 1. LedgerAgent makes task state and policy checks explicit

A tool-calling agent should not infer current task state from a transcript every time it acts. LedgerAgent maintains facts, identifiers, constraints, and conditions in a separate ledger, renders that ledger into the prompt, and checks state-dependent policies before environment-changing tool calls execute.

What to do now: build typed task ledgers for high-risk workflows and attach policy checks before mutation tools.

Category: AgenticAI and Strategy

Implementability score: 0.82

Source: https://arxiv.org/abs/2606.20529

### 2. SKILL.md trajectory mining is diagnostic, not automatic promotion

The SKILL.md mining paper shows readable clusters from GUI trajectories, but weak downstream transfer. Five of eight mined clusters reach 0.95+ purity, yet GRPO only moves IW skill-step accuracy from 18.5% to 20.5%, BrowseComp+ stays essentially unchanged, and trivial frequency priors beat the method on key source-domain metrics.

What to do now: mine traces to identify candidate skills, but require held-out task improvement, scanner output, and review before a generated skill gets default authority.

Category: AgenticAI

Implementability score: 0.61

Source: https://arxiv.org/abs/2606.20363

### 3. Multi-Agent Transactive Memory makes completed trajectories reusable

MATM treats agent trajectories as reusable population-level memory. Producer agents contribute completed trajectories; consumer agents retrieve relevant ones. The reported ALFWorld and WebArena gains come without joint training or explicit coordination.

What to do now: store successful and failed trajectories as indexed artifacts with task, environment, tool sequence, state delta, and outcome metadata. Retrieve them as examples and warnings, not blind instructions.

Category: AgenticAI

Implementability score: 0.68

Source: https://arxiv.org/abs/2606.19911

### 4. GitHub is turning repo state into agent control state

GitHub Copilot code review now reads repository-root `AGENTS.md`; GitHub's MCP server can now read and write issue fields. That makes repository instructions and structured project metadata part of the agent control surface.

What to do now: add concise `AGENTS.md` files to repos where agents review code, and scope MCP issue-field writes by workflow identity. Treat field mutation as work-state mutation.

Category: Strategy

Implementability score: 0.90

Sources:
- https://github.blog/changelog/2026-06-18-copilot-code-review-agents-md-support-and-ui-improvements
- https://github.blog/changelog/2026-06-18-duplicate-detection-and-issue-fields-mcp-support-for-github-issues

## Practical implementation moves

1. Add a task-state ledger schema to one side-effecting agent workflow.
2. Write pre-mutation policy checks over ledger fields before write/refund/delete/send/deploy tools.
3. Mine existing traces for candidate skills, but hold them in review until replay tests show improvement.
4. Start a trajectory repository for repeated agent tasks, including failures and avoided retries.
5. Add a repository-root `AGENTS.md` to coding-agent repos and keep it short enough to test.
6. Use GitHub issue fields as typed agent work-state only behind scoped MCP access.
