# Friday Synthesis: Week ending 2026-06-05

This week’s strongest signal is that agent systems are becoming evidence-bearing control planes. The useful question is no longer “can the model use another tool, skill, memory, search result, or context compressor?” It is “which runtime artifact had authority to shape this run, what scope did it have, and what evidence proves it behaved?”

The practical model is clear: make capabilities explicit before admission, preserve trajectory evidence during execution, and push high-authority effects through gateways that bind identity, origin, budget, policy, and replayable traces.

## Executive Summary

1. **Skills became capability governance.** NVIDIA verified skills, SkillHarm, SkillGuard, state-grounded skill retrieval, SciVisAgentSkills, and EVA-Bench all point to the same move: skills need metadata, permissions, tests, fixtures, provenance, and lifecycle controls.
2. **Evaluation moved from final answers to evidence-bearing trajectories.** Real-session coding labels, belief-state gates, proposal-soundness filters, production-failure fixtures, continual-transfer streams, domain-state fixtures, search-contamination controls, and artifact-loop benchmarks all make answer-only grading look obsolete.
3. **The gateway became the strategic control plane.** MCP guidance, principal/session binding, cloud storage MCP, AgentCore Gateway, description-code mismatch, WebMCP poisoning, token-budget leases, workflow contracts, and sandbox controls all converge on identity-bound runtime mediation.

## Deep Dives

### 1. Skills should be governed capability artifacts, not prompt decorations
- Category: [AgenticAI](../AgenticAI/2026-06-05/reasoning.md#skills-should-be-governed-capability-artifacts-not-prompt-decorations)
- Durable topic: [Skills as Control](../AgenticAI/skills-as-control/skills-as-control.md)
- Core sources: https://github.com/NVIDIA/skills, https://developer.nvidia.com/blog/nvidia-verified-agent-skills-provide-capability-governance-for-ai-agents/, https://arxiv.org/abs/2606.02540v1, https://arxiv.org/abs/2606.03024v1, https://arxiv.org/abs/2606.04391, https://arxiv.org/abs/2606.05525, https://huggingface.co/blog/ServiceNow-AI/eva-bench-data
- Why it matters: skills are now both leverage and attack surface. They can encode procedure, domain state, fixtures, and tool discipline, but they can also smuggle unsafe lifecycle behavior, overbroad permissions, or stale assumptions into every future run.
- Implementable now: require skill cards with purpose, scope, permissions, inputs, outputs, owner, version, loaded hash, tests, fixtures, negative cases, and retirement criteria. Gate load decisions by task, current state, and policy. Pair important skills with executable validators, not only prose.
- Implementability score: 0.80

### 2. Agent evals need trajectory, process, state, and contamination evidence
- Category: [AgenticAI](../AgenticAI/2026-06-05/reasoning.md#agent-evals-need-trajectory-process-state-and-contamination-evidence)
- Durable topics: [Trajectory-Aware Evaluation](../AgenticAI/trajectory-aware-evaluation/trajectory-aware-evaluation.md), [Agent Harness Architecture](../AgenticAI/agent-harness-architecture/agent-harness-architecture.md), [Agentic Search and Retrieval](../AgenticAI/agentic-search/agentic-search.md)
- Core sources: https://arxiv.org/abs/2605.29442v1, https://arxiv.org/abs/2605.30329v1, https://aws.amazon.com/blogs/machine-learning/build-a-test-suite-that-grows-with-your-agent-with-dataset-management-in-amazon-bedrock-agentcore/, https://arxiv.org/abs/2606.02461v1, https://arxiv.org/abs/2606.02568v1, https://arxiv.org/abs/2606.05080, https://arxiv.org/abs/2606.05241
- Why it matters: a correct final answer can hide the reason the system should fail review: leaked benchmark context, wrong process, unsafe tool use, invalid backend state, lost proposal soundness, or brittle long-horizon recovery.
- Implementable now: store tool traces, search queries, clicked URLs, retrieved snippets, backend state, intermediate artifacts, verifier outputs, process-defect labels, and contamination labels with every result. Run no-search, no-skill, wrong-skill, and repeated-trial baselines.
- Implementability score: 0.76

### 3. Memory and context systems should preserve evidence before compressing it
- Category: [AgenticAI](../AgenticAI/2026-06-05/reasoning.md#memory-and-context-systems-should-preserve-evidence-before-compressing-it)
- Durable topics: [Memory Systems](../AgenticAI/memory-systems/memory-systems.md), [Context Economy](../AgenticAI/context-economy/context-economy.md)
- Core sources: https://arxiv.org/abs/2605.30219v1, https://arxiv.org/abs/2605.31086, https://arxiv.org/abs/2605.31575, https://arxiv.org/abs/2606.03463v1, https://github.com/chopratejas/headroom
- Why it matters: long-lived agents do not fail only because they forget. They fail because they update beliefs without provenance, retrieve stale distractors, compress away ground truth, or let noisy context pretend to be authority.
- Implementable now: keep raw episodes and evidence IDs outside the prompt, classify memory decisions as stay, update, or isolate, use deterministic retention/pruning before generative summaries, add distractor-rich retrieval fixtures, and test compression against answer preservation.
- Implementability score: 0.79

### 4. Multi-agent coding should be dependency-wave orchestration, not broadcast chat
- Category: [AgenticAI](../AgenticAI/2026-06-05/reasoning.md#multi-agent-coding-should-be-dependency-wave-orchestration-not-broadcast-chat)
- Durable topic: [Multi-Agent Orchestration](../AgenticAI/multi-agent-orchestration/multi-agent-orchestration.md)
- Core sources: https://arxiv.org/abs/2605.30335v1, https://arxiv.org/abs/2606.03115v1, https://arxiv.org/abs/2605.12925v3
- Why it matters: the week’s multi-agent evidence says bigger teams are not automatically better. Agents can be locally coherent and globally incoherent unless decomposition, dependencies, interfaces, conflict checks, and process defects are explicit.
- Implementable now: decompose work into a dependency DAG, dispatch only ready waves, preserve subclaim provenance, require interface contracts between agents, run coherence checks after merges, and score process defects separately from final task success.
- Implementability score: 0.64

### 5. The agent gateway is becoming the identity-bound MCP data plane
- Category: [Strategy](../Strategy/2026-06-05/sovereignty.md#the-agent-gateway-is-becoming-the-identity-bound-mcp-data-plane)
- Durable topic: [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md)
- Core sources: https://www.nsa.gov/Press-Room/Press-Releases-Statements/Press-Release-View/Article/4496698/nsa-releases-security-design-considerations-for-ai-driven-automation-leveraging/, https://github.com/modelcontextprotocol/python-sdk/releases/tag/v1.27.2, https://cloud.google.com/blog/topics/developers-practitioners/build-ai-agents-faster-with-gcs-google-cloud-storage-mcp-server/, https://aws.amazon.com/blogs/machine-learning/extending-mcp-support-for-amazon-bedrock-agentcore-gateway-2/, https://aws.amazon.com/blogs/machine-learning/building-a-secure-auth-code-flow-setup-using-agentcore-gateway-with-mcp-clients/, https://arxiv.org/abs/2606.03518
- Why it matters: MCP is crossing from developer convenience into data-plane infrastructure. Storage, browser security, cloud workflows, SaaS, and local devices become agent-callable. The sovereignty boundary is the gateway that decides what a principal, agent, session, workflow, and delegated task may do.
- Implementable now: put MCP servers behind a gateway, bind user, agent, client, server, session, and workflow identity, scope tool discovery, project data before disclosure, mediate credentials, record policy IDs, and test permission laundering with canary flows.
- Implementability score: 0.76

### 6. Tool surfaces and runtime contracts are now security boundaries
- Category: [Strategy](../Strategy/2026-06-05/sovereignty.md#tool-surfaces-and-runtime-contracts-are-now-security-boundaries)
- Durable topics: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md), [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md)
- Core sources: https://arxiv.org/abs/2606.04769, https://arxiv.org/abs/2606.06387, https://arxiv.org/abs/2606.04056, https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-at-build-2026-announce/, https://aws.amazon.com/about-aws/whats-new/2026/06/aws-step-functions-agentcore/, https://github.blog/changelog/2026-06-02-cloud-and-local-sandboxes-for-github-copilot-now-in-public-preview/
- Why it matters: tool descriptions, WebMCP registrations, token budgets, workflow states, sandbox identity, retry policy, and external observation are not background metadata. They determine what the model thinks is allowed and what the environment observes.
- Implementable now: hash and revalidate tool metadata, bind dynamic tools to origin and version, freeze visible tools at policy checkpoints, enforce single-spend budget leases, record workflow and sandbox contracts as trace fields, and verify observed tool effects against declared descriptions.
- Implementability score: 0.81

## Signals

- **Highest single implementability:** Headroom-style local context compression at 0.86. It is not a trust decision yet, but measuring token reduction and answer preservation against local logs is straightforward. Source: https://github.com/chopratejas/headroom
- **Highest week-level Strategy score:** tool-surface and runtime-contract integrity at 0.81. The implementation path is mostly gateway plumbing, hashing, policy checks, traces, and sandbox metadata.
- **Lowest week-level score:** speculative external observation governance at 0.60. Ghost tool calls are strategically important, but robust issue-time privacy policy is still architecture-heavy. Source: https://arxiv.org/abs/2606.02483v1
- **Best immediate build target:** a skill admission schema plus an evidence package trace schema. Together they make capability selection and run review auditable without waiting for model changes.
- **Noise filter:** deprioritize larger tool catalogs, generic MCP wrappers, broad skill marketplaces, and benchmark leaderboards that do not expose scope, provenance, fixtures, traces, or failure labels.

## Actionable Insights

1. **Admit skills like software artifacts.** Add owner, version, hash, permissions, preconditions, tests, fixtures, and retirement policy before a skill can affect production runs.
2. **Standardize an evidence package.** For every agent run, keep task, sources, prompts, retrieved evidence, tool calls, state snapshots, artifacts, verifier outputs, policy decisions, and failure labels.
3. **Put MCP behind a gateway.** Treat tool discovery, storage access, browser/admin surfaces, OAuth, data projection, and exfiltration checks as one control plane.
4. **Add contamination controls to research evals.** Preserve search logs, isolate benchmark metadata, run no-search baselines, and grade leakage separately from accuracy.
5. **Make memory writes reviewable.** Store raw episodes, preserve provenance, classify belief updates, and prevent generative summaries from becoming unverified authority.
6. **Route multi-agent work through dependency waves.** Do not let agents chat until there is a task DAG, interface contract, merge check, and process-quality label.
7. **Trace runtime contracts.** Budget leases, workflow retries, sandbox identity, visible tools, metadata hashes, and approval gates should be visible in the run log.
