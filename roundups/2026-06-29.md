# Daily roundup, 2026-06-29

## Bottom line

Today's scan strengthens one thesis: serious agent systems need control at the repository and information-flow layers, not only at the agent prompt.

The actionable stack shape is:

1. measure coding-agent risk at the repository level;
2. put architecture-changing agents behind verifier cascades;
3. audit privacy across tool arguments and backend sinks;
4. treat prompt injection as a control-data separation problem.

## Top findings

### 1. Repository-level risk means coding-agent evals have to measure the repo

Category: AgenticAI
Analysis: [AgenticAI reasoning](../AgenticAI/2026-06-29/reasoning.md#repository-level-risk-means-coding-agent-evals-have-to-measure-the-repo)
Core source: https://arxiv.org/abs/2606.28235v1
Implementability score: 0.70

Agent-authored PRs can each look locally acceptable while the repository accumulates integration friction. The unit of governance should be the repo: merge delay, review churn, conflict rate, CI retries, rollback rate, and post-merge defects.

### 2. Verification-aware harnesses turn architecture work into a checked loop

Category: AgenticAI
Analysis: [AgenticAI reasoning](../AgenticAI/2026-06-29/reasoning.md#verification-aware-harnesses-turn-agentic-architecture-work-into-a-checked-loop)
Core source: https://arxiv.org/abs/2606.27243v2
Implementability score: 0.66

NOVA is the useful harness pattern: agents propose architecture changes, but verifier cascades check semantics, executability, offline metrics, production constraints, and high-risk handoff before promotion.

### 3. Purpose-bound privacy makes tool arguments part of the security boundary

Category: Strategy
Analysis: [Strategy sovereignty](../Strategy/2026-06-29/sovereignty.md#purpose-bound-privacy-makes-tool-arguments-part-of-the-security-boundary)
Core source: https://arxiv.org/abs/2606.28061v1
Implementability score: 0.78

ToolPrivacyBench shows why final-response privacy checks are too shallow. An agent can complete the task while sending private fields to unnecessary tools. Privacy has to be audited over the trajectory.

### 4. Prompt injection is a control-data separation problem

Category: Strategy
Analysis: [Strategy sovereignty](../Strategy/2026-06-29/sovereignty.md#prompt-injection-is-a-control-data-separation-problem-not-a-better-prompt-problem)
Core source: https://arxiv.org/abs/2606.27567v1
Implementability score: 0.44

The useful implication is architectural: if trusted instructions and untrusted data share the same representational channel, the model cannot be the only authority boundary. Tool grants, policy routing, and memory writes need external enforcement.

## What is implementable now

- Add repo-level PR friction metrics for coding-agent work.
- Require verifier cascades before agent-proposed architecture changes advance.
- Add field-level purpose policies and argument audit logs to one sensitive tool workflow.
- Preserve provenance and taint labels through tool calls, memory writes, and policy decisions.

## Implementability range today

Highest score: 0.78, purpose-bound tool privacy.
Lowest score: 0.44, prompt-injection impossibility as an architectural theorem.
