# Daily AI and Agent Research - 2026-10-23

## Thesis

Today's strongest signal is that agent reliability improves when runtimes own the transition from evidence to action: normalize effects for replay, recover facts before consequential calls, route skill abstraction during execution, and reward terminal state instead of persuasive narration.

## Top findings

### 1. AgentTriage makes cross-runtime security diagnosis replayable

A canonical event contract captured all 159 applicable executions across five runtimes. On 120 adjudicated cases, the system reports 0.858 grounded joint diagnosis, 0.966 required-evidence coverage, and a 0.036 unsupported-claim rate.

Sources: [paper v1](https://arxiv.org/abs/2610.30738v1), [Apache-2.0 repository](https://github.com/AsnGs/agenttriage-open-source)

Implementability score: 0.84

### 2. Skill granularity is a runtime routing decision

Adaptive Skill Granularity moves skill choice below retrieval. The runtime chooses micro tools, macro skills, or macro-to-micro recovery and grades route match, state transition correctness, success, and cost.

Sources: [paper v1](https://arxiv.org/abs/2610.31461v1), [public repository](https://github.com/Jayceon-3/Adaptive-Skill-Agent)

Implementability score: 0.78

### 3. Missing evidence is a distinct safety boundary

EpiSEM-Bench uses 300 matched safe and unsafe task pairs to test whether agents recover omitted facts, withhold prohibited effects, and still complete permissible twins. Recovery access reduced unsafe execution for all 10 models, but safe restraint did not reliably become useful recovery.

Source: [paper v1](https://arxiv.org/abs/2610.31650v1)

Implementability score: 0.68

### 4. Executable database-state checks can train repeatability

ThinkingBox Training reuses terminal database and side-effect checks as GRPO rewards. The reported 27B checkpoint increased pass@1 from 51.70% to 60.78% and repeated 20-of-20 task success from 38 to 107, while pass@20 declined slightly.

Sources: [implementation article](https://huggingface.co/blog/microsoft/thinkingbox-training), [public repository](https://github.com/microsoft/thinkingbox-training)

Implementability score: 0.62

## What to implement now

1. Define one canonical lifecycle for source ingress, tool intent, tool result, and terminal effect.
2. Bind security findings to replayable event IDs and mark synthesized identity explicitly.
3. Require critical evidence or a recovery attempt before high-impact effects.
4. Add preconditions, postconditions, and micro-tool fallbacks to macro skills.
5. Use deterministic world-state checks for evaluation before considering RL training.
