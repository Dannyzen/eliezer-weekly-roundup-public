# Deep Dive Wednesday Roundup, 2026-07-08

This week's strongest finding is Context-to-Execution Integrity. The shared thesis across the week is representation integrity, but CXI is the durable architecture move: agent platforms need a release gate between writable context and protected execution.

## Weekly deep dive

### Context-to-Execution Integrity separates evidence from authority

Deep dive: [Context-to-Execution Integrity](../Strategy/context-to-execution-integrity/context-to-execution-integrity.md)
Category: Strategy
Implementability score: 0.70

CXI says an agent can read attacker-writable context without letting that context choose a tool, fill a protected argument, mark approval as satisfied, schedule a retry, or trigger a side effect. Protected sink fields need typed releases, exact-effect commitments, and invocation authority bound to the same canonical action manifest.

Why it won: the week had several strong boundary findings, but CXI connects them. Unicode TAG-block concealment shows approval views can lie. Untrusted Content Masking restores a browser observation boundary. Agent Data Injection shows trusted-looking data can steer agents. SessionBound scopes database execution. CXI supplies the common runtime rule: evidence can be read, but authority must be released.

Core sources:
- https://arxiv.org/abs/2607.06000v1
- https://anonymous.4open.science/r/cxi

### 2. MCP approvals need view-to-bytes fidelity

The Unicode TAG-block MCP paper shows that tool metadata can look benign in an approval dialog while hiding model-visible payload bytes. The fix is practical: canonicalize, scan, hash, and compare the approval view against the exact bytes that reach model context.

### 3. StateFuse makes multi-agent memory conflict-preserving

StateFuse is a lightweight Python library and paper for deterministic, conflict-preserving agent memory built around immutable operations, explicit conflicts, correction handles, and deterministic projections. The key lesson is to preserve disagreement rather than flatten multi-agent memory into last-write-wins state.

## What is implementable now

- Build a small internal SWE-bench-style replay pack for one Danny-owned repository or language surface.
- Add MCP metadata scans for invisible Unicode, TAG-block characters, bidi controls, zero-width characters, control bytes, and metadata drift after approval.
- Represent multi-agent memory writes as immutable claim operations with explicit conflict objects and correction handles.
- Mark protected sink fields on privileged tools and require typed releases before untrusted context can populate them.
- Prototype a repository-file-write execution broker with FilePath releases, patch exact-effect commitments, invocation leases, and JSONL allow/deny traces.

## Working conclusion

Representation integrity is now a buildable layer. The next serious agent stack should have replayable eval packs, conflict-preserving state, faithful approval views, and typed release gates between untrusted context and protected execution.
