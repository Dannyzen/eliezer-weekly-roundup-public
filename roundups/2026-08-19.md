## Thesis

Reliable agents need explicit gates at state transitions: harness configuration, memory-to-context admission, tool-code lowering, and self-improvement promotion. Completed tasks are not safety evidence.

## Top findings

### 1. Harness safety is a lifecycle, not a model score

Across 128 sandboxed cases, three harnesses, and 14 model-harness configurations, attack success ranged from 12.6% to 80.9% while utility stayed between 75.0% and 97.6%. Configuration was the weakest phase. Detection above 90% still left substantial attack success.

Implementability score: 0.86

Sources:
- https://arxiv.org/abs/2608.17597v1
- https://baiyajing.github.io/harness-risk/
- https://github.com/Baiyajing/HarnessRisk
- https://huggingface.co/datasets/YajingB/HarnessRisk

### 2. Memory must be authorized before it enters context

A single anti-monotone audience-membership rule at the memory-to-context boundary keeps facts inside the audience that produced them. In the evaluated configuration, no known forbidden fact entered unauthorized context, and audited read paths failed closed.

Implementability score: 0.78

Source:
- https://arxiv.org/abs/2608.17148v1

### 3. Self-improvement needs order and variance controls

Memory-based self-improving agents increased variance in 71% of cases. The default task order produced a 1.5% gain; shuffled orders produced a 4.5% loss. Extra specification closed only 31% of that gap.

Implementability score: 0.84

Sources:
- https://arxiv.org/abs/2608.18066v1
- https://github.com/SalesforceAIResearch/self-improve-fragility
- https://huggingface.co/datasets/Salesforce/self-improve-fragility

### 4. Skill code needs checked lowering before dispatch

When models emit tool programs, they default to eager full-input access. SkillEffect rebuilds a bounded lowering from the program and immutable input before granting execution. In the smolagents path, all 16 eager calls were lowered and all 48 capped repeats verified.

Implementability score: 0.62

Source:
- https://arxiv.org/abs/2608.17007v1

## What is implementable now

- Score harness runs on utility, attack success, persistence, and detection, with configuration fixtures first.
- Stamp recorded audience on memory writes and exclude unauthorized items before prompt assembly.
- Require multi-run and shuffled-order evidence before promoting self-written memories or workflows.
- Register bounded implementations for large-input tools and reject unchecked eager plans.

## Current implication

The next control plane is the transition, not the transcript. Configuration, recall, generated tool code, and learned memory all change what the agent can do later. Those transitions need receipts.
