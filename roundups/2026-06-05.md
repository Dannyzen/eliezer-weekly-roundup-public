# Daily AI Agent Research Roundup - 2026-06-05

## Thesis

Today's scan says agent reliability is moving into the layers around the model: search isolation, domain-specific tool fixtures, context compression middleware, and runtime tool-surface integrity. The common pattern is simple: do not let the model infer authority from whatever context, search result, skill, or web-exposed tool happens to be visible.

## Top findings

### 1. Deep-research evals need search-contamination controls

Search-enabled agents can retrieve benchmark metadata, question context, or explicit answers during inference. That turns public benchmarks into leaky evaluation environments unless the harness stores search trajectories and controls what can be retrieved.

Implementable now:
- run no-search baselines;
- log queries, clicked URLs, retrieved snippets, and evidence paths;
- isolate benchmark metadata and answer keys from the search corpus;
- score contamination separately from answer accuracy.

Implementability score: 0.74

Source:
- https://arxiv.org/abs/2606.05241

### 2. WebMCP tool surfaces need origin-bound lifecycle controls

WebMCP Tool Surface Poisoning shows how dynamic web-exposed tools can be hijacked or framed mid-session, especially through third-party scripts. This is the runtime version of MCP description mismatch: the agent may be deciding from a manipulated tool surface.

Implementable now:
- bind tool identity to origin and version;
- hash and revalidate tool metadata;
- freeze or checkpoint the visible tool set before high-risk calls;
- log tool registration, mutation, selected call, and observed effect.

Implementability score: 0.80

Source:
- https://arxiv.org/abs/2606.06387

### 3. Agent evals are becoming domain-specific tool and state fixtures

SciVisAgentSkills and EVA-Bench Data 2.0 point in the same direction: useful agent evaluation needs domain tools, realistic backend state, expected final state, and reproducible scenario generation. Generic tool-use tasks are too thin.

Implementable now:
- package one internal domain workflow as a skill plus fixture;
- give each fixture initial state, allowed tools, expected final state, and negative cases;
- score tool-call correctness, authentication, final state, and trace quality separately.

Implementability score: 0.68

Sources:
- https://arxiv.org/abs/2606.05525
- https://github.com/KuangshiAi/SciVisAgentSkills
- https://huggingface.co/blog/ServiceNow-AI/eva-bench-data
- https://huggingface.co/datasets/ServiceNow-AI/eva-bench

### 4. Context compression is becoming local-first middleware

Headroom is an open-source tooling signal: context compression is being packaged as a library, proxy, MCP server, and agent wrapper. The repo's quality claims still need local smoke testing, but the architecture is right: compress noisy evidence before it reaches the model, keep originals retrievable, and measure token reduction against answer preservation.

Implementable now:
- add token-category counters to agent traces;
- test compression on logs, JSON, code, and RAG chunks separately;
- keep original evidence outside the prompt for retrieval and audit;
- run any third-party compression layer in a local sandbox before production use.

Implementability score: 0.86

Source:
- https://github.com/chopratejas/headroom

## Highest and lowest implementability today

Highest: 0.86 for Headroom-style local context compression middleware.
Lowest: 0.68 for domain-specific skill and tool-state fixtures, because the pattern is clear but requires real domain modeling, validators, and fixture maintenance.

## What to do with this

Short-term build moves:
- Add search-contamination labels and no-search baselines to any deep-research eval.
- Treat dynamic web-exposed tools as mutable runtime state, not trusted page metadata.
- Build one domain-specific skill fixture with initial state, expected final state, and validators.
- Measure context compression with answer-preservation tests before adopting a middleware layer.
