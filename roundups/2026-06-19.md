# Friday Synthesis: Week ending 2026-06-19

This week’s strongest signal is runtime objectification. The agent stack is turning implicit prompt-time behavior into explicit platform objects: Session, memory event, skill manifest, capability catalog, tool contract, tool program, evidence packet, eval endpoint, and mutation certificate.

The practical conclusion is simple: if an agent system is serious, the model should not own state, capability, evidence, or authority. The runtime should.

## Executive Summary

1. **Sessioned state is becoming the agent runtime primitive.** OpenRath, GateMem, TencentDB Agent Memory, and recursive harness work all point at a branchable, replayable run-state object that binds memory, tools, workspace, lineage, and handoff evidence.
2. **Tool use is moving from static catalogs to discovered and compiled capabilities.** ToolPro, HyperTool, Agentic Resource Discovery, and context-selection papers make the tool layer searchable, cache-aware, effect-typed, and executable.
3. **Skills are becoming admitted behavior modules, not helpful prose.** Skill topology, SkillSpector, SkillWeaver, and learned skill work all imply the same control plane: scan, route, benchmark, freeze, and regression-test skills before they can affect a run.
4. **Evaluation is moving from terminal outcomes to trajectory evidence.** SafeClawBench, All Smoke No Alarm, trajectory-preference evaluation, HANSEL, and Hugging Face tooling evals separate oracle strength, harm layer, effort, route quality, and evidence path.
5. **Governance is becoming evidence provenance and runtime contract enforcement.** ProvenanceGuard, ContractGuard, C-Trace, TRACE, StakeBench, and Five-Plane Runtime Governance all make source ownership, policy predicates, and contract integrity trace-time fields.
6. **Mutation authority is leaving agents for brokers.** Sovereign Execution Brokers, DeepMind AI Control, API-router hardening, GitHub Agentic Workflows, and sandbox evidence work converge on a deployment rule: agents propose, brokers verify, scoped credentials mutate.

### 1. Sessioned state replaces scattered memory, context, and handoff logs

- Category: [AgenticAI](../AgenticAI/2026-06-19/reasoning.md#sessioned-state-replaces-scattered-memory-context-and-handoff-logs)
- Durable topics: [Event-Sourced Agent Runtime](../AgenticAI/event-sourced-agent-runtime/event-sourced-agent-runtime.md), [Memory Systems](../AgenticAI/memory-systems/memory-systems.md), [Agent Harness Architecture](../AgenticAI/agent-harness-architecture/agent-harness-architecture.md), [Multi-Agent Orchestration](../AgenticAI/multi-agent-orchestration/multi-agent-orchestration.md)
- Core sources: https://arxiv.org/abs/2606.19409v1, https://github.com/Rath-Team/OpenRath, https://arxiv.org/abs/2606.18829v1, https://github.com/TencentCloud/TencentDB-Agent-Memory
- Why it matters: memory, tool evidence, token use, sandbox placement, handoff state, and branch lineage cannot stay in separate logs once agents fork, replay, compress, and collaborate.
- How it fits: Session or run-state should sit below orchestration and above raw storage. Agents, tools, selectors, memory writers, sandboxes, and evaluators transform this object instead of reconstructing state after failure.
- Implementable now: define a Session schema with branch ID, parent ID, memory read/write references, tool evidence handles, workspace placement, token accounting, and replay pointers. Keep raw events append-only, then project compact prompt views from them.
- Implementability score: 0.77

### 2. Tool surfaces become discovered, compiled, and cache-aware

- Category: [AgenticAI](../AgenticAI/2026-06-19/reasoning.md#tool-surfaces-become-discovered-compiled-and-cache-aware)
- Strategic angle: [Strategy](../Strategy/2026-06-19/sovereignty.md#capability-discovery-and-skills-are-now-supply-chain-authority-surfaces)
- Durable topics: [Skills as Control](../AgenticAI/skills-as-control/skills-as-control.md), [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md), [Context Economy](../AgenticAI/context-economy/context-economy.md), [Agentic Search and Retrieval](../AgenticAI/agentic-search/agentic-search.md)
- Core sources: https://arxiv.org/abs/2606.19992v1, https://huggingface.co/blog/agentic-resource-discovery-launch, https://github.com/huggingface/hf-discover, https://arxiv.org/abs/2606.13663v1
- Why it matters: dumping every tool schema into context is not scalable. For repeated workflows, letting a model babysit endpoint calls is expensive, brittle, and hard to govern.
- How it fits: discovery should narrow the capability surface before prompt construction. Compiled tool programs should turn repeated multi-step service intent into checked execution objects with READ/WRITE effects and replay semantics.
- Implementable now: put scoped search in front of skills, MCP servers, A2A agents, and internal tools; log discovery query, selected capability, manifest hash, effect type, compiled program hash, execution result, and fallback path.
- Implementability score: 0.82

### 3. Skills become admitted and measured behavior modules

- Category: [AgenticAI](../AgenticAI/2026-06-19/reasoning.md#skills-become-admitted-and-measured-behavior-modules)
- Strategic angle: [Strategy](../Strategy/2026-06-19/sovereignty.md#capability-discovery-and-skills-are-now-supply-chain-authority-surfaces)
- Durable topics: [Skills as Control](../AgenticAI/skills-as-control/skills-as-control.md), [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md)
- Core sources: https://arxiv.org/abs/2606.11543v1, https://github.com/zhiyuchen-ai/skill-juror, https://github.com/NVIDIA/SkillSpector, https://arxiv.org/abs/2606.18051v1
- Why it matters: skills are executable influence. A markdown skill, retrieved adapter, MCP skill graph, or generated resource can route tools, mutate context, hide bad instructions, or improve performance. Treating skills as harmless docs is now a security and reliability bug.
- How it fits: skills need the same lifecycle as code and tools: provenance, dependency topology, utility measurement, security scanning, immutable runtime mounts, and promotion gates.
- Implementable now: require owner/hash/scope metadata, scan prose and scripts jointly, evaluate no-skill versus wrong-skill versus full-skill variants, compose skills through dependency DAGs, and mount admitted skills read-only.
- Implementability score: 0.75

### 4. Evaluation shifts from final outcome to trajectory, oracle, harm, and effort telemetry

- Category: [AgenticAI](../AgenticAI/2026-06-19/reasoning.md#evaluation-shifts-from-final-outcome-to-trajectory-oracle-harm-and-effort-telemetry)
- Strategic angle: [Strategy](../Strategy/2026-06-19/sovereignty.md#mutation-authority-leaves-agents-for-brokers-and-tamper-resistant-paths)
- Durable topics: [Trajectory-Aware Evaluation](../AgenticAI/trajectory-aware-evaluation/trajectory-aware-evaluation.md), [Agent Sandboxing](../Strategy/agent-sandboxing/agent-sandboxing.md), [Evidence Provenance Control Plane](../Strategy/evidence-provenance-control-plane/evidence-provenance-control-plane.md)
- Core sources: https://arxiv.org/abs/2606.18356v1, https://huggingface.co/blog/is-it-agentic-enough, https://openai.com/index/deployment-simulation, https://arxiv.org/abs/2606.18168v1
- Why it matters: pass/fail hides where the system actually failed. A test may pass with weak oracles. A model may refuse semantically while the tool protocol still mutates sandbox state. A library may work but force agents into long, deprecated, high-token paths.
- How it fits: evals should preserve the trajectory, intended API path, explicit oracle signal, environment state delta, harmful endpoint layer, and deployment-like distribution used for measurement.
- Implementable now: normalize traces into action alphabets, lint agent-authored tests for explicit oracles, separate semantic/audit/sandbox harm, track turns/tokens/time/errors/API path adoption, and replay representative historical tasks before rollout.
- Implementability score: 0.85

### 5. Governance moves to evidence provenance and runtime contracts

- Category: [Strategy](../Strategy/2026-06-19/sovereignty.md#governance-moves-to-evidence-provenance-and-runtime-contracts)
- Durable topics: [Evidence Provenance Control Plane](../Strategy/evidence-provenance-control-plane/evidence-provenance-control-plane.md), [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md), [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md)
- Core sources: https://arxiv.org/abs/2606.18037v1, https://arxiv.org/abs/2606.18550v1, https://arxiv.org/abs/2606.19242v1, https://arxiv.org/abs/2606.13385v1
- Why it matters: governance cannot live in prompt instructions if tools, memory, claims, retrieval, and delegation happen across multiple systems. The trace must carry source IDs, contract hashes, policy verdicts, compliance predicates, and harmed stakeholder labels.
- How it fits: this is the strategic control plane under MCP, agent gateways, enterprise orchestration, and regulated deployment. The unit of trust is not the final answer. It is the proof packet attached to a source, tool contract, policy rule, and trace segment.
- Implementable now: add source_id and raw_output_ref fields to tool outputs; require claim-to-source evidence for high-risk answers; sign and hash tool contracts; express policies over trace fields; compile recurring corrections into deterministic checks.
- Implementability score: 0.76

### 6. Mutation authority leaves agents for brokers and tamper-resistant paths

- Category: [Strategy](../Strategy/2026-06-19/sovereignty.md#mutation-authority-leaves-agents-for-brokers-and-tamper-resistant-paths)
- Durable topics: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md), [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md), [Agent Network Containment](../Strategy/agent-network-containment/agent-network-containment.md)
- Core sources: https://arxiv.org/abs/2606.20520v1, https://deepmind.google/blog/securing-the-future-of-ai-agents/, https://github.blog/changelog/2026-06-11-github-agentic-workflows-is-now-in-public-preview, https://arxiv.org/abs/2606.16358v1
- Why it matters: standing credentials inside an agent runtime bypass admission. If the agent can mutate production directly, certificates, policies, red teams, and monitors are advisory rather than binding.
- How it fits: mutation needs an external enforcement point. Agents propose; admission systems certify; brokers validate certificates, drift, revocation, policy epoch, and resource scope; short-lived scoped credentials perform the side effect; signed records close the loop.
- Implementable now: remove standing write credentials, route production mutations through a broker, mint scoped credentials only after validation, reject non-broker mutation identities, pin router/provider paths, and attach evidence dimensions to sandbox claims.
- Implementability score: 0.71

## Signals

- **Highest implementability this week:** trajectory, oracle, harm, and effort telemetry at 0.85. The cheap version uses existing trace storage, state snapshots, test-oracle linting, marker extraction, and deployment-simulation sampling.
- **Lowest implementability this week:** brokered mutation authority at 0.71. The pattern is real and implementable, but it requires IAM changes, live-state checks, revocation, broker enforcement, and production mutation paths that reject direct agent credentials.
- **Most durable Wednesday finding:** evidence provenance. ProvenanceGuard won the week because source ownership is the primitive that also explains oracle strength, tool contracts, skill routing, and brokered authority.
- **Noise filtered out:** generic model news, leaderboard churn, and isolated benchmark claims mattered less than papers and releases that changed runtime objects or operational evidence.

## Actionable Insights

1. **Make Session explicit.** Every serious agent run should have a branchable run-state object, not only logs and chat history.
2. **Search before exposing capabilities.** Discovery should narrow tools and skills before context construction.
3. **Compile repeated workflows.** Stable multi-step service patterns should become effect-typed programs or deterministic workflow calls.
4. **Admit skills like code.** Scan, route, benchmark, freeze, and regression-test them before they influence a run.
5. **Evaluate the path, not just the answer.** Preserve oracles, state deltas, harmful endpoint layers, effort metrics, and trajectory evidence.
6. **Bind governance to runtime fields.** Source IDs, contract hashes, policy predicates, capability manifests, and broker decisions should be first-class trace fields.
7. **Take credentials away from agents.** Let agents propose; let brokers mint scoped authority after certificate and policy checks.
