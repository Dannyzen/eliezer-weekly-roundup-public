# Daily AI and Agent Research - 2026-08-23

## Thesis

Agent improvement should be admitted only when the evidence identifies the mechanism, transfers across tasks, and survives an executable boundary test.

## Top findings

### 1. Self-improvement benchmarks must separate algorithm design from tuning

AI4AI-Bench evaluated 29 configurations of six systems across 10 frozen training repositories. More than half of the 263 changed submissions did not change how the model learned. Genuine algorithm changes scored better, but even the strongest system closed less than one fifth of the gap from the repository baseline to the task optimum.

Action now: classify agent changes by mechanism, then rerun them from a clean start under a hidden terminal evaluator and fixed budget.

Implementability score: 0.58

Sources:
- https://arxiv.org/abs/2608.20318v1
- https://lab.einsia.ai/ai4ai

### 2. Reusable skills belong at the subtask boundary

Across three long-horizon benchmarks and 11 models, whole-task skills usually hurt relative to no memory, while subtask-level text skills helped on average. The practical control is to admit atomic procedures only after they demonstrate transfer utility.

Action now: induce text skills per reusable subtask, score utility offline, and retain a no-memory baseline for every skill-assisted evaluation.

Implementability score: 0.72

Sources:
- https://arxiv.org/abs/2608.20274v1
- https://github.com/Zesearch/skill-transfer-llm-agents

### 3. Dependency upgrades need differential compatibility tests

BreakGuard generated tests from real client call sites and ran them against old and new dependency versions. It detected 27 of 89 real Java breaking changes. The public prototype makes the pattern usable now, but the 30.3 percent detection rate means it is a supplemental gate, not a complete proof.

Action now: require agent-assisted upgrades to include client-specific pass-to-fail evidence, static checks, and explicit uncovered call sites.

Implementability score: 0.82

Sources:
- https://arxiv.org/abs/2608.20167v1
- https://zenodo.org/records/22016493
- https://github.com/CuriousBeing1508/LLMBreakGuard

### 4. Prompt-injection defense should learn without becoming the authority boundary

COPA uses a lightweight LoRA adapter, GRPO, and margin-weighted replay to adapt across sequential attack variants while retaining earlier defenses. The measured gains are strong, but the study has no public artifact and remains architecture-heavy.

Action now: build a versioned attack corpus and shadow evaluation loop, while keeping tool authority, approvals, isolation, and side effects behind deterministic controls.

Implementability score: 0.38

Source: https://arxiv.org/abs/2608.19982v1

## Supporting tooling signal

Apache Maka appeared on GitHub Trending with an append-only local execution record and declarative multi-arm evaluation. Its current public artifacts predate the strict 48-hour release window, so it is a design reference rather than a top fresh finding.

Source: https://github.com/apache/maka

## Scope and duplicate gate

There is no Sunday arXiv announcement batch. All selected papers were first listed Friday, August 21 and submitted Thursday, August 20, so they are carry-forwards rather than new Sunday submissions. Exact paper IDs and titles were checked against the repository. Pandora's Router and Phantom Gains were excluded as August 22 duplicates. MidTool was reviewed but not selected because its 20.3 billion-token training path is operationally heavy and its paper-linked Hugging Face collection currently requires authentication, although individual public model and gated dataset records resolve.

Hugging Face, GitHub Trending, GitHub changelog feeds, vendor research pages, and arXiv category pages were scanned. Paper PDFs were downloaded as documents and converted to text on Bigs. No external repository source was cloned, downloaded, installed, built, imported, or executed.
