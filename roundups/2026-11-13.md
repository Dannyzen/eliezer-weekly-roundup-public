# Friday Synthesis: Evidence Is Not Authority

Week ending 2026-11-13

## Weekly thesis

The strongest findings this week all expose the same architectural mistake: treating a model output as sufficient justification for the next state change. Reliable agent systems preserve evidence across the loop, then let runtime-owned gates decide whether to answer, delegate, call a tool, promote memory, render an approval, or execute an effect.

## 1. Evidence sufficiency is a separate quality dimension

Correct answers can emerge from incomplete histories, weak controls, or a lucky run. The practical gate is support: grade whether the available evidence justifies the conclusion, and calibrate monitors so they distinguish task difficulty, model weakness, and run-specific failure.

Implementability score: 0.88

Sources: [Correct Answers from Insufficient Histories](https://arxiv.org/abs/2611.11840v1), [BioBasicsBench](https://openai.com/index/measuring-how-ai-agents-handle-wet-lab-science), [Hard Issue, Weak Model, or Bad Run?](https://arxiv.org/abs/2611.08285v1)

## 2. Orchestration needs evidence-preserving state transitions

Delegation can reduce quality when the parent distorts the source question, drops retrieval failures, or overwrites returned evidence. State-paired tests and trace compilation point toward a stronger orchestration model: explicit states, justified actions, lossless handoffs, and compiled workflows only where observed behavior is stable.

Implementability score: 0.76

Sources: [Lost in Delegation](https://arxiv.org/abs/2611.16526v1), [StateAlign](https://arxiv.org/abs/2611.16304v1), [ReTrace](https://arxiv.org/abs/2611.14492v1)

## 3. Memory should remain reversible and source-linked

The durable pattern across Anthropic's memory architecture, WikiTrace, FGSE, AstroMemBench, and MAPE is consistent: retain canonical events, derive query-specific memory, link every lesson to evidence, test writeback before promotion, and evaluate under operational scenarios and lifecycle cost.

Implementability score: 0.82

Sources: [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory), [Evidence-Linked Memory](https://arxiv.org/abs/2611.14320v1), [FGSE](https://arxiv.org/abs/2611.14326v1), [AstroMemBench](https://arxiv.org/abs/2611.16590v1), [MAPE](https://arxiv.org/abs/2611.17068v1)

## 4. Evaluation must include inherited state and final artifacts

Clean prompts hide the conditions that break deployed agents. Research workspaces, changed contracts, migration boundaries, tool errors, rendered deliverables, and side effects should all be part of the test fixture and receipt.

Implementability score: 0.84

Sources: [ARE-bench](https://arxiv.org/abs/2611.14364v1), [Accepted but Wrong](https://arxiv.org/abs/2611.08269v1), [Multimodal Knowledge Agent benchmark](https://blog.google/innovation-and-ai/models-and-research/gemini-models/multimodal-knowledge-agent-benchmark/)

## 5. Provenance and application-owned interfaces are deployable authority controls

GitHub's review attribution fields and A2UI 1.0 show product surfaces catching up with governance needs. Provenance can become a release input, while host-rendered components and scoped functions can bind visible approvals to exact effects.

Implementability score: 0.91

Sources: [GitHub Copilot review API update](https://github.blog/changelog/2026-11-06-copilot-code-review-api-management-and-review-overview-updates/), [A2UI 1.0](https://developers.googleblog.com/a2ui-10-build-delightful-fast-reliable-agentic-experiences/), [A2UI repository](https://github.com/a2ui-project/a2ui)

## 6. Cost control belongs at observable runtime boundaries

Harness interposition, executable verifiers, and program-level memory search all support the same implementation order: instrument first, optimize fixed workloads, retain candidate lineage, and keep rollback possible.

Implementability score: 0.64

Sources: [System Optimizations for Cost-Efficient Agent Harnesses](https://arxiv.org/abs/2611.12122v1), [MAPE](https://arxiv.org/abs/2611.17068v1), [TaxOps](https://huggingface.co/blog/Manoj2142/taxops-efficient-tool-agent)

## What is implementable now

1. Add evidence-sufficiency and abstention scores beside answer accuracy.
2. Require lossless evidence contracts for delegation and tool handoffs.
3. Keep raw event logs canonical and derived memory source-linked and reversible.
4. Build production-shaped fixtures from inherited state, changed contracts, and real artifacts.
5. Bind approvals to app-owned components, scoped functions, and exact-effect receipts.
6. Optimize tokens, latency, and memory cost only after runtime instrumentation exists.

## Implementability range

Highest: 0.91 for provenance-aware review and application-owned capability surfaces.

Lowest: 0.64 for harness-level cost optimization, because the pattern is ready but durable gains require workload-specific instrumentation and experiments.

## Provocative question

If an agent can change durable state without preserving the evidence that justified the transition, is the system learning, or merely accumulating unreviewable authority?
