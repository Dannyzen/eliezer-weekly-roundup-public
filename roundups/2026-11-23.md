# Daily Agent Research Roundup: 2026-11-23

## Thesis

Agent reliability depends on evidence and authority paths that remain outside the agent's writable environment. Today's papers make four boundaries concrete: isolated grading, exercised recovery proof, uncertain-effect reconciliation, and tool-metadata provenance.

## Top findings

### 1. Grade outside the candidate environment

SplitBench separates candidate execution from the trusted Oracle. It converted 180 of 202 tasks, matched native verdicts on 98.7% of attempts, and rejected 75% of completed full-knowledge adversarial attempts. Its weakness is upstream task quality, not the separation mechanism.

Action now: export bounded observations from a disposable runner and keep expected answers plus verdict logic in a separate trusted process.

Implementability score: 0.68

Source: [Who Grades the Agent?](https://arxiv.org/abs/2611.27860v1)

### 2. Require incident-shaped recovery evidence

Across 50 systems and eight recovery mechanisms, only 19 of 128 real-use reports described full recovery. Checkpoint or resume recovered once in 27 reports, and rollback or undo recovered once in 15.

Action now: inject faults and label recovered, partial, failed, and unclear outcomes. Do not promote a recovery feature from documentation alone.

Implementability score: 0.92

Sources: [Exercised, Rarely Recovered](https://arxiv.org/abs/2611.27090v1), [replication package](https://doi.org/10.5281/zenodo.24122560)

### 3. Reconcile uncertain effects before supplier failover

OPCP shows why retries across tool suppliers need persistent effect state. Retry-all duplicated every tested lost-reply-after-commit effect, while persistent runtime state prevented cross-supplier replay after restart.

Action now: model uncertain outcomes explicitly and fail closed until the first supplier's effect is reconciled.

Implementability score: 0.62

Source: [Keep the Process, Change the Supplier](https://arxiv.org/abs/2611.26966v1)

### 4. Govern tool descriptions as executable inputs

GRAFT changes MCP tool descriptions to preserve normal-looking tool selection while steering an argument to an attacker value. It reached 81.5% average stealthy attack success on MCP-SafetyBench and 63.8% on MCPTox.

Action now: pin tool descriptors and schemas, diff every change, and bind consequential argument values to trusted request evidence.

Implementability score: 0.76

Source: [Subverting Tool Arguments](https://arxiv.org/abs/2611.27041v1)

## Implementability range

- Highest: 0.92, exercised recovery evidence can be added to current QA and release gates now.
- Lowest: 0.62, supplier-swappable effect governance requires persistent runtime state, reconciliation, and idempotency contracts.
