# Daily roundup, 2026-06-25

## Bottom line

Today's scan strengthens one thesis: agents need explicit runtime and context contracts. Happy-path function calls, prompt-only design guidance, and in-runtime guardrails are the weak default.

The actionable stack shape is:

1. validated context artifacts before the agent edits;
2. hazard-injected tool tests before the agent ships;
3. two-pass execution when tool calls and schema constraints conflict;
4. external safety kernels before privileged actions mutate the world.

## Top findings

### 1. ToolBench-X turns tool-use eval into recovery testing

Category: AgenticAI
Analysis: [AgenticAI reasoning](../AgenticAI/2026-06-25/reasoning.md#toolbench-x-turns-tool-use-eval-into-recovery-testing)
Core source: https://arxiv.org/abs/2606.25819v1
Artifact: https://github.com/Foreverskyou/ToolBench-X
Implementability score: 0.68

ToolBench-X injects specification drift, invocation error, execution failure, output drift, and cross-source conflict into otherwise solvable tool tasks. The useful move is to score diagnosis and recovery, not only function-call formatting.

### 2. Constraint Tax shows tool calling and JSON Schema can interfere

Category: AgenticAI
Analysis: [AgenticAI reasoning](../AgenticAI/2026-06-25/reasoning.md#constraint-tax-shows-tool-calling-and-json-schema-can-interfere)
Core source: https://arxiv.org/abs/2606.25605v1
Implementability score: 0.78

The paper reports Tool Suppression when tool calling and schema-constrained decoding are enabled together. The practical mitigation is two-pass execution: tool-capable reasoning first, strict schema serialization second.

### 3. DESIGN.md makes agent UI context a validated artifact

Category: AgenticAI
Analysis: [AgenticAI reasoning](../AgenticAI/2026-06-25/reasoning.md#designmd-makes-agent-ui-context-a-validated-artifact)
Core source: https://github.com/google-labs-code/design.md
Package metadata: https://registry.npmjs.org/%40google%2Fdesign.md
Implementability score: 0.92

DESIGN.md is a useful concrete pattern for agent context files: machine-readable tokens plus human rationale, linted and diffed like code.

### 4. Execution-time safety kernels move alignment below prompts

Category: Strategy
Analysis: [Strategy sovereignty](../Strategy/2026-06-25/sovereignty.md#execution-time-safety-kernels-move-alignment-below-prompts)
Core source: https://arxiv.org/abs/2606.26057v1
Supporting source: https://arxiv.org/abs/2606.26028v1
Implementability score: 0.54

The Unfireable Safety Kernel argues that real agent control needs process separation, pre-action only-path enforcement, fail-closed behavior, and external signed evidence. The thin implementable version is an external reference monitor around dangerous tools.

## What is implementable now

- Add a small internal ToolBench-X-style test suite for 20 high-value tool workflows.
- Add joint-mode tests for tool calling plus strict JSON output, then use two-pass execution where needed.
- Add a `DESIGN.md` file to UI repos and make agents read it before UI edits.
- Wrap one high-risk tool with an external reference monitor that logs allow, deny, timeout, and fail-closed decisions.

## What did not make the top set

Progress Advantage for LLM Agents is worth watching for teams that control both RL-trained and reference-policy logprobs, but it is less immediately deployable than today's tool-reliability and context-contract findings.
