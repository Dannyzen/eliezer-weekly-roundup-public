# Daily Synthesis: 2026-06-13

Today’s strongest signal is that long-lived agent capability now needs admission control. Memory, skills, prompt-injection exposure, and GitHub-native workflows are all becoming stateful runtime assets. They should be versioned, tested, scanned, scoped, and traced before they can steer action.

## Executive Summary

1. **Memory needs evolution history and poisoning resistance.** EvoArena, MemRefine, and SMSR show that durable memory must handle changing environments, storage budgets, and adversarial writes.
2. **Skills are becoming dependency graphs.** SkillJuror, SkillCAT, and SkillSpector move skills from markdown advice to topology-aware, scanner-backed, verifier-admitted capability packages.
3. **Prompt-injection evaluation needs harmed-party evidence.** Stakeholder-centric web-agent benchmarks and PI-Hunter make source locality and stakeholder harm more important than a single attack-success number.
4. **Agentic workflows are now governed CI resources.** GitHub Agentic Workflows compiles natural-language automation into Actions with runner policy, sandboxing, safe outputs, and threat detection.

## Deep Dives

### 1. Memory systems need evolutionary state, compression, and poisoning gates

- Category: [AgenticAI](../AgenticAI/2026-06-13/reasoning.md#memory-systems-need-evolutionary-state-compression-and-poisoning-gates)
- Durable topics: [Memory Systems](../AgenticAI/memory-systems/memory-systems.md), [Event-Sourced Agent Runtime](../AgenticAI/event-sourced-agent-runtime/event-sourced-agent-runtime.md), [Context Economy](../AgenticAI/context-economy/context-economy.md)
- Core sources: https://arxiv.org/abs/2606.13681v1, https://arxiv.org/abs/2606.13177v1, https://arxiv.org/abs/2606.12703v1
- Why it matters: a persistent agent’s memory is an evolving state system. It can drift, bloat, compress away needed facts, or get poisoned across sessions.
- Implementable now: add update histories, storage budgets, delete/merge/preserve logs, writer provenance, signed write paths, and memory-poisoning fixtures.
- Implementability score: 0.70

### 2. Skills need topology, probes, and scanner-backed admission

- Category: [AgenticAI](../AgenticAI/2026-06-13/reasoning.md#skills-need-topology-probes-and-scanner-backed-admission)
- Durable topic: [Skills as Control](../AgenticAI/skills-as-control/skills-as-control.md)
- Core sources: https://arxiv.org/abs/2606.11543v1, https://github.com/zhiyuchen-ai/skill-juror, https://arxiv.org/abs/2606.13317v1, https://github.com/NVIDIA/SkillSpector, https://github.com/addyosmani/agent-skills, https://github.com/obra/superpowers
- Why it matters: skill libraries are becoming operational dependency trees. The useful question is not “does the skill text look good?” It is “did this organization, topology, and admission evidence improve behavior without adding unsafe authority?”
- Implementable now: use progressive disclosure, routable sub-skill topology, skill/no-skill baselines, verifier-passing trials, static/semantic scans, SARIF output, and runtime probes.
- Implementability score: 0.86

### 3. Prompt-injection risk should be scored by stakeholder harm and source locality

- Category: [Strategy](../Strategy/2026-06-13/sovereignty.md#prompt-injection-risk-should-be-scored-by-stakeholder-harm-and-source-locality)
- Durable topics: [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md), [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md)
- Core sources: https://arxiv.org/abs/2606.13385v1, https://github.com/StakeBench/SBC, https://arxiv.org/abs/2606.12737v1
- Why it matters: web-agent attacks can harm users, sellers, platforms, or third parties differently. A benchmark that only records attack success misses the business-process failure.
- Implementable now: label stakeholder harm, source locality, contaminated process steps, final outcome, and whether the user’s delegated task still appeared to succeed.
- Implementability score: 0.78

### 4. Agentic workflows are now governed Actions resources

- Category: [Strategy](../Strategy/2026-06-13/sovereignty.md#agentic-workflows-are-now-governed-actions-resources)
- Durable topics: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md), [Agent Gateway Governance](../Strategy/agent-gateway-governance/agent-gateway-governance.md), [Local-First Agents](../Strategy/local-first-agents/local-first-agents.md)
- Core source: https://github.blog/changelog/2026-06-11-github-agentic-workflows-is-now-in-public-preview
- Why it matters: natural-language workflow definitions that compile into Actions are deployable automation, not just prompts. They need owners, review, runner policy, sandboxing, output validation, threat detection, and trace evidence.
- Implementable now: treat workflow definitions as code, preserve compiled YAML and policy artifacts, run read-only by default, and require safe-output plus threat-detection evidence before applying changes.
- Implementability score: 0.82

## Signals

- **Highest implementability today:** skills topology and scanner-backed admission at 0.86. The tooling exists now: SkillSpector-style scans, skill/no-skill baselines, progressive disclosure, and trace-bound runtime probes.
- **Lowest implementability today:** memory evolution plus poisoning resistance at 0.70. The primitives are clear, but certified influence bounds and signed memory write paths require deeper architecture.
- **Noise filter:** I deprioritized generic agent launch press releases, generic MCP announcements, and model-development eval tooling that did not directly change agent runtime design.

## Actionable Insights

1. **Gate memory writes.** Start with writer principal, source hash, update history, and storage-budget decisions before adding learned memory policy.
2. **Test skill organization.** Measure progressive-disclosure skills against flat baselines, and log which resources were touched.
3. **Scan skills before install.** Treat community skills like dependencies: static scan, semantic scan, runtime probe, hash, owner, and scope.
4. **Add stakeholder labels to web-agent security tests.** Track who was harmed, where the injected content entered, and which process step was contaminated.
5. **Treat agentic workflow definitions as code.** Review Markdown workflow specs and compiled YAML together, then require sandbox and threat-detection evidence before mutation.
