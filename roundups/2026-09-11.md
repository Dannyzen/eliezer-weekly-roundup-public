# Friday Synthesis - 2026-09-11

## Thesis

The agent can propose state, but it cannot own the evidence that makes that state authoritative.

Across tool schemas, lifecycle reports, coding tests, memory, harness evolution, delegation, and fleet monitoring, the same failure recurred: a plausible output was allowed to stand in for independent world evidence. The practical response is not another model role. It is a runtime-owned evidence constitution that defines who may observe, propose, verify, authorize, and finalize each transition.

## Week-level findings

### 1. Runtime-owned truth replaces self-report

SilentProbe shows that HTTP success can hide a query the server did not understand. Only 15.2% of 721,320 audited OpenAPI parameters exposed any machine-checkable constraint. Prose-only constraints failed silently in 44 of 61 live perturbations, and downstream loops repaired none. The Unreliable Progress Bar finds the same problem in task completion: mid-task and completion reporting differed by 29.4 to 89.3 percentage points across deployments.

What changed: transport status and model status are observations. Schema validity, semantic result, pending obligations, and verified provider state are runtime objects.

Implementable now:
- encode finite vocabularies and required constraints in JSON Schema;
- record transport, schema, semantic result, and effect separately;
- derive ready, blocked, and done from runtime state;
- compare model reports with runtime truth instead of trusting them.

Implementability score: 0.86

Sources:
- https://arxiv.org/abs/2609.00035v1
- https://github.com/Jasper0122/silentprobe
- https://arxiv.org/abs/2609.08589v1

### 2. Independent acceptance requires independent evidence

ExecCritic freezes a qualified test before repair and keeps the repair agent from editing its own oracle. VP-CONTROL shows why role separation alone is insufficient: cross-model voting over shared evidence approved 62.9% of unsafe proposals, versus 22.9% when one verifier had an independent source. SEC-BENCH adds the security version: top agents exceeded 97% on a single proof of concept, then fell to 75-82% with multiple proofs and roughly half with semantic validation.

What changed: a second model is not a second oracle when it shares the same evidence or can rewrite the test.

Implementable now:
- freeze qualified test hashes before repair;
- separate test, repair, and commit-verifier principals;
- attach evidence-lineage IDs to verifier results;
- include related-proof and semantic oracles for security fixes;
- defer when current independent evidence is unavailable.

Implementability score: 0.74

### 3. Persistent state needs provenance, migration, and probe gates

The memory-portability study shows that an unchanged store can still fail after a model upgrade. Compressed notes moved by as much as -13.28 percentage points depending on writer-reader direction, and mixed embeddings recovered less than half the gain of full re-embedding. Grounding Agent Memory adds a write gate: a read-only curator probes the current environment before committing memory, lifting CLBench pass rate from 39% to 73% while cutting task-agent cost from $3.38 to $1.68. Skill-Evo4GUI applies the same principle to procedures by executing against a frozen snapshot and exposing accepted changes only in the next version.

What changed: memory and skill files are not inert context. They are versioned policy-bearing state with compatibility and admission requirements.

Implementable now:
- bind memory to writer, reader, embedding, schema, and source identity;
- re-embed as an explicit migration;
- require read-only probe receipts before memory write admission;
- preserve superseded facts but filter their answer-time authority;
- freeze skill snapshots per run and roll changes forward only after acceptance.

Implementability score: 0.77

### 4. Authority must attenuate across every principal and hop

CapScope gives each sub-agent only the typed capabilities its role needs. Injected effects fell from 33 of 75 under the strongest global baseline to 3 of 75, while 68 of 75 repairs still completed. CONTINUITY binds authenticated witnesses to exact effects across security-relevant transforms. A2ABreak then shows that specification-compliant A2A delegation can still lose end-principal identity, mix client context, and trust unattested capabilities.

What changed: broad task authority, valid protocol messages, and advertised capabilities are not execution authorization. Authority must remain scoped, attributable, and exact across every hop.

Implementable now:
- derive a task-wide ceiling from trusted input;
- issue role-specific typed capabilities;
- carry tenant, end principal, context owner, audience, and delegation lineage across A2A;
- require capability attestations and exact-effect witnesses at commit.

Implementability score: 0.73

Sources:

### 5. Improvement needs held-out portability and fleet-level observation

Ecdysis clusters recurring failures before proposing harness changes and reports up to 1.84x faster training with 18.56% higher reasoning accuracy. Skill-Evo4GUI freezes the current procedure snapshot. A multi-harness RL study found that harness choice moved mean solve rate 4.3x without a statistically clear held-out gain from reward grouping. MOLE adds the organizational layer: persistent principal histories across nine stateful services, triaged under the actual analyst review budget.

What changed: improvement is not portable until it survives held-out tasks, models, and harnesses. Safety is not operational until persistent behavior can be correlated above individual tool calls.

Implementable now:
- cluster failures by interaction structure;
- accept harness changes only into a new content-addressed version;
- keep a held-out harness and model in the gate;
- correlate stable principal IDs across services and days;
- use cheap anomaly features first, expensive semantic review second.

Implementability score: 0.61

## The stack after this week

1. Observe: retain raw tool, model, environment, and service-state evidence.
2. Type: validate schemas, identities, lifecycle states, and evidence lineage.
3. Separate: keep proposers, test authors, repairers, and verifiers under distinct write scopes.
4. Probe: let read-only curators establish current world state before memory admission.
5. Attenuate: issue per-principal capabilities and preserve them across delegation.
6. Gate: require exact-effect witnesses and transactional preconditions before commit.
7. Evolve: roll memory, skills, and harnesses forward only through held-out version gates.
8. Monitor: correlate persistent principals across services, then triage under a real review budget.

## Implementability range

The highest weekly score is 0.86 for schema-backed tool truth and runtime-owned completion state. The lowest is 0.61 for held-out harness evolution, because research code is immature and portability evidence remains expensive.

## Strongest objection

This architecture adds IDs, snapshots, schemas, receipts, and states to a stack already criticized for control-plane overhead. Several findings are new preprints, and some repositories have no root license or production release. That is survivable because the cheap controls come first: schema enumerations, frozen test hashes, stable principal IDs, and runtime completion state. Promote the heavier mechanisms only when a fault fixture proves they catch a failure the simpler boundary misses.
