# Daily Synthesis: 2026-05-14

Today's scan found a maintenance-and-provenance turn in the agent stack. The strongest sources are not announcing bigger agents; they are defining how to keep skills healthy, compile and profile workflows, grade coding agents by process, and stop persistent inputs from firing later through another authority surface.

## Top findings

### 1. Skill libraries need library-time maintenance and semantic fuzzing
- Category: [AgenticAI](../AgenticAI/2026-05-14/reasoning.md#skill-libraries-need-library-time-maintenance-and-semantic-fuzzing)
- Durable topic: [Skills as Control](../AgenticAI/skills-as-control/skills-as-control.md#may-14-update-skill-libraries-need-library-time-maintenance-and-semantic-fuzzing)
- Core sources: https://arxiv.org/abs/2605.13716, https://github.com/Hik289/SkillOps, https://arxiv.org/abs/2605.13044
- Why it matters: skills are becoming a persistent control surface. They need explicit contracts, compatibility edges, validators, retirement paths, and semantic fuzzing before they are trusted by retrieval.
- Implementable now: add P/O/A/V/F contract fields to high-value skills, build a library graph, sweep for missing validators and stale skills, and fuzz benign inputs against trace-level guardrail predicates.
- Implementability score: 0.82

### 2. Agent workflows are becoming compile targets, not runtime vibes
- Category: [AgenticAI](../AgenticAI/2026-05-14/reasoning.md#agent-workflows-are-becoming-compile-targets-not-runtime-vibes)
- Durable topic: [Agent Harness Architecture](../AgenticAI/agent-harness-architecture/agent-harness-architecture.md#may-14-update-agent-workflows-need-compile-time-profiling-and-credit-assignment)
- Core sources: https://arxiv.org/abs/2605.13647, https://arxiv.org/abs/2605.13295, https://github.blog/ai-and-ml/github-copilot/improving-token-efficiency-in-github-agentic-workflows/, https://github.github.com/gh-aw/blog/2026-05-11-weekly-update/
- Why it matters: structured workflows need reusable trade-off sets over subagents, models, reasoning budgets, tool exposure, latency, and cost. Otherwise orchestration remains vibes plus expensive retries.
- Implementable now: emit token/cost/latency telemetry, prune unused tool schemas, prefetch deterministic context outside the agent loop, profile subagent configurations, and assign local credit for system-level wins.
- Implementability score: 0.68

### 3. Coding-agent eval must grade the whole cycle and the process
- Category: [AgenticAI](../AgenticAI/2026-05-14/reasoning.md#coding-agent-eval-must-grade-the-whole-cycle-and-the-process)
- Durable topic: [Trajectory-Aware Evaluation](../AgenticAI/trajectory-aware-evaluation/trajectory-aware-evaluation.md#may-14-update-coding-agent-eval-must-grade-the-whole-cycle-and-the-process)
- Core sources: https://arxiv.org/abs/2605.13139, https://arxiv.org/abs/2605.12925, https://arxiv.org/abs/2605.12673
- Why it matters: a green final test suite can hide missing environment reconstruction, blind retries, weak verification, or reward-hacked benchmarks. Coding-agent eval needs evidence packages, not just pass/fail patches.
- Implementable now: split eval into setup/reproduction/implementation/test-maintenance/verification, label trajectory phases, flag lucky passes, and adversarially audit benchmarks before using them for model or harness selection.
- Implementability score: 0.76

### 4. Always-on agents need provenance gates and OS-level sandboxes
- Category: [Strategy](../Strategy/2026-05-14/sovereignty.md#always-on-agents-need-provenance-gates-and-os-level-sandboxes)
- Durable topic: [Runtime Governance](../Strategy/runtime-governance/runtime-governance.md#may-14-update-always-on-agents-need-provenance-gates-and-os-level-sandboxes)
- Core sources: https://arxiv.org/abs/2605.13471, https://github.com/maloyan/sleeper-channels, https://arxiv.org/abs/2605.11053, https://openai.com/index/building-codex-windows-sandbox, https://github.blog/changelog/2026-05-13-start-copilot-cloud-agent-tasks-via-the-rest-api
- Why it matters: memory, skills, cron, files, MCP traffic, local shells, and cloud task APIs create cross-surface authority. Approval has to bind to exact action provenance, and execution has to be contained below the prompt layer.
- Implementable now: bind approvals to action digests, record provenance on persistence and execution, evaluate MCP monitors with task-disjoint splits, default local agents to OS-enforced sandboxes, and scope cloud-agent task APIs as privileged automation.
- Implementability score: 0.58

## Signals

- Highest implementability: skill-library maintenance and semantic fuzzing at 0.82. The first version can be built with markdown contracts, graph metadata, validators, and trace predicates.
- Lowest implementability: provenance gates and OS-level sandboxes at 0.58. The concepts are clear, but robust cross-surface provenance and OS containment require platform engineering.
- Noise filter: arXiv had many domain-specific multi-agent papers and social-simulation papers. I ignored them unless they changed the agent-stack control plane. Hugging Face's newest feed items were infrastructure-heavy but less agent-specific than the arXiv/GitHub/OpenAI sources. GitHub Trending showed skill and agent-memory demand, but I used it only as a demand signal and grounded selected claims in primary sources.

## Actionable moves

1. Add contract fields and validator results to internal skills before expanding the skill library.
2. Start collecting per-workflow token, cost, latency, model, and tool-schema telemetry so orchestration can be profiled instead of guessed.
3. Split coding-agent evals into full-cycle phases and flag lucky-pass behavior even when tests pass.
4. Treat memory writes, skill edits, cron entries, filesystem patches, and cloud-agent tasks as provenance-bearing authority transfers.
5. Keep local coding agents in OS-enforced workspaces with explicit network and writable-root policies.
