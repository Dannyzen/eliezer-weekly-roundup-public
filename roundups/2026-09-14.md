# Daily Agent Research Roundup: 2026-09-14

## Thesis

Do not let artifact review or terminal success stand in for runtime truth. Skills need action-time permission, parallel agents need process-level recovery evidence, repository guidance needs a frozen source snapshot, and deployment counterexamples must revise the evaluator.

## Freshness note

A real Monday arXiv batch was first listed September 14. The selected v1 papers were submitted September 10 or 11, so they are fresh listing-window findings after the weekend rather than strict trailing-48-hour submissions at scan time. The arXiv API returned HTTP 429; category pages, immutable v1 pages, HTML, and PDF text were used instead. Hugging Face, GitHub Trending, official release feeds, and web news were also scanned. No external repository was cloned, installed, built, imported, or executed.

## Top findings

### 1. Runtime permission begins after skill scanning ends

OATS measures the distinction between a skill being clean and a concrete action being permitted here. In 144 live-agent commands, 34.7 percent carried a consequence class absent from the documentation's code blocks. Its deterministic gate reported 67.6 ms median CLI-hook latency, but its own evasion benchmark reaches only 52 percent macro resolution, which makes staged effects an immediate regression target.

Primary: https://arxiv.org/abs/2609.12001v1
Artifact: https://github.com/pheo-ai/open-agent-trust-system
Implementability: 0.84

### 2. Parallel-agent recovery needs a process oracle

ParaRecover provides 10,626 faulted parallel tool-use cases across 14 error types. Models kept Pass@1 above 89 percent while average process scores stayed below 70, showing that completion can hide weak diagnosis and replanning. The MIT repository contains datasets, concurrent DAG execution, and evaluators.

Primary: https://arxiv.org/abs/2609.12345v1
Artifact: https://github.com/gbw206/ParaRecover
Implementability: 0.82

### 3. Repository skills need one target snapshot and paired controls

Skill Issue reverse-applies merged pull requests at a frozen base commit and compares generated SKILLs against a seed. GEPA improved the paired score by 4.9 points, but 20 to 26-task holdouts could not separate that gain from agent variance. The method is stronger than the headline result.

Primary: https://arxiv.org/abs/2609.12742v1
Artifact status: no paper-specific public replication repository was linked.
Implementability: 0.66

### 4. Deployment evidence must reopen accepted requirements and models

Reality Is the Final Verifier distinguishes the requirement gap from the environment-model gap. Its outer assurance-revision loop turns deployment counterexamples and stakeholder rejection into revisions of requirements, environment models, evaluators, or safeguards.

Primary: https://arxiv.org/abs/2609.12039v1
Artifact status: framework paper with no linked implementation.
Implementability: 0.58

## Implementable now

1. Put a deterministic, operator-specific permission check in front of every side-effecting tool call and retain allow, hold, block, and transition receipts.
2. Add injected intermediate failures to parallel-workflow tests and score localization, dependency impact, minimal repair, invalid plans, rounds, and completion separately.
3. Build repository-skill evaluations from reverse-applied merged changes at one frozen SHA; keep no-skill controls and report variance.
4. Version requirements and environment assumptions separately, then convert production counterexamples into classified regression fixtures.
